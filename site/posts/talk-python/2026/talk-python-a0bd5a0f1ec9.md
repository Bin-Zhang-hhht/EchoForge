## 速读

数字人文项目的难点不止是把研究做成网站，还要把数据建模、搜索和部署设计成经费结束后仍能保存与访问的系统。本期主持人 Michael Kennedy 采访 Harvard Digital Arts and Humanities（DARTH）团队的 David Flood，讨论他如何从没有编程背景的文本批评研究者，走到用 Python 为学者搭建研究平台的工作。节目最值得关注的主线是：动态应用适合研究进行时的录入与协作，但归档阶段应主动评估静态化、浏览器内运行和可迁移的搜索方案。

这期适合数字人文、科研软件、数据平台和需要维护长期项目的开发者。它同时包含项目案例、工具陈述和个人经验：Apatosaurus、Mapping Color in History 与 Finn Folklore 说明研究问题如何决定界面；Django、Postgres、PageFind、Django Bakery 与 WebAssembly 说明实现路径；Flood 的自学经历和对 AI 编码的提醒，则更像个人观察，不应当被读成普遍规律。

## 主题正文

### 1. 研究问题先于技术栈：从文本、颜料到民间故事

Flood 的个人起点是文本批评。他在 2019 年开始攻读人文学科博士时还不知道 Python 或其他编程语言；文本批评要比较同一文本的多个版本，以推断早期文本及其随时间的变化，他主要研究新约文本。节目用莎士比亚“To be or not to be”的异文作直观例子，但这只是主持人与嘉宾的说明性例子，不是本期项目的数据结论（`00:03:04–00:05:07`）。

他注意到，进化生物学家用于比较 DNA 序列、追踪变异的系统发育软件，也可以把文本变体作为序列元素，用于分析文本变化与分组；这属于方法类比和嘉宾的研究兴趣，不代表文本与 DNA 在证据性质上等同（`00:05:19–00:06:16`）。由于现成工具往往不是桌面应用或公开 Web 应用，他先用 Python 把工具串起来，再把从“自上而下”的个人脚本改成同事可以复用的工具，最终转向 Web 以便分享（`00:06:21–00:07:29`）。

DARTH 的工作方式更像大学内部的小型代理团队：研究者通常带着有期限的经费项目来咨询和开发，Flood 说团队每年大约做两到三个大型新项目，也会让几个项目进入收尾；数字是嘉宾的工作经验，并非机构的固定产能指标（`00:12:09–00:14:05`，`00:26:53–00:27:24`）。项目可分为供研究进行的虚拟研究环境、面向公众探索的展示与搜索界面，以及把表格等材料清洗、建模并导入数据库的数据处理工作；这些是节目中的工作分类，不是正式标准（`00:12:57–00:15:03`，`00:23:32–00:24:27`）。

案例的共同点不是“给人文学者上一门编程课”，而是让领域专家在熟悉的研究问题上获得合适的界面。Apatosaurus 让研究者上传文本校勘结果、可视化不同读法，并在后台编辑校勘和添加注释；名称取自“apparatus”的谐音联想（`00:20:01–00:21:03`）。Mapping Color in History 则把艺术品颜料的光谱分析与图像位置关联起来：研究者在深度缩放图像上标出采样点，公众按颜色或颜料探索包含这些颜料的亚洲绘画；这是节目对具体项目功能的介绍（`00:21:25–00:23:10`，`00:37:43–00:38:04`）。Finn Folklore 数据库收集与爱尔兰神话人物 Finn 相关的录音和书面材料，并用地图和搜索帮助发现不同讲述；它还支持英语、苏格兰盖尔语和爱尔兰盖尔语，翻译不仅发生在界面，也进入数据模型（`00:32:41–00:34:18`）。

### 2. 数据建模与可搜索性，往往比页面本身更费力

这些项目常从一个或多个 Excel 表开始，团队先把材料导入 Postgres，再确定数据模型和关系；Flood 说他们是 Django 团队，而不是把数据库连接直接交给研究者。完成导入后，研究者得到的是用于继续录入、探索和发布的 Web 平台（`00:23:32–00:24:27`，`00:25:21–00:26:34`）。日期并不总是精确日期，项目可能要处理“2020 年 7 月”或“2020 年夏天”这样的模糊时间；嘉宾还提到过一个基因名称被 Excel 误解析为日期的生物学案例，作为数据导入边界的旁证而非 DARTH 项目案例（`00:24:31–00:25:21`）。

主持人和 Flood 都强调，好的搜索界面本身就能改变研究数据的可用性：节目以把数据放到 Elasticsearch、配合过滤来快速发现内容为例，强调从表格中翻找转为搜索与筛选；这是对界面价值的概括，不是对 Elasticsearch 在所有项目中都最优的建议（`00:18:31–00:19:49`）。Amendments Project 的公开端保存并检索至少 22,000 个从未通过的美国宪法修正案提案全文，用户可以按州、国会届次或共同提出者等维度过滤；“至少 22,000”是节目中的项目数字，搜索维度是访谈展示时列出的例子（`00:30:36–00:32:08`）。节目谈到该项目时也出现了关于宪法修正难度的闲谈，主持人与嘉宾没有核实具体法律门槛，因此本文不把那段推测写成事实。

可搜索性还必须服从语言和资料结构。Finn Folklore 中同一个人可能有多个语言的名字，有时同一语言也有多个名称，翻译和关联关系因此成为数据库问题，而不是简单替换几段界面文字（`00:34:23–00:35:22`）。这类学术案例说明，数据模型应从材料的身份、版本、语言和关联关系出发；这是基于案例的编辑归纳，不是嘉宾给出的统一建模规则。

### 3. 经费结束不是删除项目：把动态应用变成可维护的档案

DARTH 的 Django 应用通常部署在 AWS 容器中，配套可能包括 Elasticsearch 和 RDS Postgres。Flood 认为这种方式稳健可靠，但成本不低；项目由研究经费支持，资金结束后，团队必须面对谁来支付服务费、谁来维护升级的问题（`00:40:44–00:41:46`）。因此他们形成的“金标准”是先问：能否把应用烘焙成静态网站？代价是搜索能力会减少，新数据不易加入，但对已经进入归档阶段的项目，这个取舍可能合适（`00:41:46–00:42:20`）。

Water Stories 是节目中的正向案例。它曾为 Harvard Radcliffe Institute 的艺术装置服务，访客在 iPad 上提交水相关故事，内容进入数据库；团队使用 Django Bakery，并按其基于类的视图方式构建，从而在项目结束时较低成本地生成静态文件（`00:42:20–00:43:05`）。静态化不等于源数据消失：Flood 说，若后来需要修改，可以在本地用 Docker Compose 启动完整应用，在 Django 管理后台修改，再重新烘焙网站；但一次菜单改动也可能导致约 7,300 个页面重新生成，这个数字来自主持人对该类静态站维护代价的举例（`00:43:22–00:44:06`）。

搜索可以用 PageFind 保留一部分交互体验。团队正在把含有 22,000 个提案全文的 Amendments 网站退役为静态站，并用 PageFind 替换 Postgres 的全文搜索；代价是失去向量搜索，但关键词搜索、筛选和分面仍可保留。Flood 还描述了 PageFind 将索引拆成许多小文件、按查询需要加载片段以减少网络传输的工作方式，并说可以用 Python 或 TypeScript 手工建立索引；这些是节目对工具的陈述，不应外推为所有规模下的性能保证（`00:44:45–00:47:18`）。

对于简单的 Django 页面，Django Bakery 是一条路径；但 Finn Folklore 和 Mapping Color in History 使用 API，分别涉及 Django REST framework 与 GraphQL，并有 Vue 或 React 前端，直接烘焙后端 HTML 并不能自动解决客户端应用的归档问题（`00:50:24–00:52:53`）。Flood 因而在探索另一类方案：Pyodide、PyScript 可在浏览器运行 Python，SQLite 以及 PGlite 可把数据库能力带入浏览器，Django WebAssembly 的概念验证甚至能在 Service Worker 中让用户登录到自己浏览器里的 Django 管理后台。节目把这些说成可行性探索；从 RDS Postgres 转换到 SQLite 或 PGlite、处理浏览器资源和长期标准兼容性，仍是需要验证的工程工作（`00:53:34–00:56:37`）。

### 4. 工具能加速个人工作，但学习与团队约束不能省略

Flood 的 Python 学习路径是个人经历：他在洗碗时看 YouTube 教程，疫情期间增加练习时间，先为自己的研究解决工具串接，再为同事改造成可复用工具；这说明非计算机背景的人可以进入软件实践，但不构成学习时长或职业转型的保证（`00:06:43–00:07:29`）。他还说自己在 2019 年接触 Talk Python 后，把播客当成了解开发者文化、库和部署经验的“语言浸泡”，会搜索“deployment”来听人如何谈真实部署，而不只是阅读四步教程；这是他的学习策略（`01:05:44–01:08:22`）。

AI 部分同样应区分观察与建议。Flood 回顾说，若自己开始博士研究时已有今天的 AI 编码工具，可能不必先获得同样的技术能力，也可能因此不会进入数字人文软件工作；这是反事实个人判断。当前他把 AI 用于数据提取，并在处理 beatbox 音频时结合 Librosa 与 Claude：让模型处理自己不熟悉的数学，再由自己用领域判断把组件串成可用输出（`00:58:46–01:01:11`，`01:02:48–01:03:39`）。他明确说，团队还没有验证“用三天替代一个月”的交付承诺；这句话正好提醒读者不要把 AI 的潜在效率当成已证实指标（`01:01:48–01:02:58`）。

对刚开始用 AI 编码的人，节目给出的可迁移建议是保持学习者心态：把工具当作解释和探索的帮手，而不是按下按钮后不理解结果就离开；Flood 也建议先教 faculty 使用 Copilot 或 Cursor 等专门工具，而不是只从聊天窗口复制代码。建议的核心不是拒绝 AI，而是保留理解、判断和验证（`01:02:17–01:02:58`，`01:08:30–01:09:15`）。同样，是否采用事件建模、静态化或浏览器内运行，最终要由研究目标、维护能力和项目生命周期共同决定；这是结合整期访谈的编辑归纳，不是节目宣称存在一套适用于所有项目的模板。
