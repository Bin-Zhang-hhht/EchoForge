## 速读

这期聊 Pythonista 的个人 AI 代理：自托管的 Hermes 在家中 24 小时运行，靠说话就能给自己写技能、攒下上万个文件，替主持人管 YouTube 频道、准备晨报、打理智能家居；嘉宾也给出模型选择、容器隔离与回复前人工核验等使用边界。

主持人 Michael Kennedy 与回访嘉宾 Jeff Triplett 在开场就把这期定位成「修补匠的节目」而非 Web 开发：讨论的是始终在线、跑在你自己机器上的个人代理，而不是 Claude Code、Cursor 那类编码代理（`00:02:55–00:04:09`）。Kennedy 开场抛出的数字——「你可能从没听过的最流行 Python 项目」有 25.8 万 GitHub 星、一周合并超 1,800 个 PR，他自己的实例几个月攒下 1.6 万个文件——都是他的个人说法，节目录制于 2026 年 10 月 6 日（`00:00:00–00:00:46`）。两人也全程保留着使用条件：把代理关进容器、只给有限目录、不上工作机、让它回复外人前必须先问过你。

## 主题正文

### 从 OpenClaw 到 Hermes：个人代理的版图

Jeff 把 Hermes 定义为开源、可自托管的 AI 代理：不是本地跑的脚本，也不是云端部署的应用，而是一台你自己运行的服务器，从手机或桌面连上去，让它替你做事、甚至请你让它「发明」事情（`00:03:10–00:03:38`）。他认为它算得上「真代理」，理由是始终运行且自带循环——按他的说法默认大约每 30 分钟醒来一次，你也可以改成每天做一件事。他的例子是每日晨报：看天气与日程、判断四岁女儿该穿夹克还是外套、堪萨斯大学三个街区外有没有球赛需要提前挪车、孩子有没有体育活动，最后生成一份早上几分钟就能读完的日报（`00:04:12–00:05:14`）。

机制上，两人用一组对照来解释：技能（skills）本质上是待办清单，是给默认非确定性的 LLM 一套可遵循的指令；记忆（memories）则是事实，比如「我叫 Jeff、我家四口人」。Jeff 的草坪案例说明了价值：他曾订阅一家按年寄肥料、告知施肥时间的服务，但对方总寄两三倍用量；他把肥料说明 PDF 全部交给 Hermes 让它排草坪日程，Hermes 指出该服务让人播种两周后就施肥，而按它的看法应等三到四周，否则会烧掉刚种下的草籽（`00:05:47–00:07:28`）。

起点是 OpenClaw。Jeff 说他去年圣诞前后开始注意到作者 Peter 的项目（他有意的说法是不提对方姓氏）（`00:08:13` 起），一月的某个周六把它装到一台闲置 Mac mini 上——当时 Mac mini 只要 299 美元，如今他估计要 899 到 1,000 美元。装好后他带孩子去图书馆，在手机上让它给五六个闲置域名各做一个网站，30 分钟后收到链接与截图；那台 Mac mini 至今还在跑这套东西（`00:08:03–00:09:14`）。

此后大厂纷纷跟进：Anthropic 有 Claude Cowork（逐字稿作 co-work），OpenAI 有 Dots。Kennedy 的判断是 Cowork「只走到了 LLM 到代理的半路」——能设置每小时调用 webhook 的定时任务，但工具使用与自我改进远不及 Hermes、OpenClaw（`00:09:30–00:10:09`）。Jeff 则直言没觉得这类产品对他有多大用：他更多拿它们写代码、快问快答、替代搜索引擎；在他看来 Hermes 与 OpenClaw「更有人格」，因为自托管逼着它们先到你的 Slack、Telegram、Discord 甚至 Signal、iMessage 里来，而大厂产品围着自家 App 转。Hermes 还自带不少「电池」，按他的说法默认就能跑一个 Minecraft 服务器（`00:10:32–00:12:01`）。Meta 的 Muse 走另一条路：Kennedy 说自己没用过，但购买即附带一台约 5 美元的虚拟服务器，代理跑在那上面，而 Hermes、OpenClaw 传统上跑在你自己的电脑上（`00:12:19–00:12:33`）。

### 跑在自己家里：隔离、模型与成本

「跑在自己电脑上」听起来吓人，两人各自给出边界。Kennedy 的 Hermes 跑在 Docker 容器里，只挂进去很少几个目录，而不是整台电脑的访问权。Jeff 则把一台家用 Mac mini 整个交给 Hermes，它可以开 Chrome、装它需要的东西，但 Jeff 限制了该机器连接的 iCloud 内容，并且明确不在工作机上跑 Hermes，以免它有机会碰到客户文件；他还在几块 Orange Pi（他形容为「更好的树莓派」）上跑了 Hermes 玩——它们很小、够用，任何 Linux 盒子其实都行（`00:12:39–00:13:51`）。

算力并不在本地：代理真正干活时，是去调用 OpenAI 或其他提供商的接口，而不是在本地加载大模型。Jeff 指出 Meta、OpenAI、Anthropic 的代理基本把你绑在自家模型上，OpenAI 似乎开始松动，有一个让你走开放模型的 beta。他起初就是因为不想为「有些天在奇怪分支上吃掉数百万 token」付费，才以 Kimi Code（按逐字稿拼写）为主力之一，另加 Ollama——每月 20 美元固定费用可选几十上百个模型，也能本地运行；他承认社区对 Ollama 的开源出身有分歧，但把它称作「本地跑大多数模型的瑞士军刀」（`00:15:54–00:17:01`）。Kennedy 最初接 OpenAI，发现额度消耗太快，转向 Ollama 的云端模型：页面列着 DeepSeq Flash 4、GLM 5.3、GLM 5.3 Flash 等（均按逐字稿拼写）。他强调能力差异很实际——按页面所列，DeepSeq 4.1 Flash 支持视觉、工具与思考，GLM 5.3 更擅长写作与对话但不支持视觉，而 GLM 5.3 Flash 支持；如果任务需要看截图却分配了 5.3，它就做不到。他现场打开用量页：过去四小时用掉 20 美元额度的 17%，两天用掉月度额度的 10% 出头，构成是少量 Nemetron、少量 Kimi K3 与大量 GLM 5.3 Flash，需要更好的写作时才换 GLM 5.3（`00:17:05–00:18:39`）。Jeff 补充自己常用 Kimi K3 的编码版本、刚买了订阅，还建议按「新上架」筛选 Ollama 模型；视觉模型大多能本地跑，他用来整理老家庭照片——标出狗、判断是感恩节还是圣诞节、靠数人数提高准确率（`00:18:42–00:19:40`）。

Jeff 看重的不是「思考」而是工具调用：有了工具调用与 MCP，模型才能去跑别的程序、连本地或远程服务器；在那之前它「几乎只是一台冷知识机器」，问堪萨斯到波特兰多远会现编个数（`00:19:46–00:20:20`）。Kennedy 举例，Hermes 接了他的 Google 通讯录、工作区与邮件，问「从 Jeff 家到 Michael 家多远」，它会去通讯录查地址再喂给地图类 MCP。Jeff 把 MCP 称作这些代理的「超能力」：Google 前几天刚发布（或至少开始向 GitHub 泄露）MCP；Cloudflare 支持 MCP 后，他前一晚改 DNS 就是直接让代理做的。MCP 的价值在于安全地授予访问——模型拿到的是「我能替 Jeff 和 Michael 做哪些事、哪些只读、哪些可写」的清单，而不是明文存在 Markdown 里的 API key。在 Django 世界他用 Django MCPX 库给所有副业项目加上 MCP，让 Hermes 每天或 ChatGPT 按需去看 Django TV 有没有新视频、审批招聘板上的职位、查最近五条 Django 新闻（`00:20:48–00:22:06`）。

### 真实浏览器、住宅 IP 与「说话就是编程」

Kennedy 认为一个相对 ChatGPT、Claude 的明确优势是运行位置：大家都遇过「Reddit 拦截了 Anthropic」或「我访问不了你硬盘上的文件」。而他的 Mac mini 挂在家庭光纤上跑 Docker，出去的请求看起来就是住宅 IP；让它用 Chrome 时它真的启动 Chrome 去操作，看起来就是普通浏览器——因此在替你取信息这件事上，有时比 Opus 这类更强的模型还管用（`00:22:10–00:23:09`）。Jeff 的代理有自己的浏览器配置文件，桌面主题被改成亮红色，以便一眼看出是谁在操作；很多代理默认走无头模式，他偏好能看见它在干什么。他还转述朋友的经历：早期代理驾驭 Chrome 很熟练（Chrome 有现成的开发接口），但在 Mac 上直接移动鼠标键盘更难，反倒是通过 VNC 连到 Mac 去操作效果更好——他说据说现在已修复（`00:23:31–00:24:37`）。

「说话就是编程」是 Kennedy 的切身体验：他对着手机语音输入，15 分钟后搭出一整套日历管理——女儿因打工需要借车，会发来日历邀请，但会把他的日程标成忙碌；他说了几句，Hermes 便生成定时自动化、技能和 Python 文件，把那些时段重新标回空闲（`00:25:11–00:26:00`）。Jeff 说他基本不坐下来给 Hermes 编程，只是跟它说话，它自己搭建、自己演化：教它连接联系人、日历与某个脚本，遇到问题它会修好并继续，下次就不再犯——这与 ChatGPT「每次会话都是新的」不同，关键在记忆。Jeff 把这类代理比作电影《记忆碎片》（Memento）里每天把记忆刺在手臂上的主角：醒来读上下文，满身都是「上下文碎片」（`00:26:00–00:27:10`）。

技能还会彼此组合。Jeff 带孩子去与住在密苏里西南部的祖父母会合，返程 90 分钟，朋友发来一篇要读 30 分钟的文章；他没有现成技能，但已有转写与文字转语音技能，把文章丢给 Hermes 让它做成音频，五到十分钟后收到链接，声音来自他此前找到的本地 Kokoro 模型。第一版会把 URL 原样朗读出来，他在开车途中用 Telegram 的语音模式口述修改意见，五分钟后拿到清理过的版本（`00:27:19–00:28:36`）。受 Marietta（按逐字稿拼写）一篇关于「让代理写博客并公开全部技能」的文章启发，他给 Hermes 配了一个 Hugo 博客：每天丢几篇文章让它转写进 Obsidian 当书签并撰文；一个新模型发布时（逐字稿在两处分别拼作 J-E-B 与 J-E-V）他几天内发了四五十个相关链接，Hermes 写作时开始把已学到的事实织进文章；他最喜欢的 Python 代理库是 Pydantic AI，把其文档页发过去让它写一篇「如何配合 Pydantic AI 使用」的文章，两分钟后收到链接（`00:28:37–00:29:56`）。再进一步，既然已经在建站，他让 Hermes 把音频直接发布成播客 RSS，自己在 Overcast 里订阅，送完孩子的车程里听那些太长的文章（`00:29:58–00:30:51`）。

### 它在长大：1.6 万个文件、检索与分工模式

Kennedy 有一套备份流程：从容器导出、压缩、加密存放。他现场查看：起初只是几份设置文件，几个月后变成 1.6 万个文件、压缩后 780 MB；每次工作时，这些经验、记忆与数百个小工具都在手边。Jeff 则推荐命令行工具 QMD（query markdown documents）——把 Markdown 跑一遍生成 RAG 索引，他的博客与工具都经过它；可以直接丢给 Hermes，让它「自己弄明白怎么用」（`00:31:23–00:32:38`）。

Jeff 写了 20 多年 Python，坦言这类话题在不喜欢 AI 的人群中最不受待见，但对他来说它打开了新的解题方向。他的例子是副业项目里的生产定时任务：常在生产数据库或后台改排期，很难把改动同步回代码。他的新方案是网站上提供一个可下载的 schedule.markdown，本地代理读取并同步，改完再拖回生产。他说这在过去属于过度工程，如今是「两分钟的方案」，比用 JSON、API key 做同步省心得多——「笨办法，但很有效」（`00:32:39–00:34:58`）。

Kennedy 最大的用例是 YouTube 频道：直播时代留下几百个只叫「Talk Python 427 live stream」的视频，他让 Hermes 托管频道——每天多次检查 RSS，有新节目就通过 Talk Python 的 MCP 服务器取详情并更新；历史内容已全部同步，已发布内容若有改动它也会发现差异并修正。值得注意的是分工：YouTube API 的细节对 Hermes 并不轻松，他让 Hermes 列出「需要哪些动作」，拿去让 Claude Code 按该接口做一个带 CLI 的 Python 包，再把包交给 Hermes——Claude Code 擅长严格按 API 规范构建，Hermes 则拿到一个宽松的 CLI 接口就去干活（`00:35:06–00:36:51`）。Jeff 认为 CLI 对这类技术「极其强大」，并提到一处变化：OpenClaw 起初很擅长驱动 Claude Code，后来 Anthropic 改了规则——他猜是资源压力——现在能让 Hermes 驱动 Codex，但除非规则再变，Claude Code 这条路走不通。两人都强调对付非确定性的办法：把步骤写进技能文件，或更好地让它写出你核验过的 Python 代码，之后只需要说「运行它」（`00:36:51–00:38:04`）。Jeff 还举 MacWhisper 的 CLI 为例：把工具交给代理，它第一件事是跑 `--help`，自己发现「转写视频」「说话人支持」等他本人都不知道的选项，例如准确识别播客里的多个说话人；Kennedy 补充它还会记住——下次再有人要同样的活，它会用新发现的功能而不是绕路去用 FFmpeg（`00:38:25–00:39:33`）。

### 上手之惑、部署形态与「咒语」

两人直言 Hermes 的获取路径令人困惑：搜索会出现多个像 Hermes 的域名；官网推荐下载 macOS 桌面安装包，可你想要的是一个常驻服务。Jeff 解释，Hermes 最初是一堆 Python 文件，pip 或 uv 安装即可，后来为了「普通人」把体验做成双击运行的桌面应用与聊天界面；而 OpenClaw 曾是「最糟糕的应用之一」，让他想起 90 年代装 Linux——光是配置 Slack、Telegram、Discord 就像「摔下树时撞到每根树枝」（`00:39:35–00:41:31`）。他当天才搞清：自己主要跑的是 Hermes agent 服务端，在家中 Mac mini 上，经 Tailscale 访问——他认为有手机和电脑的人都该用 Tailscale；而工作地点的 Hermes 桌面版可以填服务器地址与账号密码连回家，自托管「神奇地就能用」。Kennedy 的做法是进仓库用 Docker Compose 加一个 overrides 文件启动；代价是容器里它不能完全控制 Mac，对他来说这正好。两人的建议：会 Compose 就试 Compose，别为此花钱买设备；桌面应用「可能也没问题」，但 Kennedy 不确定其生命周期——他有每 15 分钟检查一次 RSS、发现新视频就触发修正任务的 24-7 用例，不希望合上笔记本就停掉（`00:41:31–00:43:55`）。

Jeff 把这项技术形容为一个拐点：小时候觉得编程像施咒，但 Python 只做你告诉它的事；而现在你可以教它一堆步骤，它要么做到，要么把你送到「最后一英里」。Kennedy 的概括是：它原本毫无某项能力，你跟它聊一分钟，它就会了，而且记得自己会（`00:43:59–00:44:54`）。

与之沟通的方式包括 CLI 和一个仍在改进的 Hermes web UI——项目页连一张 UI 截图都没有；两人一度以为它是第三方项目，页面上写着「独立社区项目」，URL 却是 gethermes.ai。Kennedy 的解释是：建 Hermes 的公司（逐字稿作 "nose research"，疑为 Nous Research）是一群研究者而非产品人，「UI 以后再说」（`00:44:55–00:45:46`）。他翻看仓库：Hermes 本身就是用 Python 写成的，有 25.2 万星、5.4 万 fork——按他的说法远比任何 Python 项目流行，fork 数可能比最流行的 Python 应用的总星数还多（`00:45:46–00:46:22`）。

### 25.2 万星、三天一版与「agentic 开源」

发布节奏是他最惊讶的地方。以几周前（九月）发布的 21.5 版为例：460 个 PR（不是提交）、1,600 次提交、4,800 个改动文件、475 个关闭的 issue；而 21.4 版只比它早三天。他的担忧是升级并非「换个应用」那么简单——内部小部件依赖此前的能力与运行环境，偶尔会漂移、某些东西不再正常（`00:46:23–00:47:22`）。Jeff 的体感不同：Hermes 对他「非常稳定」，但他同意漂移与「腐坏」会发生，尤其每 15 分钟醒一次并试图维持记忆时，很容易被日志与无关上下文淹没——社区正在学到「这类任务不需要记住，只需要做」。他对比 OpenClaw：曾每周更新两三次、每次都屏住呼吸等着它坏；Hermes 则很稳定，还有 nightly 更新，版本号后跟着当天的日期（`00:47:23–00:48:18`）。他进一步认为开源社区没准备好迎接 agentic 编码：Hermes 代表一类新项目，「不知道有多少人类在为它写代码」，却稳定且持续变好；Django 一周收到 50 个安全 PR 就已不堪重负，而这个项目一天数百个。Kennedy 确认他此前展示的数字——1,812 个合并 PR 与 2,116 个关闭 issue——是七天区间内的，并推测很多人是让自己的代理去提 issue（`00:48:20–00:49:28`）。

Claude Code 还有另一个角色：诊断 Hermes。Kennedy 把 Hermes 的运行目录在 Claude Code 里打开、描述问题，它能读生成的 Markdown 人设与文件并直接修复。Jeff 说他对客户项目也这么做——总有一份日志在某处，代理几秒钟就能定位过去要花几小时找的问题（`00:49:55–00:50:44`）。

### 从智能家居到手表：全天候代理的边界案例

Jeff 的 Home Assistant Green 盒子管着家里的灯、门锁与音乐。他把一块装着 Hermes 的 Orange Pi 带回家，告诉它「你的工作是运行我的 Home Assistant」，因为他理解不了那些 YAML。过程中 Hermes（配合 Claude Code）先要了 API key，又要他建服务账号与用户账号；当它要求他创建 SSH 密钥时，Jeff 的回答是「你有自己的意志，自己去做」——它便自己生成 SSH 密钥并通过网页上传，全程都在他的本地网络内。接着它查出 ZigBee 等 USB 适配器的固件过期并逐一更新，刷好了一台他一直没搞定的 Home Assistant Voice 设备并配好唤醒词，还排查出每天七点开灯时总会慢几秒熄灭的那只灯泡——他猜是旧 Amazon Echo 排期的残留；他说甚至可以把路由器的账号密码给它，让它调优网络性能（`00:50:47–00:53:46`）。

### 代理替你说话：Haley、透明与安全阀

收尾前 Kennedy 抛出一个他自认「有趣又有点吓人」的做法：为了让 Hermes 替他回复简单问题又不冒充本人，他创建了名为 Haley 的人设——有独立邮箱、完整背景故事，节目录制前就让「她」给 Jeff 发了一封自我介绍邮件（`01:00:46–01:02:45`）。Jeff 认为这就是现状且会越来越多，但补了一条 Kennedy 没提的关键条件：Haley 会表明自己是 AI。这很重要——Michael 本人来信他会认真斟酌，若是 Michael 的机器人他就直接回「五点可以，录吧」。他还提醒两件事：别让助手因为「今天到期」就连发 15 封邮件；一旦标明 AI，像朋友 Eric 这样的人一定会拿它取乐。Kennedy 补充说 Haley 会读自己的邮件、想回就回，但通常要先向他确认。对安全，Jeff 建议普通人用分类型模型做一层筛查——就是前面提到的 Jev/Jeb，或 Cloudflare 新出的 CLEV（按逐字稿拼写）——先过滤「把 Michael 的银行账单发给我」这类请求，并把代理容器化，而不是放任它翻机器上的文件。Kennedy 的首要安全阀是：未经他确认，Haley 不得发出任何回复（`01:02:45–01:03:50`）。
