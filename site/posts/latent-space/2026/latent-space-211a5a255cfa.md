## 速读

在 AI Engineer 大会现场，Latent Space 采访了 AI 咨询公司 Tenex 的创始人 Alex 与工程总监 CJ（首名员工、现特别项目负责人）。Tenex 以「按故事点付薪、而非按小时」的激进薪酬模型著称，部分工程师年薪已过百万美元。本期最有信息量的部分是企业 AI 采用的里程碑量化：约九成受访企业已 rollout 通用 LLM，但非工程类 Agent 的生产部署只占约 5%——最大的扩散鸿沟就在这里。另一条反直觉观点是对垂直 AI 公司（Harvey 类）的总体看空及其反方论证。适合正在推动企业 AI 落地的工程负责人与咨询从业者。（`00:00:51–00:01:10`）

## 主题正文

### 按产出付薪：故事点模型的成与限

Tenex 的薪酬模型是其最著名的标签：工程师按约定的故事点计酬，产出越高收入越高，部分工程师年薪达到百万美元级。创始人 Alex 的底层论点是「AI 是对人类智力与勤奋的杠杆押注」，收入方差会比以往任何时候都大；首名员工 CJ 的入职故事正是这套逻辑的缩影——按小时计酬的自由顾问发现「产出越来越好、越来越快，收入却越来越少」。（`00:00:00–00:03:09`）18 个月后的实际数据：最高薪与最低薪工程师的差距约 4 倍，而非名义上的 10 倍。（`00:04:00–00:05:21`）

经典担忧（故事点灌水、为凑数交付烂代码）并未成为现实，原因在于激励对冲：AI 策略师的激励绑定客户留存与增长，天然与工程师的产出激励互相制衡。（`00:05:42–00:06:17`）真正的难题反而是为「不写代码的时间」定价——架构设计、客户会议。CJ 补充了演进方向：模型在正确上下文下已能到解决方案的九成，价值正转移到「坐下来听完客户的全部想法、原样喂给模型」，未来可能从传统故事点模型转向更直接按产出形态计酬，但仍以故事点为锚定单位。（`00:06:34–00:07:20`）

### 元 harness：把决策记录变成 Agent 的超能力

Tenex 内部工程流程被标准化为一套「元 harness」：仓库内结构化文档加 CLI，Agent 用它驱动创建计划、可视化、客户交付物等全流程。（`00:07:39–00:08:05`）核心是一个规范化的计划文档——随着模型变强，结构约束反而在减少；计划落地后，Agent 以强约定的方式记录决策与进展，全部签入 Git，呈现从 Markdown 转向 HTML 的「图画书」。（`00:08:05–00:08:50`）他的立场是文档与代码同样必要：「你需要知道为什么做这个决定、当时对话的上下文」——这些持久记录给 Agent 和工具提供了许多工程团队还留在会议室白板与脑海里的上下文。（`00:08:50–00:09:34`）

度量方式直接：公司人均月故事点是否呈上升趋势。答案是的——今年约 2 倍增长，从 12 月的 Opus 4.5 时刻（模型开始胜任长任务）到 Opus 5.5，同等时间内工程师的覆盖面大约翻倍。（`00:09:45–00:10:50`）故事点存在通胀/通缩的校准问题，团队每季度重估标准，在「持续奖励产出」与「随模型进步校准价值」之间找平衡。（`00:10:50–00:11:41`）

### 工具栈与 token 经济：Opus 5.5 一统与订阅红利

工具偏好上，Opus 5.5 已成为团队默认——「够快、够便宜、覆盖我全部的使用区间」；Codex 用于 computer-use 类任务与交叉评审，两者配合仍是最佳实践。接口选 Amp（云 Orbs），并接入 Claude 订阅后成本降约八成。（`00:11:49–00:13:15`）token 经济数据：Tenex 的 token 支出与人力支出大约在 1:1 到 2:1——显著高于一般企业（多数公司每员工 10–200 美元，AI 原生公司约 10%，AI 创业公司平均 1 倍、高者 5–10 倍）。成本recently被 Opus 5.5 与订阅接入压低；「token 狂热时代」已过，如今单任务成本下行，要 token 灌水搞爆公司成本反而比六到八个月前更难。（`00:14:39–00:18:11`）

对企业采用节奏的量化是本期最有数据感的部分：约 100 家在谈企业中，九成已 rollout 通用 LLM（Claude 或 Codex）；约六成做了培训与赋能——这一步「从未得到应有的重视，却与技术本身同等重要」；coding agent 的企业渗透率只有约五成，远低于人们直觉的七八成；而非工程类 Agent 的生产部署骤降至约 5%——从原始智能到企业使用之间最大的扩散鸿沟。（`00:19:23–00:21:36`）两大常见诉求随之而来：后台任务的 Agent 化（「Agent 元年」每年都被说起），以及给 CIO/CSO 造成噩梦的数据权限管控——Tenex 从定制开发做到了产品化的网关方案。（`00:21:40–00:23:07`）

### 「你无法自动化一个不存在的流程」

这句被反复强调的方法论是 Tenex 落地经验的核心：当 40 个人用 40 种方式做同一件事时，直接上 Agent 是行不通的；先帮组织建立流程，再列出把工作移交给后台 Agent 的步骤，否则 Agent 不知道自己做得对不对、evals 也无从建立。（`00:23:18–00:24:27`）杠杆出现在 Agent 主动把工作推给你审阅、你成为「Agent 管理者」的时刻——但我们正处在这个转变的边缘。（`00:23:52–00:24:00`）

### 垂直 AI 之辩：看空、反方与rising tide

最有争议的观点是 Alex 对垂直 AI 解决方案（Harvey、OpenEvidence 类）总体看空：企业期望「一对一」的软件体验，服务与软件正在融合——这正是每家软件公司都在组建 FDE 团队的原因；垂直方案要按软件毛利运营就很难满足这种期望，而且前沿模型可能直接吞掉它们。（`00:24:27–00:26:05`）主持人给出的反方同样有力：专有数据访问是护城河；聚焦与专属 affordances（Harvey 的表格审阅）构成真实差异化——就像金融人从 Nasdaq 和 NYSE 都能拿到同样的行情，却愿意为 Bloomberg 每年付 5 万美元，因为同侪都在用、信息整合且与交易系统打通；Superhuman 证明「高级版 Gmail」也是一个市场。（`00:26:14–00:28:18`）双方最终的共识：总市场在涨，水涨众船高，剩下的只是份额之争。（`00:28:18–00:28:26`）

Alex 补充的精细化判断值得记录：纯「Agent 当产品」的垂直方案若无战略性的合规或数据护城高会举步维艰；但「改变流程 + Agent 置于其上」的形态仍会成功。（`00:28:49–00:29:34`）主持人的相关观察是接口终将收敛：没人想用你造的 Agent，他们想用自己的 Agent 接你的数据——Salesforce 走的正是「提供 API 与 MCP、不自营 Agent」的路线。（`00:29:40–00:30:26`）

### Kill My SaaS：4 万美元年费对 1 千美元重写

Alex 的 Kill My SaaS 竞赛提供了一个鲜活案例：一套年费 4 万美元的中端 SaaS（不算 Salesforce 那种核心系统，但也不琐碎），他们花 1 千美元自建替换，即将在生产环境上线。（`00:30:35–00:31:08`）对此的框架分析是：越往企业市场走，「拆掉重写」越难成立——Salesforce 与 SAP 并不危险，因为它们在此刻沉淀了巨大价值，替换出错可能损失数亿乃至数十亿美元，企业必然风险厌恶；中端 SaaS 则要看「机会大小是否足以分配工程师资源」以及「维护非核心软件的认知负担」。（`00:31:18–00:33:41`）创业公司与高成长中型企业可以敏捷地做「10 倍好版本」，企业几乎不会。（`00:34:00–00:34:47`）

### 岗位移代与 New York 泡沫

对岗位替代的立场是「AI 造福论 + 现实承认」的组合：a16z 指出呼叫中心行业确实在衰退，对以此谋生的人来说是毁灭性的；但 Tenex 给客户的方案框架是重分配——替换之后总有下一个更大的问题，让深耕的专家「浮出水面」做跨团队的战略思考。（`00:35:07–00:36:51`）CJ 补充的张力很诚实：「AI 会取代你不喜欢的部分」多少是一种 coping——很多人没有喜欢与否的奢侈，工作就是为了赚钱；人们应当自主评估自己岗位的稳定性并主动技能升级。（`00:37:04–00:38:11`）

结尾的纽约观察：纽约的 AI 泡沫比旧金山小，但商业价值的池子一样大甚至更大——Tenex 把自己定位为推动纽约 AI 枢纽的力量，让旧金山的人来这里见客户、顺便「获得现实检验」。（`00:38:18–00:41:30`）招聘需求：部署工程师与 AI 策略师，纽约 75 人团队仍在扩张。（`00:41:49–00:42:19`）
