## 速读

斯坦福 CS146S《现代软件开发》二度开课，主讲人、Monaco AI 负责人 Mihail Eric 逐周拆解 AI 原生工程怎么教：200 行写一个编码代理、上下文工程与技能编写、把给真实开源项目贡献代码变成作业，再到代码评审瓶颈、供应链安全与软件工厂里剩下的人类卡点。

这是 AI Engineer 频道订阅破百万的特辑。嘉宾 Mihail Eric 身份双重：斯坦福兼职教授、CS146S（The Modern Software Developer）主讲，同时也是 AI 原生销售平台 Monaco 的 AI 负责人；对谈者为主持人 Swyx 与 Latent Space 的另一位联合主播（后者在逐字稿中未被点名）。录制时课程刚结束第一周（`01:57:54–01:58:07`）。本期最值得关注的三点：把给真实开源项目做贡献、接受维护者评审变成课程作业的"导师制"设计（`00:10:09–00:13:28`）；第一周现场用 MITMProxy 拆开真实的 Claude Code，把系统提示词、计划提示词、压缩提示词摊给学生看（`00:27:12–00:28:20`）；以及两位从业者在"软件工厂"话题上共同保留的条件——连最前沿的公司也只敢说三成上下的代码由代理完全驱动（`00:20:36–00:21:31`）。

## 主题正文

### 一门课的两年：从全景导览到原则固化

CS146S 的想法诞生于 2024 年 11 月：当时编码代理已经显现出改变开发方式的苗头，但方法论散落在博客里，他想把课程结构化，也算回母校"还愿"。从立项、写提案、过委员会花了九到十个月，2025 年秋首开，反响不错，去年还有 Business Insider 报道过这门课（`00:01:36–00:03:08`）。按他的说法，首届课程开在"Opus 4.5、4.6 之前"，而今年重开的理由是自主编码代理的爆发：去年各公司还在做覆盖 AI SDLC 每个环节的单点代理——评审的、做规格设计的、做 SRE 的——课程相应地是一场"全景导览"；今年则是原则在固化，比如非常精细的上下文工程、把设计与架构当作驾驭复杂任务的方式（`00:03:17–00:04:35`）。

课程定位被讲得很清楚：不面向编程初学者，也不是算法课的替代品——那些课是先修要求；它教的是有基础的学生如何在真实生产环境里应用这些原则，成为进入职场后最有生产力的成员。他在 Monaco 处理的就是大规模代码库（`00:04:40–00:05:17`）。大纲有相当的动态性，"一大块内容今年都换了"，这是设计使然；但他也强调有些东西会留下来，客座讲师正是为"前沿的人带来超越从业者汇总的视角"而设（`00:07:52–00:09:45`）。

### 该不该学 CS：被抬高的入场线

主持人问出学生最关心的问题：现在还该学计算机吗？Claude Code 和 Codex 就够了吗？他先承认焦虑真实存在，然后给出论点：训练有素的 AI 原生工程师仍是任何公司最有用的资产之一，但"地板高了很多"——用 Google 的职级说话，毕业进门只当个 L3 不够了，得接近 senior 水平（`00:05:40–00:06:35`）。基础软件工程——系统如何构建、权衡是什么——仍然重要，实现细节则可以更多推迟给工具（`00:06:42–00:07:04`）。

他也不避讳争议表述："大多数学生完蛋了（cooked），少数人会极其有价值"，并自嘲这是故意说得刺激；主持人追问：斯坦福的孩子没事，"其余的美国学生怎么办？"他承认这是开放问题（`00:07:04–00:07:26`）。选课人群也超出了 CS 系：有其他系所的博士后、病理或医药等交叉学科学生，还有不少 GSB 的 MBA——后者想学的大概是"如何不需要技术联合创始人"（`00:29:20–00:29:52`）。

### 把开源贡献变成作业

这是他自称最自豪的新设计。去年的九份作业加期末开放项目偏教学练习，"很多人可以直接 one-shot"，在人人用代理的今天意义有限；今年夏天他花了大半个暑假招募开源伙伴，选的是他心目中最好的 AI 原生仓库——要么本身是编码代理，要么是服务代理的工具（`00:10:09–00:10:58`）。开课前的周二调查里，全班没有一个学生再手打代码，全是二、三年级生（`00:10:58–00:11:07`）。

动机是补上导师制：资深工程师在代理时代如鱼得水，新人却不知道何去何从，他想让学生在复杂大型代码库里与维护者真实协作——作业的一部分就是给这些项目做贡献，由维护者评审代码、帮学生建立"好软件"的心智模型，等于把好软件设计的班交接下去；学生做得好甚至可能被合作方挖走（`00:12:04–00:13:28`）。资源上，学校通过各厂商教育计划默认提供 Claude、Cursor 乃至 Cognition 的许可，他又额外拉来 Factory、Cognition、OpenAI 为学生追加额度——"想 token 拉满看看可能性，就去"（`00:11:21–00:12:04`）。

### 十周大纲速览

第一周拆编码代理内部，从零写一个 harness（`00:15:15–00:15:24`）；第二周讲规模化的上下文工程与工具设计，他明确表示仍支持 MCP——"它已经是一个会继续存在的标准"（`00:15:24–00:15:56`）；第三周讲 skills，从单一用途的工具扩展到程序化流程，并引入代理自动化（`00:15:56–00:16:09`）；第四周讲定制代理的机制：AGENTS.md、CLAUDE.md 这类配置文件、hooks、子代理（`00:16:09–00:16:23`）；第五周是他最喜欢的"agent-ready 代码库"——什么样的仓库能被代理高效摄取，涉及边界设计、文档与可验证性（`00:16:23–00:16:55`）。

第六周是代理化代码评审：对今天用编码代理的人来说，代码评审成了新瓶颈，这一周讨论如何疏通（`00:16:55–00:17:35`）；第七周安全：自主系统大量执行动作的年头攻击面在增多，他点名今年 Vercel、LLM 网关等基础设施被黑的案例，讲新攻击向量与缓解（`00:17:35–00:17:56`）；第八周后台代理：不只活在 IDE 里，还有基于代码库触发器、CI/CD、事件乃至 SRE 式机器人的形态，Ramp、Spotify、Stripe 等公司都发过内部基础设施的介绍（`00:17:56–00:18:51`）；第九周是 AI 原生团队的团队级基础设施——LLM 网关、规模化的 MCP 门户——以及角色的演化与"什么技能变得可防御"（`00:18:51–00:19:31`）；第十周收束到软件工厂：人类还留在哪、哪些卡点是刻意设置的——意图与可验证系统——以及当代码绝大部分由代理驱动（他顺口说"也许 89%"）时的极限图景（`00:19:31–00:20:05`）。

他提醒这些"并非都是定论"，主持人的背书也很有分寸：全是业内人士在谈、你应该知道的事，"我们知道开放问题，未必知道答案"（`00:20:05–00:20:28`）。暗工厂本身是个光谱：最前沿的 Warp、Factory 这类把工厂当服务卖的公司，也只敢声称三成上下的代码贡献是完全代理驱动的；还有人深入暗工厂后又公开认错。连创造了 Claude Code 的 Boris 都发推说"我常常是错的"——这是工程不是政治，他希望大家保持实验心态（`00:20:36–00:21:31`）。落在操作上，他的建议朴素到每天花十分钟，用新工具重做一件老事情，"这就能覆盖大部分差距"（`00:21:40–00:22:09`）。

### 第一周现场：200 行代理与真 Claude Code 的提示词

他强调课程不背书任何工具，工具会来来去去（`00:24:17–00:24:47`）。第一周的组合是"三级跳"：先是他博客里那个不到两百行的最小编码代理——用入门算法课的知识就能写出的代理循环，没有子代理、没有 MCP，但确实能改文件（`00:25:54–00:26:45`）；然后课堂上用 MITMProxy 拦截真实 Claude Code 的请求与响应——他拿一个两天前刚发布的 Opus 新模型现场演示，把系统提示词、计划提示词、压缩提示词逐一摊开给学生看，让学生直接理解一个最前沿的 harness（`00:27:12–00:28:20`）。他的教育理念是剥开"秘方"，教概念原理（`00:25:54–00:26:45`）。

主持人一方回忆当年请 Boris 上播客时低估了 Claude Code：那时它才两个月大，"我用了一次，一条查询五毛钱，谁会用这玩意？"（`00:24:47–00:25:11`）。另一位主持人补充的现场数据是：Claude Code 拥有所有编码代理里最长的系统提示词，约两万 token，先砍掉八成、又涨回来，像跷跷板（`00:29:52–00:30:15`）。Mihail 的观察更有结构性：早期 Claude Code 靠"让更少的工具做更多的事"（倚重 Bash 这类瑞士军刀）取胜；如今如何用 Git、如何建任务这些内容已从系统提示词里消失，被压进模型权重——公司该投资模型还是 harness，社区仍在两边摇摆；弱模型时代需要往提示词里塞好坏示例，模型变强后这些示例又变成过度约束，何时撤掉本身就是功课（`00:30:33–00:32:16`）。

### 上下文工程与技能：课程的核心方法论

他在面试里见过太多人停留在"帮我做这个事"的一句话提示，这在模型足够好时能走一段，但进了 Google 那种大规模代码库就必须认真设计上下文的摄入（`00:33:10–00:33:41`）。他教的框架（转写作 Repit）与 Dex 的 RPI 功能类似：先做研究阶段，给出几个候选方案并让人类决策者拍板，再进入计划（规格）、实现与测试——这套流程可以扩展到数百万行的代码库，在陌生代码库里注入代理所需的上下文时尤其有价值（`00:33:41–00:34:45`）。主持人补的是多代理一层的语境管理：子代理是继承全部上下文还是只拿摘要、扇出后如何收敛，现在"没什么像样的答案"，还有上下文过载后代理把你的随口一提当成圣旨去执行的坑；Mihail 认可这是整门课里"艺术成分最高"的部分，并引用 Dex 的"dumb zone"概念提醒及时刷新膨胀的上下文（`00:34:55–00:36:40`）。

技能（Skills）这一周的立场也务实。好的例子包括 Matt Peacock 的 Grill Me，以及 Jeffrey Blitz 的 Explain Diff——对代码变更做可视化讲解并在结尾出小测验，逼你真的理解 diff（`00:38:44–00:39:30`）。主持人概括这批技能的共性是"多问我问题"，因为"任何关掉大脑的场景都不是好事"，一行提示换来上万行代码不叫生产力（`00:39:38–00:40:18`）。而写技能本身需要技能：默认生成的技能往往臃肿，他有个专门"剪技能"的技能；误触发是最大的痛，Eugene Yan 则会定期修剪不用的技能。他还抛出一个不受欢迎的猜测：OpenAI 和 Anthropic 内部有聪明人盼着 skills 消亡，因为"一堆 Markdown 文件"不像 AGI 该有的样子——但他同样认可另一面：在聊天里迭代技能、从不看 Markdown 也能拿到价值；而像 Devin 那样把组织级最佳实践固化成技能的做法，可能比"随机流程"活得久（`00:42:39–00:46:42`）。

### 另一半身份：Monaco 的 AI 原生销售实践

课程之外，他是 Monaco 的 AI 负责人。Monaco 是一家总部在旧金山的 B 系列 公司，做全栈的 AI 原生销售平台——代理接管人类不爱做的杂事，销售专注成单（`00:50:45–00:51:12`）。打法是从初创切入而非硬抢 Salesforce 的企业客户：在客户还是用 Google 表格管管道时就相遇、一起长大，仿效 Brex 等 YC 公司"卖同期公司"的路径，客户集中在种子轮到 A 轮，他自称是初创场景最好的销售平台（`00:51:24–00:52:24`）。技术上他们自研了面向 GTM 的代理 harness，借鉴 Codex、Claude 这类系统，从 TAM/ICP 打分、管道演化到会议纪要、摘要更新都由长短视野不同的代理驱动（`00:52:33–00:53:31`）。

模型策略是垂直 AI 的典型曲线：先用第三方前沿模型探边界，等成本变得敏感（他提到 Harvey"上下五成利润率"的讨论）再考虑开源权重模型，用 RL 后训练和自建环境——他们正处在这个阶段（`00:53:42–00:54:23`）。主持人把这总结为"代理实验室剧本"：应用先行、用户起量后回头补模型，模型实验室则反向而行（`00:54:27–00:54:51`）。数据侧他们是 Parallel 与 Exa 的早期用户（被要求比较时他选择"保持瑞士中立"），更值钱的是自建的"世界数据库"——持续富化的公司与联系人信息；他自称 Monaco 世界级的能力是需求生成，比如检测到目标客户销售 VP 换工作（LinkedIn 变动）就是最好的触达时机（`00:55:33–00:57:19`）。内部基建大量自建：跑在 Coder 平台上的后台代理平台 Monocoder 承载长视野编码任务，Slack 里的机器人 Hal 身兼 AI SRE、客服与 QA，甚至要为面对销售还是开发者切换"人格"（`01:00:09–01:01:31`）。

自建与采购的界线，他给了一句原则："买是为了学，建是为了留。"代码评审工具他们在一年多前普查过一轮——CodeRabbit、Graphite、Ellipsis 等——做了自家 PR 的饼图分析，结论是没有一家跨过"立刻有用"的门槛；第二次尝试 Devin 时他没有再推，团队自发觉得好用、陆续要求接入，至今仍在用（`01:01:53–01:04:25`）。主持人借机澄清自己如今只是 Cognition 的顾问，不深度参与（`01:04:39–01:04:48`）。营销上这家公司也出名：买下 monaco.com 域名还被国家告过、并且赢了（据他所述），旧金山天上那几架拖着公司名和大额数字的广告飞机据说每天约 6000 美元，换来的是每个会议的破冰话题（`00:46:52–00:48:35`）。销售组织里另有一个细节：卖 Monaco 的同一批人也是"现场部署账户主管（FDAE）"，负责帮客户上手搭代理工作流（`00:58:19–00:58:53`）。

### 代码评审成为瓶颈：中间地带在哪

第五、六周的落点是把前面一切拼起来。他的判断是：agent-ready 代码库是后续一切的前置块——多代理并行、几十个代理同时干活的前提是代码库可验证、结构良好、代理能读懂（`01:05:36–01:06:49`）。主持人的补充是把闭环真正闭上：让代理读构建日志、读生产分析，Mihail 当场决定把这个建议编进后台代理周和软件工厂周，两人还顺便戳破包装——所谓事件驱动，"其实都是 cron"（`01:07:00–01:08:07`）。

代码评审的位置很微妙。生成速度暴涨后，理论上一天能提三十多个 PR，然后呢？把自己插进传统评审就等于亲手成为速度的卡点；他要学生思考的是中间地带：哪些问题在可验证性设计到位后可以按比例自动批准，哪些必须人工仔细看，以及看的时候还在不还在逐行读（`01:12:45–01:14:08`）。主持人提到 Aviator 的 Ankit 写的"杀死代码评审"，Mihail 说大体正确，但补充卡点其实有两个：评审，和顶层的意图（`01:14:14–01:14:49`）。数据上的剪刀差是明确的：合并的 PR 在涨，评审数量没有同步涨；Amplitude、Cloudflare、Augment 都写过自家 AI 评审系统设计的文章，他推荐学生去读（`01:14:49–01:15:53`）。关于规格的维护，两人有一段真实的分歧：Monaco 的做法是把 PR 描述写成"这个时点的规格"，带文件级指针（`01:16:04–01:16:58`）；主持人反问功能级规格是所有 PR 的总和，谁来保证它不烂掉——他自己试过让模型维护，"它们做不好"；Mihail 介绍了 Basis 把规格与"代码规范态"分开做版本控制的方案，主持人则透露自己在做一个替代 Git 的"程序数据库"侧项目（未必发布），还半开玩笑猜最后的赢家可能是 Linear（`01:17:09–01:19:48`）。他更一般的判断是：凡是与 B2B 软件交互、掌握用户洞察的公司，都能把"发现问题→让代理修"的闭环闭上，很多公司会演化成某种编码代理公司（`01:19:57–01:20:30`）。

### 安全：依赖、供应链与"别在数据、计费、认证上撒欢"

安全周（第七周）的核心洞察是依赖追踪与供应链管理：不要随手 npm install 就指望链条完好（`01:21:36–01:22:10`）。主持人把推到极致——最安全的代码库是零依赖——Mihail 接住了这个危险结论：全自研意味着你只能靠自己的用户发现错误，而开源的"阳光消毒"意味着十万个用户里总有人找到问题；这是不能两头绝对的取舍（`01:22:10–01:23:14`）。他相信大多数开源仓库未来会变成代理运行的软件工厂——Warp 已经在把自己的开源终端当软件工厂跑——那安全边界在哪，连 OSS 从业者也没找到稳定点（`01:23:34–01:24:17`）。Vercel 的 Malte Ubl 主张把关键 C/C++ 基础软件移植到 Rust（对谈中提到约六百万美元的量级），模型实验室那边则是"先修复、再放开"的节奏主张；但他对"模型会搞定一切安全"明说不信——模型可能只是引入不同的新 bug，还给一百家组织发网络安全模型等于新建一百个攻击面（`01:24:30–01:26:40`）。

最可操作的分层来自两人共识：代码库不是生而平等的——数据存储、计费、认证这几块别撒欢，其他地方随便折腾；连 authentication 与 authorization 的区别、AWS IAM 的机制都要先学会，"有了语言才提示得动，没有语言就完了"（`01:28:39–01:29:28`）。AI SRE 的价值边界也类似：服务依赖图巨大、Kubernetes 与 Helm 文件泛滥的企业才是主场，Resolve 在福特、沃尔玛这类客户上做得好，Night Shift 也在后台代理方向做得不错；主持人补上企业级现实的量级——数万个仓库、仓库比开发者多、写代码的人已离职而代码仍在承载流量（`01:08:19–01:10:10`）。Resolve 去年还给课程做过一个埋了 bug 的多服务沙盒作业，让学生扮演 on-call 工程师用代理排障（`01:10:33–01:11:06`）。反过来他也提醒：很多规模化的公司卡住的原因根本不是缺一个 SRE 机器人，而是合并队列堵、起应用太慢这类基础 DevOps 问题（`01:11:48–01:12:36`）。

### 软件工厂与角色演化

后台代理周请的是 Cloudflare 的 Rajesh；两人顺带指出，看似消费级的产品——从 Grokbot 到 ChatGPT 里弹出的代码解释器窗口——内里都是编码代理，其中一个据称就是 Cursor 团队做的；主持人自己则把全部 SEO/AEO 工作跑在 Codex 里，因为长期、多步骤、带数据的事务迟早需要一个代码库（`01:30:41–01:32:59`）。对 MCP 门户与 LLM 网关的讨论里，Mihail 的立场是 MCP"不是牛熊问题，它就在那"，门户在规模化治理、安全、审计、成本优化时成为单点入口（`01:34:14–01:35:43`）；主持人则更进一步：门户终将并入网关，一切基建收敛成同一个"上帝盒子"问题，而 OpenRouter 只做路由也大获成功——"我喜欢被这样证伪"（`01:35:43–01:39:46`）。企业里真正的阻力常是组织而非软件——Conway 定律，"你发布的是你的组织架构图"（`01:39:46–01:40:54`）。他也点出平台工程师是未来越来越重要的角色；主持人回忆自己在 Temporal 的旧职，"如果不办 AIE，我就去做平台工程师"（`01:41:23–01:42:12`）。

软件工厂周的图景是"造机器的机器"，今天人类仍在两个卡点上：意图（定义规格与要建什么）和评审，而评审这个瓶颈会比意图更早松动（`01:42:36–01:43:10`）。开源伙伴 Warp 干脆让学生参与运营跑在工厂里的 Warp 版本（`01:43:10–01:43:31`）；但整厂产品很难被一家整体拥有，落地只能一块块来——先成为对方的编码代理，再加后台代理、再接管部分 SRE（`01:43:31–01:44:32`）。OpenAI 那篇内部工具博文是具象案例：五个月、零行手写代码，还总结了"harness engineering"与先慢后快的曲线（`01:44:32–01:45:13`）。

角色的答案还在形成。抽象层级逐级上移后，总得有人能跨过产品需求与技术约束做出裁决——"代理管理者"之类的称呼都是流行语；一个参照系是 Anthropic 的产品负责人与工程负责人同台时被问"你们的岗位何时合并"，回答是"还没"，连 Anthropic 都没到，学生不必觉得迫在眉睫（`01:45:51–01:47:13`）。主持人的框架更递归：你从写提示词，到写"会写提示词的提示词"，工厂是一层层从下往上建起来的；从顶层目标直接往下建的系统"现在只会制造 slop，但 someday 会行"（`01:47:39–01:48:26`）。当 PR 合并率不再是工程师的度量，Mihail 的猜测是工程演化成产品工程师的混合体；他给期末项目的种子 ideas 就是 YC 的 RFS——"去建个公司吧"。去年的案例包括 EE 学生做手册解析翻译器，以及一位设计师学生拍下笔记本草图直接生成完整应用、凭此进了 Vercel、如今在做 v0（转写作 Eve）；Vercel 与课程的合作方式之一就是让学生用 v0 搭建（`01:48:26–01:51:01`）。两人都提醒别被硅谷的气泡骗了：大量公司还停在单次调用 ChatGPT 的阶段（`01:51:01–01:52:16`）。

收尾部分谈的是社区生态。Steve Yegge 那篇约一年前的分级成长文仍有影响力，他的 Gastown 项目烧掉重来、公开走了两年弯路；主持人说作为雇主只想招"穿过 AI psychosis 并从另一端出来的人"，否则自己正在替员工付这笔昂贵的学费（`01:52:16–01:55:10`）。Boris 的团队采纳阶段图（gated、assisted、parallel、supervised autonomy、AI-native 五级）被两人翻出来对照——连 Anthropic 自己都还在第三阶段（`01:55:44–01:57:30`）。Mihail 还提到 Anthropic 命名的"dynamic workflows"模式：为任务按需写一个 harness 再作为子代理运行，Monaco 也自建了面向 GTM 的版本（`01:56:03–01:57:06`）。最后他送给学生一条"第十一周免费建议"：去做 benchmark 和 eval，这是敲开每个前沿实验室大门的路径——SWE-bench 出身不过是普林斯顿的本科生项目（`01:59:56–02:00:43`）。
