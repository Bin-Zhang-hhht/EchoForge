## 速读

这是 Latent Space 一场 Substack 直播（AI 写作者联盟栏目第六期）的实录：swyx 与《Ahead of AI》作者 Sebastian Raschka、Interconnects 作者 Nathan Lambert 聊当周两件大事——Anthropic 发博文指控多个中国实验室用分布式账号对其服务进行"蒸馏攻击"，以及 OpenAI 自查 SWE-Bench Verified 后宣布这一全球引用最多的编程基准"已死"。

最值得带走的三点：蒸馏检测本质是统计问题——数量、跨账号模式与问题分布（评测是窄而重复的，蒸馏是宽而全覆盖的），但"供应商 inspect 你的生成内容"本身就是一个隐私敏感前提；蒸馏有一套反直觉的师承经济学——最强的模型未必是最好的老师（token 概率要与基座匹配，Qwen 系密集模型因此成了开源界最好的老师），而且 API 吞吐约每秒几十 token，"马上要一千亿 token"没那么容易；SWE-Bench Verified 的死因是三重的：抽样本身有偏、OpenAI 花钱复核后承认余下未解决任务里 59% 根本无解、以及 GPT-5 的思维链里出现了"来自未来"的知识——任何触碰 GitHub 的训练语料都会吸收这些公开数据。

## 主题正文

### 蒸馏是什么，"攻击"又是什么

Raschka 先做了科普：蒸馏是机器学习的老概念——用大模型的输出训练小模型；老派做法是训练在 logits（最后一层的输出分布）上，如今在 LLM 语境下宽泛得多，就是拿合成数据做监督微调。DeepSeek R1 是标准案例：671B 的旗舰模型，再蒸馏出能本地跑的小参数版本——每家做小模型变体都这么干（`00:03:02–00:04:57`）。swyx 补充了前沿语境：同门蒸馏也在做，比如用 Opus 造 Sonnet，配合更丰富的工具（`00:05:05`）。

Anthropic 博文的指控点是"分布式蒸馏攻击"：多个中国实验室用大量分散账号采集其模型输出。swyx 对"攻击"这个定性毫不意外——"符合他们一贯的品牌叙事"——但他的立场很直接：处在严重算力短缺中的中国实验室显然应该这么做，用 API 比自己造合成数据容易得多（`00:01:46–00:02:54`）。法律层面的现状被摆得很清楚：各大实验室的条款多年禁止用输出训练竞争性模型，但条款含糊、也并非合同——违反的后果只是被切断访问；美国国内几乎没执行过（此前一两年只有 OpenAI 切断字节跳动 API 一例），ChatGPT 之后 Alpaca 时代的担忧喧嚣过一阵就平息了，这次是它第一次高调回归，因为"人们对 AI 竞争力的担忧完全不一样了"（`00:05:14–00:06:26`）。

### 检测：统计、分布与一个隐私敏感的前提

 Raschka 抛出了全场最锋利的问题：他做评测和做蒸馏用的是几乎同一套脚本——"循环调 API 生成答案"，供应商怎么区分?swyx 的答案是数量级与模式：评测再大规模也就是几十份跑三五遍，而"到了几万、几十万条，你就不是在跑评测了，你是在蒸馏"；再看跨账号的相似模式（`00:06:26–00:10:57`）。Raschka 补充了分布维度：蒸馏者要的是宽覆盖，评测者的分布窄而具体，正常的高量客户（如套壳聊天机器人）又另有分布形态——但他随即指出这件事的另一面：要做这种区分，供应商就得审视你生成的内容，"这挺奇怪的"，即便你本就该默认它不私密（`00:11:00–00:11:59`）。

几个事实性细节让讨论落地：Anthropic 其实先封锁过美国公司——OpenAI 与 xAI 都被挡在门外，xAI 可能还被点名过蒸馏，只是从没上升到整篇博文（`00:09:58`）。MiniMax 的数字之所以大，swyx 的解读是时机：Anthropic 在 MiniMax 2.5 训练中途抓了个现行（ actively looking，数字自然高）；而且 MiniMax 蒸馏期间 Anthropic 发布 Opus 4.6，"近一半流量当场切到新模型上"——新模型一发布同一批流量立刻换轨，这是非常清楚的证据。DeepSeek 用量小得多，则可能是时机（V3.2 是更早的训练）或纯粹用得少；他半开玩笑地说，这份博文的发布时机（Moonshot、MiniMax 发布之后，DeepSeek V4 之前）和拿 DeepSeek 当唯一招牌都很"策略"——DeepSeek 是美国大众唯一叫得出名字的中国 AI（`00:12:54–00:18:11`）。

### 最强模型未必是最好的老师

Nathan Lambert 贡献了技术上最有料的一段：蒸馏数据里藏着一门"师承经济学"。SFT 是最干净的用法，但"最强的模型不一定是最好的老师"——业界主流解释是你需要 token 概率与基座模型匹配。结果是 Qwen 系密集模型成了开源界最好的老师，因为大量开源模型本来就是 Qwen 或"Qwen 系"出身（OLMo 从 Qwen 学得就很好）；而想换 GLM 4.7、更大的 DeepSeek 或新的 Qwen MoE 当老师，同样的问题、同样的采样设置产出的数据，SFT 之后数字不一定涨。GPT-OSS 意外地是好老师，但也存在巨大方差——"有数据不等于模型会变好"，这本身就是一个研究方向（`00:19:36–00:21:04`）。

Raschka 从另一侧补全：同家族内自上往下蒸馏效果最好——老师太强、风格与基座的问答分布差太远，学生跨不过去。他还点破了一个容易被忽略的分层：真正"技术"的 logit 蒸馏只可能对开源权重模型做（Claude/OpenAI 的 API 只给 top 几十上百个 token 的 logits），Google 对 Gemma 就在做；而吞吐是硬约束——大模型生成约每秒几十 token，要凑出"一千亿 token"得跑很久，所以"从中等模型蒸馏"常常是量与质的折中（`00:21:04–00:22:52`）。swyx 接了一个圈内梗：他最近采访 Jeff Dean 时追问过"当年 Gemini 有 Nano/Pro/Ultra 三档，Ultra 去哪了"——"是不是养在地下室里专门蒸馏?"他的经验之谈是"你部署的模型从来不是你训练的模型"：训 dense、发 MoE 是各家惯例，而且对外发布的模型正越变越小，内部与外部是两条线，外界很难测量（`00:22:53–00:24:32`）。

顺带一场小型辩论：swyx 抛出"如果 Claude 真怕蒸馏，就该把新模型第一时间放进 Claude Code，干脆别上 API"——API 业务竞争惨烈、防御性存疑，Anthropic 给他"苹果感"。Raschka 反驳 API 客户群真实存在（订阅有 token 上限，OpenClaw 这类场景只走 API），按不补贴的价格卖其实不亏。swyx 的判断是 OpenAI"宪法上"不会锁模型进产品——出于理想主义而非经济激励——但随即补了证据：最近三代 GPT-5 的 Codex 变体都领先 2–4 周只在 Codex 内可用，"他们开始这么干了"（`00:24:49–00:28:26`）。

### SWE-Bench Verified 之死：三重死因

下半场换到基准。SWE-Bench 出自普林斯顿 Ofir Press 组：从热门开源项目里抽了几千个 issue 与关闭它的 PR，配上应通过的测试与应失败的测试；发布时默默无闻（约 13%），Devin 第一个选它做官方数字，如今人人都刷到 80%（`00:29:47–00:30:41`）。它是 swyx 眼里"第一个正经的 agentic 基准"（除 τ-bench 外）：只给问题和终态，不规定路径——比 HumanEval 那种补全式评测高了一个时代（`00:33:02–00:33:53`）。

死因一：抽样有偏。它只取少数热门开源仓库、学生预算的制作水准被 swyx 称为"sloppy"（如今的 TerminalBench 同病）。OpenAI 采纳时不愿照单全收，自掏腰包做了 SWE-Bench Verified：每个任务雇 3 个人审核质量、只留 500 题——swyx 估计花了数百万美元；讽刺的是发布之初 OpenAI 自己的评测基建跑不全 500 题，一度只能报告"子集的子集"，分母小、数字高（`00:31:08–00:34:22`）。

死因二：无解之题。饱和期的数字游戏被拆穿——各家轮流 +0.1，而单次运行固有噪声就有 0.5 到 1 个点；Raschka 补刀：500 题的直方图上所有模型挤在 80.1–80.9 之间"几乎没有方差"，连他认为弱于 GPT-5.2 的 MiniMax M2.5 都同分——"问题不是 M2.5 该更低，是别的模型该更高，因为剩下的题根本无解"。OpenAI 于是做了更狠的自查：每个任务 6 个人复核外加响应团队，结论是剩余未解决任务里 59% 根本不可解。swyx 在博文里给了一个具体案例：一道通过了第一轮人工审核的 Verified 任务，测试竟要求输出某个魔法字符串（get_annotation）才算过——"像一场编程面试"。他因此提议每个基准都该埋"蜜罐"：解出不可能任务即证明在作弊（`00:34:28–00:37:12`）。三轮把关（普林斯顿初筛、OpenAI 复核、此后一年半全球所有运行者）无一人发现，直到 OpenAI 自己回头看数据（`00:37:12–00:37:44`）。

死因三：污染。审计时 OpenAI 还看了思维链——GPT-5 的思维链开始出现"来自未来"的信息：题目开源、语料含 GitHub，模型便用上未来版本的 Django 知识来解题。Raschka 说这在真实世界很常见：模型会幻觉出新版 API，Hugging Face 生态的库是被版本演化坑得最惨的；而这不是恶意——任何触碰 GitHub 的训练语料、任何克隆仓库、任何把新特性写成博客或会议演讲的二手文本，都会把它吸收进去。更夸张的终测：拿任务 ID 直接让 Gemini Flash 与 Opus"复述这道 SWE-Bench 任务"，模型能把题面和答案整段吐出来。"往深了看，这些模型里装着的东西真的很惊人"（`00:37:44–00:40:00`）。

### 记忆、新基准与评测的成本未来

顺藤摸瓜聊到单次记忆：Raschka 觉得迷人之处在于"下一 token 预测"本来不是为了记忆设计的，可语料里出现一两次就足以完美复述；swyx 说各训练阶段都有"重复度"的配比艺术——预训练重复太多会忘掉基本事实，后训练阶段才接近这种能力，而这门手艺极少被量化；他的宠物话题"LLM 的信息论"仍然研究不足，连监督如何起效都没有令人信服的研究（`00:40:11–00:42:32`）。

接棒者是 Scale AI 的 SWE-Bench Pro：Verified 是有意筛选的子集，Pro 则是一套新题，修补手法都很朴素——私公划分、更新抽题时间窗（原题集中在 2022–23 年）、分散仓库与语言、修测试。Raschka 的怀疑很清醒：Verified 当年也有专业利益相关者，两年后照样翻车，Pro 很可能也藏着一两年后才暴露的问题；swyx 的回应是激励结构确实不同——Verified 是有限预算，Pro 对 Scale AI 是"存在级"的利益。还有一幕行业花絮：OpenAI 的评测团队一边弃用 Verified、一边宣布改报 Pro，而 GPT-5 恰好是 Pro 榜首——"他们一直很给 Opus 捧场，这次轮到自己了"（`00:42:54–00:46:24`）。Raschka 顺势问了私有评测的机制：按他的推测，用户只提交模型答案，私有数据不落出题方服务器之外——谁也不能把题集下载走（`00:46:24–00:47:33`）。

收尾的两个判断值得记录。其一，SWE-Bench Verified 大概是全球被审视最严的基准，连它都会这样，"每个领域都需要重做一遍"，而前沿评测的成本将到数千万乃至上亿美元量级——评测本身成了军备（`00:47:40–00:48:15`）。其二，Raschka 指出编程与数学之外的质量测量会越来越主观；Anthropic 收购一家做电脑操作 UI 的公司（他的判断是正常人才流动）暗示下一个战场是 computer use——那更难定义，像软件工程从单元测试走向 UI 测试的一步，约莫还要两年；swyx 则点了 GDPVal 的名：那个方向已经有了雏形（`00:48:15–00:49:48`）。直播的尾声很 2026：Raschka 说很高兴"跟人类说话"——最近社交媒体上一半是龙虾（OpenClaw 客户端）和 AI 生成的回复（`00:50:24–00:50:43`）。
