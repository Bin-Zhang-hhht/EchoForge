## 速读

swyx 走访 Cursor，与两位"创业后加入 Cursor"的负责人对谈：Autotab 创始人 Jonas 与 New Computer 联创 Sam Whitmore。这期节目发布的数据点本身就是新闻：在"VSCode 分叉"的原型公司里，云代理的用量已正式超过 Tab 自动补全——第一波 AI 编程的标志性交互被第二波超越，Cursor 称之为"软件开发第三纪元"。

最值得带走的三点：云代理的三支柱是把"模型当同事"具象化——它自己起 dev 服务器做端到端测试（默认校准式测试，琐碎文案改动不测）、剪出功能演示视频、并把整台 VM 的桌面与终端远程遥控权交给你；Autotab 时代学到的"AGI 原教旨主义"是这一切的底层哲学——给模型像素、给模型一台完整的电脑，"瓶颈应该只剩智能"；以及吞吐量思维——10 人创业公司正在需要万人公司才需要的工程管线（发布阶段、回归检测、堆叠 diff、合并队列），因为"解决一个瓶颈会冒出三个新的"。

## 主题正文

### 三支柱：自测、视频、遥控

 Jonas 先纠正了一个误解：云代理不是"买了 Autotab 换个壳"。此前的云代理跑在空白 VM 上，只能"侧读代码"——"把自己放进模型的鞋子里：token 从眼前流过，你只能吐出 token 祈祷自己写对了？没戏。你显然需要运行代码。"新发布的三大支柱由此展开（`00:00:53–00:04:29`）。支柱一，测试：演示里那个代理干了半小时，因为不只写了代码，还起了 dev 服务器端到端测试、按需迭代，交回来的是"我测过了的 PR"而非"我试了几样的 PR"。他们的直觉泵是：人类同事给你一个没测过的 PR 你也会烦。测试是默认但校准的——琐碎文案改动不测、复杂功能必测，用户还能在 agents.md 里写规则或用 /no-test 关掉（`00:02:00–00:04:29`）。支柱二，视频：当 Agent 能写更多代码，"审查"成了新瓶颈——看 22 秒的演示视频比瞪着 700 行 diff 容易得多。它甚至会自建 storybook 式的组件画廊。视频不是代码审查的替代品，而是"值不值得继续迭代"的入口（`00:04:29`）。支柱三，遥控：通过 VNC 对 VM 桌面与终端的全权访问，视频不完美时可以亲自上手、拿到"活预览"。

最妙的演示是"保存密钥的错误提示"改造：为了让超长密钥触发报错，模型没有笨笨地敲五千个字符，而是自己打开开发者工具、写一段 JS 把 5000 个字母 A 粘进输入框、点保存、截下新错误信息——零提示词，前端后端端到端。swyx 感慨：一年前模型根本做不了这些，"六个月前都不行"，大约从 Sonnet 4.5 开始"纯像素自动化"才够用，而 Opus 4.5、4.6 与 Codex 5.3 是自主能力的又一次台阶（`00:08:00–00:09:00`）。

### Autotab 的遗产："盒子里的大脑"

Jonas 复盘了 Autotab（2023 年创立）的教训：当年做过 browser use、DOM 操作等各种方案，最后变得相当"AGI 原教旨"——"给模型像素，给模型一个盒子：你要的就是盒子里的大脑，把上下文与能力的限制都拆掉，让瓶颈只剩智能本身。以今天模型的聪明程度，这是个很远的瓶颈。"给模型一台按人类方式完成 onboarding 的完整 VM，是内部使用量从"改改文案"跃迁到"真用它开发新功能"的关键（`00:07:46–00:09:00`）。另一个产品化的遗产是 /repro 命令：对 bug，模型先复现（剪一条" bug 复现"视频）、修复、再复现验证（剪一条"已修复"视频）——这类"难以本地复现、修了也不确定"的问题，从"改几小时还不放心"变成"90 秒合并"。有个案例还相当 meta：修的是"图片移除后仍被附带提交"的 bug，验证方式是让 Cursor 代理在 VM 里打开 Cursor 代理自己提交 prompt（云代理不能生成云代理——"目前禁止，也许哪天允许"）（`00:10:00–00:13:00`）。

工具面还有两件内部利器被曝光。一是 Bug Bot 及新发布的 Auto Fix——"别留着 Bug Bot 的评论不处理"已是团队信条，因为"有两三次你合并完回头发现 Bug Bot 早就指出了那个 bug，你就学会等它了"。二是 Samantha 最爱的 cloud agent diagnosis：用 Datadog MCP 拉起一群子代理翻日志定位问题，把调试从"人肉翻日志"压成"一次 Agent 调用"。更进一步的玩法是给代理喂另一个代理的完整 transcript——让它是外部调试者，或者像 fork 一样续跑对话；底层都是同一套云代理设施与 harness（`00:14:00–00:17:00`）。swyx 顺势点出行业难题：Datadog 这类"记录系统"公司面对编程代理该开放日志还是自己做闭环（他们也有 cloud agent 产品 bits）——"你愿意把多少交给别人？"

### 三个纪元：从 Tab 到 Slack 里的开发

那组"代理超越 Tab"的数据被放进了 Cursor 的叙事框架：第一纪元 Tab/补全（月费 20 美元）、第二纪元本地模型迭代（数百美元）、第三纪元云代理长驻自己的 VM（每人每月数千美元，"可能到数万"）——Jonas 主动点名了 Jevons 悖论："不是我们贪心，是个人获得的杠杆变大了；一个人能干十个人的活，那个工具就值这个价。"（`00:50:00–00:51:00`）被问及"手写代码"时，两人笑称现在把敲字母叫"hand coding"，"你这么 boomer"（`00:18:19`）。

Samantha 分享的内部变化更有社会学味道：开发从个人活动变成了协作活动——"Slack 几乎成了我们的开发环境"。issue 频道里 @ 一下 Cursor 就拉起云代理，团队成员可以在同一线程里补充上下文；代理甚至会跑 git blame 后 @ 相关负责人进场；一条线程从讨论走向 PR、产物可见、众人拍板合并。人类在_threads里讨论的，恰好是"真正有趣的那部分"：要不要上、UX 对不对、形态合不合适——而不是"这个 if 放哪"。她说得直白："再也没有'这事你做还是我做'的讨论了——Cursor 在做，你只需要决定喜不喜欢。"当前的产品取舍是：Cursor 在线程里不会主动插话，必须被 @ ——swyx 提议的"让人类先私下商量、别让代理抢答"的静音按钮是真实需求（`00:19:00–00:23:00`）。

### 生产管线：10 人公司需要万人公司的基建

"解决一个瓶颈，冒出三个新瓶颈"在这个语境下的版本是：生成代码容易了，"把它送进生产"成了新的堵点。团队内部的玩笑是，讨论功能时总有人说"我已经有个 PR 了"，但离"有信心合并"还很远。Graphite（被收购的堆叠 PR 工具）是答案的一部分，目标显然是端到端：Cursor 不只想帮你生成代码 token，而是想帮你"创造软件"的全流程。审查被拆成分层：代码级（Bug Bot，同步等它）、功能级（视频+人工），将来还会有性能级、安全级（`00:23:00–00:25:00`）。更宏观的判断是：当云代理把并行度与代码产量拉满，"10 人创业公司会需要 1 万人公司当年发明的那些东西"——频繁或分阶段发布、检查点、自动回归检测、堆叠 diff、合并队列。swyx 补了一个观察：多数人还不知道 stacked diffs 是什么，而 GitHub 的美妙之处在于它对单人开发者也有用——开发者工具很少完成"从大到小"的普及，Cursor 则是反过来"从小到大"长大的（`00:25:00–00:28:00`）。

产品的极简哲学也体现在"砍功能"上。Cursor Web 有意不做文件编辑器——"限制你能做的事，人们就会更自然地把活交给代理"。swyx 拿 OpenAI 的 Codex 应用比较过这个"设计味道"（它有文件查看器但没有编辑器），Jonas 的立场是最终要提供全谱系——"在高抽象层工作，也能双击进到最低层"——但在某些界面（比如 Slack）上，限制反而是更干净的体验（`00:31:41–00:34:38`）。他们甚至"unship"过本地浏览器 iframe 端口转发方案（远程桌面延迟已够低、更通用）。至于 swyx 煽动的"全栈 Cursor"（自带部署、日志、上线站点，对标 Lovable/Bolt/Vercel），Jonas 的回应很有分寸：逻辑成立，但当前最大的瓶颈是把代码送出去，而且"零到一的 greenfield 和既有软件是两个问题——想象去说服 Shopify 把部署搬到你的平台上"（`00:34:38–00:36:34`）。

### 模型议会、子代理与 grind mode

模型选择正在"消失"进默认值：桌面端已有 auto 路由，云代理也会跟上——"我们有 Sam 这样精确知道自己要什么的人，也有希望我们替他选的人；我们既有流量又有内部品味"。swyx 的论题是：每个 Agent 实验室最终都会有路由器，因为用户会停止对单一模型实验室的忠诚。更激进的玩法已经内测：best-of-N 并行跑多个模型（各自独立的 VM，互不杀端口；本地 worktree 方式正在被淘汰），以及 Ian 写的 /council 命令——Karpathy（逐字稿作 Andre）管这叫"模型议会"。Samantha 还透露一个去年未上线、可能回归的实验：在 best-of-N 之上加一层"会写代码的合成代理"——不只投票，还综合多个模型的learnings写出一个新 diff；当时发现用不同供应商的模型做基底会有"协同效应"，比统一的模型梯队更好（`00:36:34–00:41:41`）。

子代理被定位为上下文管理工具：主代理用通用的任务接口按需拉起（说"探索我的代码库"可能拉起 5 个 explore 子代理），内置的 computer-use 子代理专门承接轨迹长、图片多的验证任务；子代理边界还是压缩点——把漫长的 rollout 与测试压缩成一条消息传回父代理，而不必全局压实。演示里能看到智能路由：主模型是 Opus，explore 子代理在底层跑更快的 Composer（`00:41:41–00:44:48`）。至于内部称呼为 grind mode 的长时运行代理（选择器里叫 "grind until done"），源自同事 Wilson 的实验——与网上流传的 Ralph Wiggum 循环不谋而合：给定完成标准，不达目的不罢休。但实现里有关键的 adds-on：先有对齐与规划阶段，双方认可计划后才进入执行——"如果它只跑三分钟，提示词随便写写没事；要跑三天，你最好花几个小时把需求说清楚。"而且他们真的是三天——数月无人工干预的长跑纪录在该团队内部已经出现（`00:44:48–00:46:00`）。Jonas 把抽象拔高：长时代理是"一个工作节点"，而那个用代理军团做出浏览器、又做出 OS、最后"重新发明软件工程组织架构"的实验是"工人与规划者的社会"——单节点吞吐不够时，社会自然涌现。

### 吞吐、记忆与"代理的自我认知"

团队的世界观用一根水管概括：编码是水管里的水，接下来几个月的大解锁不是"让水流更快"，而是"把管子加粗"——代理蜂群与并行代理。"当你见过一百个并发代理每秒吐出几千 token，你就回不去了。"副作用已经出现：他们的 GitHub Actions 被自家代理的提交洪流冲垮了——"人数涨 10 倍，代理跑 10 倍，这些系统都得适应"。由此推到基础设施：swyx 提到内存芯片短缺，Jonas 的判断是"即便是最乐观的算力建设预测，也低估了蜂群系统咀嚼代码的规模"（`00:46:00–00:49:00`）。

记忆被列为云代理最大的短板与下一个解锁。环境侧已经做了 cursor.com/onboard（选仓库、加密钥、代理自己安装一切——Sam 和 Jonas 为此熬了多个深夜），但"配置不是一次性状态"：依赖会更新、数据库会搬家。认知侧则更深：模型要知道"这个代码库的后端怎么起、状态怎么查"这些 quirks——"在环境里 onboarding，也在'如何做这个代码库的好开发者'上 onboarding"。Samantha 这一年对记忆的思考转向了两点：一是"动态文件上下文"路线（团队博客有述）——给代理指针与标注，而非塞满上下文；二是把记忆视为"代理自我审计"的子集——代理发现自己 harness 里有功能缺口时，可以自行提议标注、链接或记忆文件来填补，还能发现自己 rules/skills 互相冲突、顺手修掉自己遇到的 devex 问题。Jonas 由此推到那个略带科幻的问题："当模型开始编辑自己的系统提示词，那意味着什么？怎么安全地做？"——他的判断是它终将管理自己的上下文，而系统提示词就是上下文的一部分。Samantha 立刻厘清术语：这里的 self-awareness 不是意识，而是"知道自己运行在什么系统里、系统的约束是什么，并有能动性把自己在该系统中优化到最好"。她从 New Computer 带来的第一课恰好是反面教材：产品能做很多事却不知道自己能做——"它既要能做到，也要完全知道自己能做到，这两件事并不天然等价"；用户还常把"更自知"误认为"更聪明"（`01:00:24–01:05:00`）。

### 定价、招聘与小预测

定价曲线被明确讲成三段论：Tab 时代 20 美元/月，本地代理时代数百美元，云代理时代每人每月数千美元、"可能上探到数万"。Samantha 对就业的回应很个人化："近期我不担心开发者失业——要建的东西太多了。我比以前更忙、用更多 token、做更多事。"个人预测上，她押 12 月自己手写代码归零（现在约 1%，仅限烦躁时的单行修改）；Jonas 则承认自己仍手改提示词——"那是赤裸的意图传递，像写文章：写作过程就是思考"。语音编程被两人一致判为"最难的部分"（大小写拼写没法口述），Autotab 时代的教训是用户会不自觉地用"Siri 腔"——短句、夸张咬字——"Apple 毁掉了一代人对 AI 语音的预期"；正确姿势是"全部倒进来，重复、矛盾都没关系，模型足够聪明"。Jonas 的年度预测：云代理的用量将在年底前超过本地代理，且达到两倍以上；短期短板是沙箱质量与 onboarding 速度。招聘标准则与 OpenAI/Axiv 的答案殊途同归：不要求"已经擅长 AI 编程"，但看重"跟上变化的好奇心"；基本功仍是硬门槛——"模型放任太久不清理不重构，代码会变糟、抽象会变烂，你仍然需要造过系统、认得好模式、知道往哪儿掰的人"（`00:51:00–01:06:00`）。
