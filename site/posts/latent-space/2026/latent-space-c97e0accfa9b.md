## 速读

这期讲 Resend 创始人 Zeno Rocha 如何“为 Agent 设计”邮件基础设施：10 万封邮件进收件箱的批次与 IP 池工艺、默认信任的风控哲学、从 SES 走向自建金属、每月翻倍的 MCP 调用与 80 多个工具，以及 FAQ 化、llms.txt 和定价页纠错等 AEO 实战，最后回到 YC、设计与家庭的取舍。

触发这期节目的由头很具体：swyx 的 Cloudflare 邮件早已配好，编码代理却一再向他推荐加 Resend——他把这当作“答案引擎优化（AEO）”从接收端看是什么样子的样本。Rocha 给出的规模数字是节目中的说法：截至录制当天早上 430 万用户、客户含 Warner Bros 与 HBO、12 万付费客户（`00:03:32`–`00:03:52`），去年 12 月用户数还是 100 万（`00:18:55`–`00:19:19`），自称 ARR 1000 万美元的公司（`01:21:15`–`01:21:44`）。他也保留了明确的条件与分歧：邮件送达率做不到“拿 GPU 硬堆”，开信率在 Apple 隐私改动后已不可靠，SDK 全部人工手写而非生成，而“下一代 SendGrid”在他看来还谈不上品类创建、只是品类主导。适合做面向开发者产品的创始人与负责分发的人听。

## 主题正文

### 为什么要做邮件：一个没人服务开发者的老市场

节目开场提到，Rocha 曾位列 GitHub 年度最活跃用户前二十（2020、2022 年前后），后来以 Dracula 主题为人所知（`00:01:24`–`00:01:34`）。他坦承自己是前端出身、没有邮件和基础设施背景，如果早知道邮件有多难，“可能就不会创办这家公司”；让他入局的是多年使用 Mailgun、MailChimp、SendGrid 的体感——市场大、玩家多，却没有人在乎开发者画像，“也许他们在乎市场人员或产品经理，但不在乎开发者”，于是他按“如果这是邮件界的 Stripe，它该长什么样”来搭建产品（`00:01:58`–`00:02:55`）。

更深一层的判断是：每一代技术都有自己的定义性工具——Heroku、Netlify、Vercel 都当过那个角色，而新世代的工具不会再分布在原来那些地方。所以他从第一天起就要求团队“当有人问起这类问题时，我们必须是第一名”；主持人 swyx 补充的观察是，Claude Code 有超过 60% 的时候在推荐 Resend（`00:06:15`–`00:06:50`）。

### 规模数字与竞争格局

Rocha 报出的数字都应视作当事人说法：430 万用户、Warner Bros 和 HBO 等大客户加大量独立开发者、12 万付费客户（`00:03:32`–`00:03:52`）；去年 12 月用户数是 100 万，如今 400 万——他说“堆人解决不了支持问题”（`00:18:55`–`00:19:19`）。对标 SendGrid，他早年觉得“不可能打得过”，今年 SDK 的 NPM 下载量反超，如今已是两倍多；但他自己也补了条件：论实际发送的邮件量，绑定大企业客户的 SendGrid 仍远大于 Resend（`00:28:11`–`00:28:50`）。

谈到 Twilio 收购 SendGrid，主持人估计 Twilio 是一家 130 亿–150 亿美元的公司，逻辑是做横跨渠道的通信平台；Rocha 一方面敬佩 Twilio“发明了 DevRel”，另一方面对 101 大楼广告牌换上其他客户的现状感到愤怒——“你冷落了让你走到这里的东西”，并认为前 CEO Jeff Lawson 离开（买下 The Onion）之后 Twilio“在沉睡”，SendGrid 如此，SMS 也是如此（`00:28:57`–`00:30:01`）。他从这段历史里提炼的问题是：规模也许没有必然优势，“做出更好的产品就能慢慢追上”；至于当年为何是 Twilio 收购 SendGrid 而非相反，他的解释是 SMS 规模更大，而邮件和通信越像商品、毛利越薄（`00:30:01`–`00:30:43`）。渠道取舍上，SMS“总有一天会做”，WhatsApp 在很多国家很重要但要经过 Meta 且商业消息即将收费，电话和群发 DM 兴趣不大，Slack 值得关注（`00:30:43`–`00:31:52`）。

公司侧，主持人概括其团队约 50 人全球远程；销售动作刚刚启动，目前只有一名 AE，Rocha 说很幸运走到今天都没靠这套机器，且刻意分阶段开启以免伤害文化——“一两笔大单让 ARR 翻倍”是个好信号（`01:12:15`–`01:13:32`）。他的一个学习是：企业客户“其实是另一个产品”，只把 SSO、SCIM、审计日志放上定价页远远不够（`01:13:43`–`01:14:29`）。商业模式上，行业惯例按联系人计价，但这套模式正被增长极快的 AI 客户打破——他点名 Mistral 在用 Resend、增速惊人，Resend 也在设法修正；主持人则提到自己每年付 Substack 约 1 万美元发邮件、觉得太贵（`01:14:38`–`01:16:51`）。被问到 10 万封营销邮件是否该 10 分钟发完时，Rocha 的回答是按现行默认限速要超过一天，主持人惊呼“不可接受”、得多付费换队列；他把这比作模型 API 的速率限制（`01:16:10`–`01:16:51`）。

### 高量送达的手艺：逆向工程滥用者

Rocha 反复强调，高音量下把邮件送进收件箱，完全不同于“扔 GPU”式的应用扩展——Gmail、Outlook、Yahoo 各有各的规则，这是一个“老派、靠人脉”的行业；而团队对这个世界的彻底无知反而成了最好的事，因为没有先入之见（`00:07:15`–`00:08:07`）。同行的做法是注册时填表申报发送量、再过一道人工审核，多数人会被拒；他觉得这不合理，决定把摩擦全部转移到自己身上——如今三年多过去他理解了：行业里到处是欺诈、钓鱼和滥用，Resend 内部为此建了大量系统，只是很少公开谈（`00:08:07`–`00:08:53`）。

架构层面的手艺包括：给 10 万人发信时直接全量砸向 Gmail 会被节流，服务商要看的正是第一批收件人是否打开、归档还是立刻删除，并据此处置剩余邮件——所以要把互动最高的用户排在队列最前面，批次之间留间隔、在服务商之间错开，还要购买 IP 段、审查其历史、把用户分进不同 IP 池并随时间再平衡（`00:08:53`–`00:10:49`）。对新客户限速本身是保护发送者：服务商想看到持续爬升的曲线，而“一周猛发一次然后沉寂”正是滥用的形状（`00:10:03`–`00:10:49`）。滥用者画像有现成教材——他提到近期有一伙日本客户一次性带来约 2 万个域名、注册在不同注册商手里；两天前新买的域名信誉很差、网站是否返回 200、仿冒域名看起来就像钓鱼、一次性群发后不再发送，平台要做的就是把钓鱼的逻辑逆向出来、反着做（`00:10:49`–`00:11:54`）。

产品层面的原则是“让平台替用户学习”：把洞见做进产品里，发送前提供链接检查、拼写检查（如今还有 AI 参与）；一个典型决策是自动从 HTML 提取并生成纯文本版本一起发送，送达率因此大幅提升——垃圾过滤器直接读纯文本要容易得多（`00:12:07`–`00:13:29`）。追踪机制也有一笔账：开信追踪靠 1×1 透明 GIF，但 Apple 的隐私改动（预读邮件做摘要）让开信率整体不再可靠，只能依赖点击追踪；而点击追踪要求链接和图片 URL 与发送域名一致——把链接重写到自己的域名（Resend 早期也这么做过）会引入噪声邻居问题：一个滥用客户就能让共享域名进黑名单，解封要几天到几周（`00:13:29`–`00:15:22`）。风控哲学上，他宁愿“生而自由”：默认信任用户，但一旦退信率、投诉率或邮箱服务商的反馈出现异常就立刻封锁、再沟通——多数情况是误用而非滥用（`00:15:22`–`00:16:49`）。

行业层面还有两笔干货：发件信誉已从早年“以 IP 为中心”转向“以域名为中心”，用子域名把事务邮件、营销邮件分开可以隔离声誉——Resend 自己连投资人邮件都走独立的 confidential.resend.com（`00:55:54`–`00:57:16`）。市场份额方面，他说至少 60% 是 Gmail，其后是 Outlook、Yahoo 等几家；Apple 会自动生成转发邮箱地址、审核更严格，Resend 甚至做了产品内向导帮域名所有者向 Apple 注册以保证送达（`00:54:30`–`00:55:54`）。对“买一堆 .com 提升送达”的民间偏方，他以可口可乐为例：另买一个长得像的域名恰恰最像钓鱼，风险远大于收益（`00:57:26`–`00:58:20`）。

### 支持、DNS 与 Domain Connect

他把支持体系比作软件：“如果支持是一个软件，我们大概在 major version 4。”第一版是他本人坐在工位上接工单、压力大到崩溃；第二版招了懂领域的人，但仍不主动沉淀文档；随后定下一条著名的政策——回复工单只能附链接，不许直接给答案，逼着团队先写博客、文档或知识库文章，一单要花一个半小时，却攒下了知识库（`00:17:40`–`00:19:19`）。用户过百万后堆人失效，只能从零重新设计；免费层则必须保留——“我们这代人是因为 Heroku 免费层才走到今天的”（`00:18:55`–`00:19:39`）。如今大多数支持问题其实是 DNS：Lovable、Bolt、v0 带来了一批不会排查问题的新用户，不知道 CNAME、A 记录、TXT 该填在哪；主持人 swyx 顺带说，他现在用 Codex、Claude Code 这类 computer use 工具全权管理 DNS 记录（`00:20:00`–`00:21:05`）。

Resend 的解法之一是押注 Domain Connect——一个极少有人投入的冷门协议，他称之为“域名的 OAuth”：两边各是 DNS 服务商与服务商，Cloudflare 已在列，他们还说服了 Vercel 加入；但这是个疯狂的行业，GoDaddy 收费高昂，Ionos 谈判拖了好几个月，协议也没人认真维护（`00:21:05`–`00:22:31`）。更宏观的教训是：这个行业极度依赖关系，他们没有，只能雇佣来自 Postmark（创始团队时期）和 MailChimp（十五年前）的 deliverability 老兵、借他们的网络，还多次“不得不拿起电话”；他庆幸自己选的是基础设施即服务，而不是纯 SaaS（`00:22:38`–`00:23:55`）。

### 从 SES 起步到“下到金属”

公司起步时的开源漏斗是刻意设计的：React Email 之于 Resend，如同 Next.js 之于 Vercel——他亲自给 SendGrid、MailChimp、Mailgun 写过接入文档，“先给、给、给，然后再要”；用户用 React 搭好邮件模板后，自然需要发送平台（`00:23:55`–`00:25:53`）。模板之痛也是在做 Resend 期间做用户研究问出来的：设计师给的是 Figma 文件，落到邮件里就是 HTML 表格、切图、全内联 CSS，Outlook 还要特殊注释。React Email 的本质是个编译器——写一次、适配 API、到处能用，还能导入 Tailwind tokens、享受 TypeScript 类型校验；邮件里跑不了 JavaScript，没有交互和折叠面板，JSX 只是模板（`00:25:13`–`00:26:39`）。

发送侧则是另一条路径：Resend 最初也架在 Amazon SES 上，把创新集中在服务不足的 DX 层——为每种语言手写 SDK、给 Serverless 场景写“如何用 Lambda 发邮件”的指南；主持人补充的参照是 freeCodeCamp 五百万订户的新闻邮件跑在 SES 上、每月约 5000 美元（`00:32:01`–`00:33:09`）。但 SES 的隐性成本很快显现：要 SNS 接事件（退信、投诉、打开点击）、CloudWatch 看日志、SQS 做队列、再自建 webhook——“平台很好，但你的足迹很快就会超出想象”（`00:33:09`–`00:34:39`）。YC 系的 AgentMail 选择建在 SES 之上不与它竞争，Resend 则相反：如今“下到金属”自建基础设施，已经做了几个月，即将官宣；他认为到这个规模，在最低层创新才能换来更好的吞吐和送达率（`00:34:22`–`00:34:39`）。最难的部分是 IP——整段整段地买、自己管理 IP 池、对各邮箱服务商做流量控制、维持关系；回报是掌控力，尤其可观测性：一封邮件到底送达没有、进了垃圾箱还是推广 tab，过去只能猜，越贴近金属，能浮出给用户的数据越多（`00:34:39`–`00:35:59`）。

他把这条路径总结为 DX 类公司的通用剧本：从 React Email 这样的薄层起步、借别人的基础设施、上了规模再自建（`00:35:59`–`00:36:43`）。代价与反讽是：他花大力气把仪表板做得漂亮，如今客户却说“我从来不打开仪表板”；以及性能优先——P99 不该那么慢，这家 Node.js/TypeScript 全栈公司已在发送路径改用 Go，“现在语言不再重要，换门快语言重写太便宜了”（`00:36:18`–`00:37:33`）。

### API-first 与 MCP：为 Agent 设计的界面

Rocha 说自己不追“什么火什么凉”，而是想把产品做成“无形”的——什么都该能做，所以从第一天就是 API first，当时并不知道这份投入日后回报多大（`00:38:14`–`00:38:46`）。MCP 的数据是节目中的说法：每月至少两倍增长，8 月结束前累计调用已达约 120 万次，越来越多的人直接从 Claude Desktop 或 Codex 开始工作；主持人概括其曲线是从约 50% 的月环比加速到基本每月翻倍（`00:38:46`–`00:39:26`）。有趣的是，Resend 第一个 MCP 是 a16z 投资人 Yoko（逐字稿记音）以个人项目开源的本地版，走红后才移交组织（`00:39:26`–`00:40:11`）；做正式的远程版则倒逼公司重审整个权限模型——先建 OAuth、再补 RBAC、再上 Datadog 可观测，最后是艰难的分发：逐家去谈实验室、进官方商店和插件市场（`00:40:11`–`00:41:12`）。

主持人 swyx 用自己的钱包投票：他现在买 B2B 软件先看有没有官方 MCP——因为 Plausible 的 MCP 是 Sentry 代写而非官方维护，他把公司分析从 Plausible 换成了 PostHog；连跑步都用 Strava，只因它能接进自己的 MCP（`00:41:22`–`00:42:34`）。工具数量上他们站在共识的反面：上线时约 20 个，如今 80 多个还在加；把仪表板 100% 的能力（用量、计费、团队邀请、开通、注销）都暴露成 API 非常难，但“覆盖 90%”和“覆盖 100%”是两种产品（`00:43:22`–`00:44:14`）。主持人顺势提出 Next.js 的一个结构性错误：server components 让数据直绑页面、默认不会催生公共 API，理想形态是彻底 headless 的后端、前端只是客户端之一；Rocha 印证——Resend 的 API 最早架在 Next 上，账单高到付不起才迁到传统 Node 服务器，仪表板长期走私有 API、代码重复，如今全在 monorepo 里复用（`00:44:14`–`00:45:31`）。被问到“Cloudflare 只做两个工具，你们 80 个，什么会让你改变主意”时，他说自己靠亲自使用产品来判断——连发给投资人的更新都是用自家 MCP 抓取多家数据写成的（`00:45:40`–`00:46:25`）。

CLI 增长不及 MCP，但玩法同样激进：招聘页支持经 CLI 或 API 投递，CLI 里内置 skills，可以直接让 Claude “去申请 Resend 的产品设计师职位”；主持人质疑这是不是给自己灌 slop，Rocha 的回应是——CLI 来源的申请他会另眼相看，因为愿意下载、认证、走完流程的人本来就多走了一步，候选人自己也说“从没用 CLI 投过简历”（`00:46:34`–`00:47:58`）。SDK 策略同理：他优化的不只是旧金山那些网速快、设备好的“特权用户”，也包括糟糕 Wi-Fi 和 Windows 电脑背后的边缘用户——他在巴西长大；所有 SDK（Java、Rust、.NET）看过 Stainless、Fern 的生成结果后都不满意、全部人工手写，哪怕某个语言只有几百个用户（`00:48:34`–`00:50:04`）。

产品形态上，他认为邮件正从单机走向多人：编辑器支持多人实时协同，他甚至用私人 Resend 账号开全员大会——二十个人共写同一封邮件、最后一起按下发送（`00:50:29`–`00:52:04`）。收件端是下一个战场：他自己已经不读大部分邮件，靠一款记音为 Poke 的工具加两位真人助手；他正在做的方向是让程序化创建的大量收件箱能被 Agent 访问——Inbound（收信）只是最基础的抽象，往上是已读、星标、标签等 API，“全 API 驱动”，对标 Missive、Help Scout、Front 这类共享收件箱产品，即将发布（`00:52:57`–`00:54:23`）。

### AEO：从 SEO 落后者到被模型点名

Rocha 不讳言起点之低：2023 年出道时没几个人知道 Resend，Twilio、Postmark、Mailgun 在 SEO 上积累了十年以上，“想排上任何词都是硬仗”（`00:58:36`–`00:59:35`）。打法分两段：先做传统 SEO——长尾、超短的“如何用 X 做 Y”式文档；等模型起来后，把内容改成“一问一答”格式，如今几乎每个页面都带 FAQ，连安全页都要直接回答“Resend 是否 SOC 2 合规”（`00:59:04`–`01:00:12`）。然后是 llms.txt——先靠 Mintlify 覆盖文档站，再推广到每个营销页；每个页面都可以加 .md 后缀拿 Markdown 版，也支持内容协商（`01:00:12`–`01:00:54`）。

最能说明问题的是定价页故事：某个周日他让模型比较“发 120 万封邮件各家收多少钱”，结果 Resend 被答得面目全非，还被评价“定价非常晦涩”——问题在于 Agent 不执行 JavaScript 定价组件。他给定价页加了 .md 版本、把数据写成文本，几天后再问，数字全对；代价是没有单一事实源，改一处要同步改两处，“谁让我选了邮件这行”（`01:01:17`–`01:02:58`）。对比页做得不如竞对、反而更少被推荐，于是他们另辟蹊径做 /migrate 页面：粘贴任意代码块就转换成 Resend 的写法；新上的采用率对比图也吸取教训——同样的数据用文本写一遍给 LLM 读（`01:03:07`–`01:05:03`）。“如何接入 Claude Code / Codex”则单独做成 AI 页（`01:05:29`–`01:05:40`）。他观察到的规律是模型有新近偏好：至少 Opus 4.5 明显偏向较新的工具，而关于 Resend 的有机内容越多、被推荐的次数就越多——所以建议是“让更多人在更多地方谈论你的产品”；他从没请过 SEO/AEO 顾问（`01:06:03`–`01:07:30`）。

为什么这件事值得下血本？Rocha 的判断是：过去拿不准用什么工具会去问 Google、得到一串对比页，现在模型一开口就是唯一的答案，“最无摩擦的那个赢”，免费层因此更重要；他也提到 WorkOS 的 Michael Grinich 在推广“产品基本动作无需注册账号即可使用”的思路，但邮件行业滥用太重，他还在犹豫要不要做 provisioning API（`01:08:10`–`01:09:38`）。主持人 swyx 则展示了自己的 AEO 自动化循环：给 Latent Space 和 AI Engineer 各配一个 CMO Agent，让它们繁殖子代理做调研、他自己签批实验、接 Ahrefs 与 DataForSEO 作工具、自制 AEO tracker 看数字上涨；Rocha 那边是四个第三方订阅（Profound 等）全试了一遍，共同的不满是这类工具只会报告、给不出行动（`01:09:38`–`01:11:58`）。

### YC、设计与家庭：他把 ARR 和女儿放在同一个句子里

这期后半段转向个人。Rocha 为孩子离开了旧金山，如今更多待在巴西——第二个孩子即将出生；他来 YC 时女儿才一岁，周围几乎没人有家庭（`01:17:09`–`01:17:46`）。他报的是 2023 冬季批，目标直白：“做这一批 250 家里最好的公司，不是第四、第五”；但他后来想明白了 YC 没有赢家、创业是无限游戏——当年认识的人许多已经不在，联合创始人散伙、七次转型、公司死掉，而 Resend 还在；连域名都要买 resend.com 的 .com，“不做 .io”（`01:17:46`–`01:19:18`）。

他在节目里讲了个 Paul Graham 的故事：PG 说合伙人总告诫你们别做某事、你们偏做、几个月后回来后悔——他真的回去问合伙人“我现在有什么做错了”，一位合伙人答“你太在乎设计了，不在乎的话你会走得远得多”。这话伤到他，因为是真的——路演幻灯片确实漂亮但确实不重要；可几天后他想通了：宁愿做一个有自己认同、只有 1000 人用的产品，也不要 1 万人用但自己都不想打开的产品。何况这个行业里人人都是糟糕的产品，设计稀缺，正是差异化（`01:19:32`–`01:21:15`）。他给出的取舍陈述是全文的题眼：十年后女儿愿意跟他玩、公司是 1000 万美元 ARR——这好过公司 1 亿美元而女儿不想理他（`01:21:15`–`01:21:44`）。对品类，他有清醒的自我评估：Resend 目前还谈不上品类创建，只是品类主导——“下一代 SendGrid”的说法还没说清差异；主持人在此引 HubSpot 的 Dharmesh Shah 创造 inbound marketing 品类为经典案例，理想的品类命名只需要两个词（`01:23:26`–`01:24:35`）。
