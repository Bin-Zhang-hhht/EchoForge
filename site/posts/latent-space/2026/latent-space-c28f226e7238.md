对做企业级 AI 产品与金融科技的人，这期最值得看的有四层：一是产品判断——Codex 能给到一款成功产品的 80%，缺的 20% 决定成败，而其中 95% 的工作其实是初创公司也能做的；二是行业现实——第三方 MCP 连接器实测错误率高达 40% 以上，直接推动 OpenAI 把财报与市场数据内包进产品；三是安全设计——产品以人在回路为前提，把读写权限与审计嫁接到投行既有的层级复核链上；四是训练与评测——早期 RLHF 练的本来就是人类品味，而嘉宾认为当前没有可靠的金融评测，OpenAI 自家的 GDPval 已饱和失效。（`05:33–06:40`，`07:07–09:08`，`10:00–12:36`，`22:51–25:23`）

## 主题正文

### 从研究到部署：金融版 ChatGPT 的来路

Joseph Kim 出身研究侧，如今在 OpenAI 带金融服务的产研团队。他介绍 OpenAI 内部自称研究与部署公司，且有意按这个顺序排列：先看模型能力往哪走、能解锁什么，再考虑用什么产品形态把模型智能交给更多人。（`02:56–03:31`）

演讲前半段讲新产品：ChatGPT for Financial Services 是企业版产品，把消费级 ChatGPT 里好用的工具与体验，叠加企业层——公司专属模板，以及 Daloopa、S&P 等数据源。产品与 Morgan Stanley、Evercore 两家设计伙伴共同打磨，嘉宾称市场反响很好。演讲后半段则是前瞻：把模型改进的趋势线外推到 2027 年中与年底，讨论届时模型能做什么、在模型之上做产品的人该如何提前规划。（`00:56–01:22`，`01:24–01:47`）

一个关键事实是：OpenAI 为金融做的训练数据并没有留在自家产品里，而是上游并入主训练（他们称为 big run）——也就是产出 GPT-6 Astra、GPT-6.1 Astra 这类大版本模型的那条主线。金融智能因此对 API 用户、初创公司以及想直接集成的金融机构同样开放，嘉宾强调这是他们明确坚持的原则。（`02:14–02:56`）

产品侧的注脚是演讲里那张内部采用率图表：软件工程师使用 Codex 的曲线稳步向右上方走，而金融、法务、销售的采用原本接近零，突然跳升到约 90%；对照时间点，正是二月发布的 Codex 桌面应用上线之时。嘉宾以此说明产品与模型共同开发的必要性：产品面的意义就是让模型能力触达尽可能多的用户。这也是 OpenAI 少有的第一方产品——产品、模型 harness 与研究第一次放在同一屋檐下，团队为此做了约六个月。（`03:31–04:13`，`04:26–05:01`）

### 插件架构上的生意：95% 谁都能做，20% 决定成败

嘉宾给从业者最重要的判断是：他们构建的东西里，95% 是初创公司或任何公司都绝对做得出来的，并没有动用改动模型这种独家能力。（`07:07–07:37`）产品大部分建在 Codex——他随即改口说应称现在的 ChatGPT——的插件架构与插件原语上。他的团队在很大程度上就像一家搭建在 OpenAI 技术之上的初创公司：OpenAI 内部团队面临与外部开发者同样的问题，需要可扩展的方式站上 Codex 的肩膀。Codex 的记忆、技能与持久性都不错，团队的前提假设是 Codex 能给到一款能在市场上成功的产品约 80% 的完成度；但缺的那 20% 是关键，而且如果直接把 Codex 当金融产品发布，一定会失败。（`07:37–08:37`）

由此他给出对行业的判断：会出现一家建立在 ChatGPT 插件之上、十亿美元量级的生意。逻辑是横向能力全部继承，只需在顶层加自己的独门料——可能是数据、界面改动，也可能是某个集成。（`08:37–09:08`）

### 数据内包：被 40% 错误率推翻的连接器方案

回顾这六个月，嘉宾的最大心得是：做企业产品必须直面所在行业的现实去构建——竞争格局、各方各有诉求；从第一性原理出发推演出的方案听上去有理有据，但若无视行业现状与各方力量，就做不出对的产品。（`04:54–05:27`）

数据是最好的例子。纸面推演下，把财报电话会记录这类数据打包进产品是站不住的：应用商店里已有现成的 MCP 连接，客户可能已经买了数据授权，打包等于让人付两次钱，增量价值在哪里？（`05:33–06:01`）但他们实际测试了这些 MCP 连接器——包括一些大牌——错误率高达 40% 以上。看起来漂亮的东西，必须去看实际运行的数据。（`06:01–06:19`）结论因此反转：要在规模上修好数据体验，唯一的办法是把数据内包、端到端控制，为此多付的数据费用是值得的。上线后客户反馈里被点名最多的恰恰是数据——这项行业特定的产品决策得到了验证。（`06:19–06:40`）

### 安全设计：人在回路、读写权限与投行复核链

主持人提到智能体编排正在走向自动化、团队式智能体开始执行任务，金融场景风险很高。嘉宾的判断是安全的重要性只增不减：智能体正变得更自主、更独立，这个趋势他们预期延续到 2027、2028 年。（`09:26–09:41`）

已发布的这版产品定位是金融知识工作者的生产力工具，底层有一个很深的假设：人在回路。金融分析师每天有一长串任务，像软件工程师用 Codex 那样逐件先交给 ChatGPT——有的能完成 30%，有的能到 80%，取决于任务——但始终默认有人在其上监看工作。这个假设让产品可以把审计与复核的责任明确交回人手，也容易向客户沟通。（`10:00–10:46`）

下一阶段的思路是让产品的安全画像像一个人：人们对如何与同事、实习生协作有直觉，如果模型的工作方式与身边人一致，这套安全机制就容易上手、容易被金融机构接受。抓手之一是读写权限分级——嘉宾以自己在 Google 的经历类比：新工程师需要先取得 readability 认证才能修改代码；人尚且要过这套检查，模型的行为若像人，就能直接复用这些为监督人的工作而设计的系统。（`10:46–11:56`）另一条是银行业现成的层级复核链：初级分析师做大量粗活，工作交给经理复核，经理加上自己的推理再交给 VP，VP 之上还有总监与 MD——这套隐式工作检查本来就是为了拦住人的错误而建，而人犯的错并不比模型少。金融产品直接借力这套既有系统。（`11:59–12:36`）

### 错误的等级、品味的训练与失灵的评测

主持人提出金融圈的普遍顾虑：一次错误可能让整个职业生涯完蛋。嘉宾分两层回应。第一层，他先说这个观念本身不成立，但即便暂时接受它，错误也不等权：层级越高、赌注越大——MD 看到一个错误，说明层层安全网都已失效。真正致命的错误形态是把一条事实信息搞错、而这条错误又改变了结论；好消息是模型在细节与事实可靠性上的进步很快，2022、2023 年到处都在谈的幻觉，如今已很少被提起。事实类错误的持续改进，加上既有的层层检查，让这类错误传导到高层的概率变得很低。（`13:20–14:39`）第二层，模型今天真正欠缺的恰恰不是致命错误，而是涉及人类判断与品味的东西：一页幻灯片算不上错，但颜色不对、显得潦草，仍然影响工作成果的可用性。他预期 2027 年模型会在更软的目标函数上大幅进步——不是对或错，而是比较式的判断：有没有比这更好的。（`14:51–15:45`）

怎么把品味训进模型？嘉宾的回答带着一段历史：早期 RLHF 训的几乎全是品味——人类反馈本来就是成对信号，给两个选项，哪个更好；后来可验证奖励与环境等机制兴起，大家反而忘了强化学习早期就是围绕人类品味建立的。（`15:48–16:23`）技术答案至今朴素：训练一个奖励模型，让大量人类看成对样本并选出更好的那个。他们真的这样改进幻灯片生成：人类几秒钟就能判断两张幻灯片哪张更好，而评分模型要烧掉大量推理 token 逐项分析、最后还可能判错——在审美判断上人类远强于模型，人类偏好仍将是注入品味的核心依赖。（`16:25–17:12`）

先例是编码：编码没有完全解决，但大约走完了 80%，靠的是可验证奖励与人类品味的组合——能否编译、有无语法错误、函数输出是否符合预期是可验证的部分；而好的软件工程还包括系统设计是否干净、是否可长期维护、是否易于单元测试、是否符合业界主流范式。金融工作高度同构：Excel 模型能不能对上账、有无引用错误是可验证的第一道检查；老手扰动输入、观察输出，判断数据流过模型的手感是否顺畅——这与判断代码是否干净、写得是否漂亮是同一类人类偏好。编码上的成功让他们有信心在金融上解决同类问题。（`17:18–18:40`）主持人补充了一个视角：代码评测不止问答案是否正确，还有多个 PR 都能通过时你会合并哪一个的维度——这本身就是品味评测。（`18:40–19:00`）

接下来的路线是往上走。迄今 AI 在金融的应用几乎都停在初级分析师的工作上，原因有二：今天的模型擅长执行具体指令——做一页幻灯片、用指定模板做好看——产品体验因此围绕这些任务构建；同时人类本来就讨厌做 Excel 模型、在幻灯片上精确摆放 logo 这类琐碎易错的活，人类的好恶也在推动产品方向。（`19:33–20:52`）进入 2027 年，他们要从初级分析师的任务走向经理、再到 MD 的任务区间；越往上目标越模糊——一个投资想法好不好，要等大约三年才能由市场给出明确答案——训练与研究随之变难。嘉宾认为这不是不可解的问题：需要大量研究投入、好数据，以及业内顶级（p99.9）专家的反馈，再加上基座模型的持续扩展；他的团队正在把这件事变成 OpenAI 的优先方向，并因此对 2027 年的进展有信心。（`20:57–22:11`）

评测是这个计划绕不开的短板。嘉宾分享的先验是：做出一个好评测非常难——评测只是想测能力的代理，且只有单一维度；答案键与评分方式没做对，评测就极容易被 reward hack，分数很高、真实能力很差。他认为今天没有一个真正好的金融评测。（`22:51–23:51`）他们自己做的 GDPval——覆盖更广的知识工作——已经饱和，未饱和的部分基本失效，因此最近的模型发布已不再报告、不再追踪它；GPT-6 Astra 发布时也没有谈金融评测：内部有一些，当时不想公开，之后会来。（`23:52–24:25`）评测研究里还有一个偏差：数字好看时研究者就假定模型变好了、不再深究。GPT-6 跑一组金融评测数字几乎没动，他们深查后发现评测已饱和，做错题目的原因出在错误答案键、写得糟糕的 prompt 或评测本身的其他缺陷。（`24:25–25:05`）他团队当前的任务正是做一个能预测能否自动化某个职业工作的评测：比如投行评测——在这类评测上得高分，就意味着能自动化初级分析师的大部分投行工作。（`25:05–25:23`）

收尾信息：产品目前是企业版，团队正努力向 Pro 计划的 prosumer 开放；主持人预期这类能力最终会下沉到普通用户，通用 ChatGPT 在金融任务上会随之变好。团队也在快速扩张：前后端工程师；投行、股票研究与资管方向的产品经理——嘉宾称好的产品经理是他们在这个赛道取胜的最大瓶颈；以及领域专家（SME）——编码的成功有赖于训练模型的人本来就懂什么是好代码，金融没有这个先天优势，需要懂行的人与工程师、研究者一起把模型和产品打磨好。（`25:34–25:45`，`25:56–26:53`，`27:04–27:21`）
