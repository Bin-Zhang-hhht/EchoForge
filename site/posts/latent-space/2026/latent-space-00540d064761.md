## 速读

No Priors 与 Latent Space 在 Microsoft Build 现场的联合专访。纳德拉的核心叙事是"生态系统而非单一模型"：干净谱系的 MAI 小模型加爬坡脚手架、每家公司自己的私有 eval、开放 harness——"换一个模型还能爬坡，你才掌控局面"。他也罕见地细谈 SaaS 的拆解与重组、按用户/按量/按结果定价的演化、Azure 网络团队"我们不需要 headcount 我们需要 tokens"的重构，以及对社区许可的直白表态。

## 主题正文

### 生态系统叙事：平台的价值在平台之外

主持人问 Build 一上午发布的最大心得，纳德拉的答案是把这一切理解为"生态系统打法，而不是单一模型甚至单一平台"：平台的定义是"在平台之外创造的价值大于平台内捕获的价值"。主题演讲想回答的是，无论 AI 原生公司还是传统企业，如何成为一等公民、指向"自己创造的 AI"——栈长什么样、工具长什么样、什么有价值，"那是我们的工作"（`00:01:09–00:02:14`）。

### MAI 的训练策略：干净谱系、爬坡脚手架与私有 eval

谈到新发布的 MAI 系列模型，他强调先做"干净谱系"：预训练数据质量、逐项消融——现在做干净谱系比以前更难，因为网络上的污染太多了；这也是他对许多开放权重模型的批评："在一两个基准上好看，实践中不行"（`00:02:30–00:03:08`）。真正让他兴奋的是一个 5B 小模型怎么能持续爬坡：答案是围绕模型搭一个"爬坡脚手架"——不只是模型，还有 RL 环境、轨迹收集，以及最重要的**私有 eval**。"外面所有公开 eval 都不错但已经不关键了，因为都能被刷满；每家公司会有自己的私有 eval"（`00:03:29–00:04:08`）。他甚至给出"前沿"的新定义：给前沿加一点时间性——Build 上有个演示先用 GPT-5 收集轨迹，再用 5B 推理模型反超，"能站在巨人轨迹上让小模型超越，这也是一种在前沿操作"（`00:04:23–00:04:45`）。

被问"两年后你想对当年的自己说什么"，他反思：智能约等于算力的对数这个粗糙近似确实成立，但行业低估了"部署这些模型让它在真实世界产生价值"的复杂性——基准分数有趣但真正的评测是用户做出只有他们自己才觉得有价值的事；如今"token maxxing"的抱怨，其实是行业没教会大家"每一步都在用 token 创造价值"（`00:05:06–00:06:24`）。

### 价值落点：代码好到要重造 IDE，下一步是"胶水工作"

编码已经好到"我们必须重造 IDE"：一百个智能体会话的认知负载回灌给人类，需要新 UI;只有聊天也不够，所以要有画布（canvas）——"完全智能体的世界里，软件和 UI 的需求照样存在"（`00:06:37–00:07:17`）。他更看重的是把编码的成功推广到"胶水工作"：大量人力消耗在组织内部的粘合事务上，用长时运行、持久化的 token/智能体去增强，就能像编码一样放大；他预言半年后大家会说"一夜之间我的多个自动驾驶代理以我的授权干了一堆活，然后我得问我的新 IDE:你们都干了什么?"（`00:07:18–00:08:22`）。

编码智能体外面有 harness,企业的 harness 是什么?他的定义：harness 定义模型、数据、工具，并让三者成环。微软所有产品——GitHub Copilot、安全场景的 Copilot、科学发现——都是带工具访问的多模型 harness,通过渐进式工具披露保持 token 效率；过去两年最深的教训是"上下文层的准备工作量巨大，而那正是魔法所在"。GitHub 的 harness 已在 Foundry 开放，也兼容 llama 等其他 harness——"harness + 工具 + 模型一起训练就能拿到评测提升"，安全产品找到既有工具没发现的漏洞就是存在证明（`00:08:41–00:10:23`）。

### 私有 eval 是最大的 IP：换模型还能爬坡才算掌控

被问到前沿实验室"API 业务 + 第一方产品"的模式与微软生态的差异，他说平台拥有第一方产品从来不是问题（Windows、云时代都如此），关键是"不能成为别人成功的限制"。这一轮智能体的网络效应不同——模型从少量样本就能学到新意——所以游戏变成保护：**每家公司的私有 eval 可能是最大的 IP**;拿私有 eval 即便用前沿模型爬坡、且不泄漏轨迹，可能是 IP 的最大来源。他给出一个 acid test:你有一个私有 eval,用模型 A 爬坡，现在换成模型 B——还能继续爬吗？"能，你就掌控局面；不能，你就没有。"这也解释了为什么开放 harness 如此重要——这是 AI 原生创业公司、SaaS 公司和每个企业都需要的技能（`00:10:25–00:12:38`）。主持人顺势总结微软的第三幕：操作系统公司 → 云公司 → "harness 与 evals 公司"；大会的标语就是"让每家企业用自己的数据得到前沿智能"——没有这个，开发者大会就变成"对单一模型的朝拜"了。他还自嘲与英伟达的旧账："我们做了 DirectX,黄仁勋在上面做了 CUDA——我总觉得我拿了吃亏的那一头"（`00:12:39–00:14:14`）。

### 公司的"资深智能体"该上资产负债表

IP 的另一面是人。他相信人类"随时发现系统空隙"的能力仍是价值之源；当 token 资本上升时，问题是如何让人力资本与 token 资本复利——团队里智能体干活的轨迹与人类工作的轨迹，是企业创造价值的重要上下文，用它训练出的不是通才模型，而是"公司的资深智能体"，可以进资产负债表。主持人打趣："SEC 得为 token 专长制定会计准则了"（`00:14:19–00:16:05`）。

### SaaS 之辩：数据模型永存，打包方式必变

对"软件终结"之争，他的拆解很清晰：SaaS 的老公式是数据模型 + 业务逻辑 + UI——数据模型依然优秀（"总账就该是总账，不用重新发明 schema";Power BI 漂亮仪表盘下面的语义模型同样值得保留），要重新谈判的是垂直堆叠的打包方式，"学会拆包再以新方式组装，发现新的商业模式"（`00:16:40–00:18:11`）。他举了历史与当下的双料例证：当年把 Exchange、SharePoint 搬上云，以为只是换地方，结果云上服务器用量是 10 倍、100 倍——因为人们买的不是服务器是订阅；如今 Microsoft 365 的 Work IQ 把"公司最重要却从未被当数据库用的数据库"开放出来——邮件、Teams、Word、Excel、PowerPoint、SharePoint 都在它上面运转。他的示例：对 GitHub 仓库说"我上周参加了一系列相关的设计评审，把要点抓出来，告诉我该改什么"，系统能读完会议记录、回来给出改代码的计划——这在旧 M365 里不可想象。代价是 M365 要为"服务智能体"重新架构，因为"给收件箱用的架构服务不了智能体"（`00:18:11–00:20:07`）。

### 定价演化：outcome 定价的坑与 GitHub 的教训

定价的推演同样务实：按用户定价本质是预算确定性需求的产物——"一定数量的使用权益的打包"；订阅和按用户会一直在，下一步是按量，再往后有人说按结果付费——"但大多数人在真正有结果之前都爱结果;一旦有了结果，那就像分版税。我遇到过全心拥抱 outcome 定价的客户，等真要分享成果时立刻说:还是回到按用户或按量吧"。GitHub 就是活例子:按用户的 Copilot 定价是在理解智能体使用强度之前设计的——交互式补全和"一天放一万个智能体"完全是两回事，所以最近改为按用户之外叠加消耗计量（`00:19:55–00:22:03`）。

对"企业内部 agent euphoria、扬弃 SaaS 自建一切"的现象，他建议等一个完整预算周期再看均衡：自建还是外购是可以量化的——"自建加维护的边际成本高于外购就该买";维护这一环尤其要紧，AI 会找出安全漏洞，你就得赶紧修，修又要烧 token——这是个循环。"我们已经经历了'我能生成很多软件'的兴奋，下一个问题是:我到底想要哪些软件、哪些用别人的、怎么把它组合成我有掌控权的智能体工作流。"对僵硬的供应商，市场不会有耐心;灵活又交付价值的供应商，会带着新的商业模式把软件再卖一遍（`00:22:06–00:24:00`）。

### CEO 也在写智能体，以及"我们不需要 headcount 我们需要 tokens"

他自己现在大量构建 Foundry 上的长时运行智能体：上周刚搭了一个"幕僚长 autopilot"——用 Work IQ 加 Foundry 长时运行智能体、记忆存在自家后端服务里，一句"发布到 Teams"就端到端发布成功，"这挺奇迹的"。他也自嘲 AI 让"连我们这种公司的 CEO 的无能都能被兜住";回想刚入职微软时人人都要去啃戴夫·卡特勒时代的代码学 C/C++,如今 CEO 也能读懂代码库——但重点不是人人做同样的事，而是"检视、学习、看见"的能力普及了（`00:24:02–00:26:00`）。

对"未来只剩四种工程师（智能体管理、前置部署、安全、大规模基础设施）"的预测，他说方向正确但要在实验中演化;LinkedIn 已经结构调整出"全栈构建者"学科（设计、产品、前端合署但各留专长）;另一个新现实是 RL 环境成了最难的基础设施问题之一——连 Excel 团队都要配分布式系统人才（`00:26:04–00:28:27`）。他最看好的是通才："通才的杠杆会有最大回报"——过去做知识工作产出 Word 和表格，现在同一句话里就能产出应用（`00:27:40–00:28:27`）。

雄心的例子来自 Azure 网络团队：过去 15 个月建的容量超过之前 15 年的总和,同一批团队意识到照老路干不下去，于是重新定义工作——"我们的工作不是做 Azure 网络，而是构建那个做 Azure 网络的智能体系统"。他们给系统起了名字，管着 500 多名光缆运维人员与全网 WAN 的光纤作业，然后开始喊："我们不需要 headcount,我们需要 tokens。"他把这概括为"把自己的工作元化（meta）,元工作就是新工作"——就像 80 年代若有人说 40 亿人早上起来要打字，答案不是 40 亿打字员，而是知识工作（`00:28:58–00:31:51`）。

### 数据中心、社区许可与教育

被问到社区冲击，他的表态很直白：建设规模史无前例，但行业必须有原则地让收益在社区层面被真实感受到——"这不是一场公关活动"。电价不能上涨（长期反而该因更好的电网而下降）、水资源要闭环补充、培训就业和税基要真实投入，"做到这些我们就有许可;做不到就没有。社区保持怀疑、问尖锐问题是健康的"。他相信历史规律：消耗大量能源又创造大量价值的故事都有好结局；token 经济若能驱动生产率、增长、广泛参与和更好的健康结果，我们将处于很好的位置。未来 12–18 个月最重要的更新是让每个人看见自己能以一等公民身份参与——"这个世界不会相信科技公司一句'相信我们，未来很美好';你必须交付可触摸的好处，政客甚至会因为主张这个而赢得选举"（`00:31:50–00:36:57`）。财富创造会发生在大量公司里，医疗已有 Open Evidence 这样的案例；教育反而还没被同等改变——他提了 Alpha School 与某斯坦福课程坚持教学生"正确应用 softmax 而不是让 AI 修训练"的例子，认为概念学习依旧关键，但激励、证书与就业的链条必须重构——"下一个大创业公司，可能就是建一所新大学或一套新教学法的人"（`00:36:57–00:38:48`）。
