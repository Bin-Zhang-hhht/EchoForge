## 速读

前 Stripe CTO David Singleton 在这期节目里完整演示了 Dreamer——他与 Hugo Barra、Nicholas Jitkoff 在 2024 年创办的 /dev/agents 走出隐身模式后的名字：一个面向消费者的平台，用来发现、构建和使用 AI Agent 与 agentic apps，核心是一个会随着使用越来越懂你的个人 Sidekick。按节目注记的说法，这期录制于 Dreamer 团队宣布加入 Meta Superintelligence Labs 之前，是他们公开转型前接受的最后一期访谈之一，可以当作转型前的一个快照来看。

最值得带走的三点：Sidekick 被刻意设计成操作系统的安全内核——Agent 与 App 之间不直接互通，一切经由 Sidekick 按用户预设的权限放行，"就像用户与不同 ring 的关系"；全栈托管让第一次构建 10–15 分钟就能得到一个大概率能用的 Agent（每个 Agent 按需分配独立数据库，版本管理是自研而非 git）；以及一个按用量结算的工具生态，配合 Builders in Residence 计划和 4 月中旬截止的一万美元最佳工具奖。

## 主题正文

### Sidekick：先弄清计划，再构建，再自测

Singleton 把 Sidekick 描述为"会造 Agent 的 Agent"：你说出目标，它先理解你已配置的 Agent 和工具，给出实现计划，确认数据与能力齐备后动手（`00:15:00–00:15:54`）。它偶尔会拒绝——如果缺少某个工具就直说做不了，这反过来成了工具开发者的需求信号。构建循环是"先想清楚怎么做，然后构建，然后实测"，因为"任何能让现代编码模型进入一个可以修改、观察自身输出、再修 bug 的循环的地方，魔法就会发生"。代价是首次构建要 10–15 分钟，比一些纯网站生成器慢，但换来的是第一次产出的东西大概率就能用；后续的小改动（换 logo、调 UI）则快得多（`00:15:54–00:16:31`）。

想深挖的人可以打开内置 IDE 看生成的代码，其中提示词是刻意保持可读的——你能看到调度逻辑背后那个强大 LLM 用的完整 prompt（`00:16:48–00:17:08`）。一个被 swyx 点名为"Sam Altman 对 AI 应用的头号需求"的例子是"自完成待办清单"：有人把 Granola 记录的会议内容接进来，会议里承诺的招聘事项自动出现在待办清单里，再用招聘 Agent 把它完成（`00:21:34–00:21:55`）。Singleton 说这就是创业的初衷——"强大的定制体验能够彼此协作、自动化你的生活"。

### 安全模型：内核、ring 与按权限放行

信任是这期节目着墨最多的工程命题。"软件替你干活很酷，但只有可信才有用"——让这些东西好用且可信同时成立是难的。Dreamer 的模型是 Sidekick 位于一切的核心：它既是你的助手，也是系统里的"交通警察"。一个 Agent 想调用另一个 Agent 时不能直接通信，必须请 Sidekick 代劳；Sidekick 掌握你作为用户设定的全部预期——哪些 Agent 能做什么、授权了哪些工具——并确保发生的事情与你的利益一致（`00:22:00–00:23:23`）。

Singleton 把背景归因于自己多年保护敏感信息的经历，并给出了明确的架构类比："我们意识到必须造一个有点像操作系统的东西——Sidekick 是内核，Agent 和 App 就像用户，处于不同的 ring。"他强调无法只挑系统的一块来做：否则你得到的是随手抓取数据的 vibe-coded 小应用，这在规模化服务普通人时行不通。顺带一提，逐字稿里把 traffic cop 转写成了 "traffic cup"，按上下文应为前者。

### 工具生态：按用量结算与一万美元大奖

Dreamer 的工具页挂着一排真实服务：Google 搜索、Gmail、F1/MLB/NFL 的实时数据源、滑雪条件查询，以及 Granola、Attain Finance 这类第三方 Agent；付费工具（如 Parallel Web Systems 的网络数据）也在列。商业模型是按用量结算：swyx 问到支付时直接猜"你用的应该是 Stripe Connect"，Singleton 确认——钱已经在平台上流动起来，无需发明新协议，"Stripe Connect 已经存在多年"。swyx 把这总结为飞轮：工具越多、开发者越多、Agent 越多，彼此互相喂养（`00:26:39–00:26:48`）。

生态侧的运营动作也很具体。Builders in Residence 计划的灵感直接来自乐高的 Master Builder 项目——雇一群最会搭积木的人来激励社区——Dreamer 想要的是"如果你需要一个汽车方向盘工具而我们还没有，我们就为你造一个"（`00:25:43–00:26:02`）。任何人经 dreamer.com/latent-space 跳过等待名单即可上手；到 4 月中旬，平台上新增的最佳工具会拿到一万美元奖金，理由很直白："我们就是想播撒创作的种子"（`00:26:03–00:26:31`）。对 Agent 之间的商业协议，Singleton 的态度是保持开放与协议无关，并把当下比作早期 web：他 1995、96 年上网时 HTTP 只是众多协议之一，Gopher 和 UUCP 也天天在用——"HTTP 和 HTML 只是赢了，但其他协议也各有意思"（`00:27:54–00:28:15`）。生态里已经有人做出了让人惊讶的东西：Attain Finance 不是 Dreamer 员工做的，而是早期 Alpha 用户 Andrew 的作品——一个"财务健身教练"，第一次运行给他的建议就是少买卷饼（`00:55:53–00:56:38`）。

### 工程底座：TypeScript、按需数据库与自研版本管理

技术选型上，Singleton 认为办公室对话里最常被问的就是语言问题：TypeScript 是构建这些体验的最佳语言，因为强类型、训练语料充足，而且公司自己的大部分栈都是 TypeScript——"类型安全从数据库一直贯穿到前端，对编码 Agent 来说，没有什么比让它们在编译期检查正确性更好的了"。公司代码库的这套思路也被原样搬进了 Agent SDK（`00:42:08–00:42:51`）。平台内的版本管理刻意没有用 git，而是自研——为了让 Sidekick 能方便地操纵它，这是个权宜但有效的选择（`00:43:27–00:43:37`）。

托管体验是"你不用操心部署"：每个 Agent 按需获得一个独享的数据库（逐字稿写作 "SQL Light"，即 SQLite 的多用户模式），Agent 被分享给多人时所有权由平台打理；后台工作流由外部触发器拉起，日志全程可查（`00:44:08–00:45:12`）。模型侧则是 Sidekick 按任务自动选型——演示里那次调度任务它挑中了 Haiku 4.5，"质量不错、速度也快"（`00:45:00–00:45:12`）。

### 记忆是护城河：从向量库 RAG 走到了哪里

在被问到平台最重要的单一职责时，Singleton 的答案是记忆与个性化："Sidekick 会逐渐了解你、为你建立记忆，这是你的护城河——Dreamer 越用越好用。"一个具体的例子是他自己在用的 Weekend Activity Planner：两个娃一条狗的家庭，周末安排是每周都要花力气的功课。某个周六早上 Agent 主动推来圣帕特里克节游行的消息——推荐理由是它的用户画像里有"他是爱尔兰人"这一条，而这条信息正是 Sidekick 长期积累下来的（`00:49:28–00:51:11`）。

技术路线他们试了很多。"很早期我们把大量事实塞进向量数据库，做嵌入和反向检索的 RAG——能用，但复杂度远超实际所需"，后来换成了与业界多数产品类似的方案；知识图谱试过，现在的系统不是知识图谱。"外面发表的 Agent 记忆论文，我们大概实现过大多数。"公司里有不止一个人专职做记忆，并且会持续投入（`00:51:33–00:52:02`）。

### 小团队、招聘标准与 LLM 缺的"品味"

第一次当 CEO 的感受被问得很直接。Singleton 说区别在于"看全部的东西"——他管过 Android Wear，那基本是这个产品的 CEO，但自己的公司"buck 真正止于你"，温度确实不一样；如今他大量时间花在见用户、泡 X 和 LinkedIn 上（`00:52:06–00:53:24`）。团队规模印证了 swyx 的"tiny teams"论题：你刚才看到的全部产品，核心团队"说实话大约六个人"，全公司现在约 17 人，人才密度被刻意维持——"每个同事我都愿意随时和 TA 做任何项目"（`00:53:24–00:55:14`）。公司自己也在用编码 Agent 和 Dreamer 的营销 Agent 跑日常运营（`00:55:14–00:55:36`）。

招聘标准因此变了："我现在看工程师，主要看他与编码 Agent 协作得怎么样。"团队里全员都是 IC，他自己也写很多代码；不少成员做过工程经理——只要不脱离代码，EM 经验反而是让 Agent 为你和团队效力的好画像。面试保留一轮编码筛选确认基本功（"还是得有人用手指写点代码"），然后是几个和团队工程师一起做的小项目：从完整的产品想法出发即兴讨论，用对方最顺手的工具（Codex 或 Claude Code）把东西造出来，观察他如何提示 Agent、Agent 干活时他在做什么（`00:57:14–00:59:13`）。Singleton 自己的工作流永远是多个 Agent 并行，让一个 Agent 审查另一个的输出，轮转起来效率极高；也可以串成一条链，一个产码、一个审查。

至于 LLM 还不能做什么，他的答案一年内换了三次对象：一年前会说是音乐生成——但 Suno 最新的一批曲目已经"相当惊艳"；半年前会说是图像生成——而最新的 nano banana（Dreamer 平台上也能调用的工具）已经能产出漂亮的信息图与绘画质感的图。剩下的答案是品味：让生成的东西不像"AI 通用敷衍货"（AI generic slop）需要把大量品味灌注进模板、提示词和 harness，"你让我看一个待办应用，我能看出它是哪个模型做的"。他判断代码生成模型之所以成功，正因为可验证性极强，而"量化品味"是研究者的下一级台阶——swyx 补充说，基准被采纳又因被解决而抛弃的过程，本身就是我们在弄清智能含义的方式（`00:59:23–01:02:23`）。
