## 速读

Latent Space 新演播室（Kernel 内）的第一期，嘉宾是 Anthropic 的 Felix Rieseberg——Claude Cowork 的产品负责人、Electron 与 Slack 桌面端的老兵。Cowork 的定义简单得惊人：Claude Code 跑进一台轻量虚拟机，再加一点护栏与便利。但围绕它的判断不简单：为什么押注本地电脑而不是"把整台电脑克隆上云"，为什么团队"连备忘录都不写、直接把所有候选方案都建出来再挑最好的"，以及 skills 这种"给 Claude 写一个 markdown 文件它自己搞定"的形态如何从一次数据仓库接入中长出来。

第二层是工程细节与安全观：macOS 用 Apple Virtualization Framework、Windows 用与 WSL2 同源的主机计算服务，为什么要跳过这么多坑也要给 Claude 一台独立于用户的电脑；"逐条审批 vs 跳过权限"之间，沙箱才是中庸之道，而行业不必等到"100% 模型对齐"——瑞士奶酪模型就够了。尾声的 Electron/Chromium 赞歌（Slack 的 WKWebView 之痛、chrome://gpu 里的一长串 workaround、Unreal Engine 也用 Chromium 渲染文字）是近年少见的渲染栈一手史料。主持人 swyx 的结语："这是我今年感觉最接近 AGI 的时刻。"

## 主题正文

### Cowork 是什么：Claude Code 的"超集"而非阉割版

Felix 的一分钟定义：Cowork 是 Claude Code 的用户友好版。去年 12 月团队注意到，越来越多非技术、不打算亲近终端的人在用 Claude Code；另一批终端原住民则开始拿它做非编码工作——报销、整理小票、组织知识库（那场著名的 Obsidian 时刻）。Cowork 的答案是把 Claude Code 装进一台虚拟机，加一点护栏与便利，让不想先开终端的人也能用（`00:02:17–00:03:10`）。swyx 当场反对"用户友好=低配"的直觉：他用 Cowork 反而比 Claude Code 更像高级用户——Chrome 集成、视频上传、剪辑标题样样都行。Felix 用亲历呼应：十几年前他在微软做 Electron，Visual Studio Code 最初就是个网站，当时也顶着"Visual Studio 阉割版、不是给严肃开发者用的"叙事——他至今相信 VS Code 赢在可hack、可扩展，而 Cowork 可能正走在同一条路上（`00:03:46–00:04:54`）。

被问到"10 天造出 Cowork"的传闻，他先做限定：Anthropic 是原型与 demo 优先的文化，Cowork 是从一堆内部原型里"挑出对的零件"，就像建网站不会从零写 React；更重要的转变是方法论的倒转——过去产品经理低带宽地拜访客户、写 spec、再设计执行；现在"连备忘录都别写，直接把所有候选方案快速建出来，挑最好的"。执行力变便宜之后，他不写备忘录了，但"不做用户测试就上线产品"这种事他也不会再干（`00:05:26–00:10:35`）。Alessio 现身说法：一个 Electron+SQLite 的项目构建总出问题，他直接让模型用 Swift（他根本不会）整只重写——重要的只有应用逻辑，绑定层谁写都行。至于"软件价值归零论"，Felix 的看法反而保守：他不相信未来是每个人都跑自己的超个性化软件（"你的内部聊天工具怎么跟我的互通？"），变便宜的是把乐高积木拼起来的那一步，而不是重建原语——他的团队从没想过重写 Claude Code，核心论题就是"它必须是 Claude Code，我们在上面盖楼"（`00:08:46–00:10:35`）。

### 虚拟机、"沉默的律师"与本地电脑的辩护

他认为影响最大的产品决策是"如何看待你的本地电脑"——跑在你的电脑上还是云上。VM 是 Cowork 最强大的部分：一个轻量 Linux 系统，Claude Code 在里面近乎自由地安装所需（Python、Node.js），同时有严格的网络出入站控制；用户可以用平实的自然语言告诉系统什么可以什么不行。"我不用去问律师'装 Homebrew 行不行'——这种问题的含义复杂又微妙，没法让一个法务拍板。"他的心智模型是把 Claude 极度拟人化：如果雇了个聪明人，你会给他一台电脑，而不是让他用邮件把代码发来发去（"我爸至今坚持用聊天窗口写代码"）。他 甚至认为硅谷整体低估了本地电脑："不然我们为什么都在用 MacBook，而不是 iPad 或 Chromebook？"（`00:11:57–00:19:21`）另一条路——把电脑上的东西一个个搬上云——技术上可行，甚至可以偷懒读你的 Chrome cookies 上云实现云端代操作；但"很多网站（包括银行）看到同一凭证出现在两个位置就会锁号，你就得拿着护照去网点解释"。在 agent 时代真正到来前，世界还没准备好"把整台工作克隆上云"，所以他的答案是：把 Claude 放到你工作的地方（`00:17:43–00:19:21`）。

他自己已经是重度用户的活例子：开发 Cowork 的第一周，他发现自己用内部崩溃收集工具人肉筛选"可修复的 bug"，然后反应过来应该上移一层——让 Cowork 每天早上去读全部 bug 列表，分出可修复与不可修复，给每条可修复的写一个 markdown 提示词文件，再为每个文件起一个 Claude Code Remote 任务。"我没用原生的 subagent 功能，因为我用 Remote 把它发射出去——然后我就可以去开会了。"（`00:14:59–00:16:50`）评测方面，Claude Code 按"典型 SWE 工作"评优，Cowork 则按典型知识工作——金融、法务场景，他个人的基准是"管我的房贷、给全家做财富规划"；两者差异主要在系统提示词与工具选择，而且这种超优化能在下一代模型上存活多久，他自己也不确定。他对脚手架下注的态度很坦白：模型能力持续overhang（模型远比用户用出来的强），与其投入大量针对脚手架的矫正，不如"给模型尽可能多的能力、把安全兜住，然后等下一次模型发布"——MCP server 到 skills 的迁移正是这个趋势的注脚（`00:19:22–00:26:58`）。

skills 的起源故事值得全文记录：Barry 最初在桌面应用里做的原型很像"给不想写代码的人的 Cowork"，第一个想到的场景是人人都会说的数据分析。接数据仓库时，团队发现与其写定制工具，不如写一个 markdown 文件："亲爱的 Claude，想拿数据的话，端点在这，API 长这样，你自己看着办。"这种"上移一层抽象、交出控制权"的模式效果好到他们开始到处复用，最后打包成了 skills（`00:25:24–00:26:58`）。

### swyx 的演示：教你如何被自己训练的 agent 替代

swyx 现场展示了他用 Cowork 跑 Latent Space 的流水线：起初不信任，就让它做最机械的事——从 Zoom 下载录制并传 YouTube（点击地狱）；后来连下载也交出去；Cowork 会压缩视频、翻看视频帧来给文件起名、自动上传。"这替代了我作为 YouTuber 的工作。"然后是关键一步：他让 Cowork 把这些一次性的人类引导流程做成自己的 skills——一个拆成三个，再加一个父 skill 负责编排；YouTube 上传更进一步，让 Claude 读官方文档写出程序化上传的脚本再封装成 skill——"我从来不想应付 Google Cloud，Cowork 替我应付了。"（`00:27:06–00:29:41`）Felix 总结这种上手法则：从一个你平时点来点去的知识工作任务开始，信任建立后不断问"再进一步呢？"——"这就像给你的自己的人生玩 Factorio：从自动化一件小事开始， clicks 之后自动化帝国越盖越大。"他最爱的技能是每天早上检查日历冲突，自定义提示词里写满了社交规则：某些人（比如 Dario）插进来的会优先，某些会可以 punt，几点后不想工作（`00:30:12–00:31:13`）。发布时最出圈的用例反而是最不性感的"清理桌面"——Alessio 用它清下载文件夹，被 agent 数落"你这有八份办公室租约的副本"。演示里真正让 swyx 惊艳的是 ask-user-question 的呈现与可编辑的待办清单；对于"它按文件类型而不是主题归类"这种不满意，Felix 的建议是新一代的态度："我看到你在用 Opus 4.6 了——越来越不用操心这些，直接告诉它你想要什么，它大概率能想出办法，虽然未必是你习惯的办法。"（`00:31:13–00:33:14`、`00:52:07–00:52:59`）

### 技能可移植性与"一切皆是 Cowork 垂直"

可移植性讨论从 Alessio 的痛点开始：他在另一个 agent 平台 Zo 上有"给访客登记门禁"的 skill，跨不回 Cowork；他的立场是记忆应当每 agent 独立，但技能应该跨 agent。Felix 的回答回到最原始的原语：skills 就是文件和文件夹，不锁在任何私有系统里；官方的容器格式叫 plugins，Claude Code 与 Cowork 同格式，甚至可以直接把一个 GitHub repo 挂成技能市场——"这就是我们的可移植性"。他承认对普通知识工作者这套话语太工程师了；行业还没解决的是"技能里哪部分可移植、哪部分属于个人"——用字符串插值（用户名、电话、常用目录）大概能做但很笨重。飞行预订的例子引出全场最共识的一句：他其实不认为 AI 该替你订机票——"终于有人说了"（swyx）；但"便宜通常更好"是普适的，而偏好时段、座位、机场是私人的，把普适与私人优雅地拼在一个 skill 里，是个还没人解开的题（`00:37:09–00:43:05`）。Alessio 的追问是更大的产业问题：如果 Cowork 把活全干了，企业搜索（Glean 们）还剩多少价值？"几乎一切都会变成 Cowork 的垂直场景"——能活下来的创业公司，得是终端客户信任的"任务结果提供方"（`00:43:55–00:45:32`）。

### 初级员工的忧思与"模拟三年经验"

被问到"哪些行业会消失"，Felix 的回答转向劳动力市场：Anthropic 作为一群人"深度担忧这些工具对劳动力市场的冲击，尤其是初级员工"——我们自动化掉的"烦人工作"，在很多行业正是给初级员工的入门工作；他直言 Anthropic 已公开表态：冲击会相当大，而人们整体没有准备好，"社会、经济学家和政府应该比我在这里纠结得多"。Alessio 给出半开玩笑的解法："模拟岗位"——初级工程师头三年真正学到东西的时刻其实很稀疏，如今可以用 AI 把三个月的分布式系统项目压缩成一周的"速通模拟"，一年攒出三年的项目经验，就像付钱上大学、或者"Jane Street 模拟器里待三个月再上岗"；销售与营销这类反馈环稀疏的岗位则更难（`00:45:34–00:47:49`）。Felix 以工程师视角补充：担心初级的同时，资深工程师其实在加速、单位价值在提升；他一直敬佩滑铁卢大学的毕业生——课程里强制一整年实习，"一个去过 20 家公司的初级工程师"，哪怕 LinkedIn 上集齐苹果谷歌特斯拉的"无限宝石"徽章被吐槽，实际能力确实碾压没 shipped 过东西的新毕业生；而他读的德国大学信息系统专业"理论到像先读四年生物学再去当医生"（`00:47:49–00:50:34`）。至于完全起飞（takeoff）的时点，两位主持人的注脚很妙："什么时候 Cowork 在看 TensorBoard 训练模型了，就是了。"Felix 不确定是一年还是十年，"但四五年后还是会发生的话，早纠结晚纠结可能没那么重要——该纠结还是得纠结"。金融垂直方面，他确认 Anthropic 有专门的 verticals 团队与企业团队（"是业务工程，不是销售"），理由是金融、法务这类数据密集且重视正确性的行业与模型长处匹配；他自己已经发推炫耀"Claude 在给我报税"，只是"推特受众大概不想看我的退税单"（`00:53:00–00:54:58`）。

### 电脑的"亲密感"：第二光标之梦与 VM 内幕

computer use 的话题让两位都感慨时事移势：一年前发布时 swyx "非常不兴奋——慢、不可靠"，发布会 hackathon 上甚至没人 hack 它；如今 Felix 说"它离真正有效地用你的电脑（不是理论上的电脑）不远了"。swyx 的实操心得是第三方的 macOS 自动化 MCP 全都闲置了——"Claude 自己写 AppleScript、自己执行，比依赖第三方工具更可靠"，于是"我们不断在上移技术栈"。真正有意思的是设计哲学的坦白：Felix 最初梦想过给 Claude 一个"第二光标"，还把这套美梦讲给苹果和微软听——但操作系统的模型建立在"同一时刻只有一个前景用户"上，系统级双用户比应用内后台难得多。于是问题变成三选一：Claude 该有一台你偶尔凑近看看的专属电脑？趁你离开时接管你的电脑？还是云端自建一台？他说这已经"不止是隐私，几乎是亲密感（intimacy）"——而且"就算 Claude 能替你判断，你想让它做这个判断吗？"（`00:55:46–01:00:08`）

VM 的工程细节干货最足。关于"Claw 凭什么占我 10-15GB"的抱怨，他解释镜像写入时折叠了空置空间（稀疏镜像），macOS 的字节数显示方式也误导人；启动慢是真的——"反正肯定比直接跑 Claude Code 慢，取舍是真实的"。实现层面：macOS 用 Apple Virtualization Framework（"苹果这次真做出来了，API 简单到 swyx 看代码直呼'就这？'"），Windows 用与 WSL2 同源的主机计算服务——"Windows 少有的开发者一致叫好的钻石"。深度集成系统虚拟化的意义在于让锁死的公司电脑也能用（Anthropic 自己的 IT 也管控安装），并且把"Claude 的电脑"与"用户的电脑"分开：IT 关心的是数据外泄与恶意行为，在网络与文件系统层设卡之后，就不必再害怕"装了 Python 谁都能干任何事"——风险被关进 VM（`01:02:22–01:06:45`）。安全哲学上他反对两个极端："只要它什么都不做就绝对安全"和"逐条审批一切"——computer use 若要在宿主机上绝对安全，就得审批每一次击键（"我想按 L 键，你说：好的，因为我知道当前焦点在哪个光标"）。swyx 一句定调："不委托就不是自动化。"Felix 的立场是行业不必造完美系统、不必等 100% 对齐——"用我们用了几十年的瑞士奶酪模型就行，但必须普遍投资在'你不需要批准每一步'的系统上"。他还不忘拉全行业下水：我们都用完整用户权限跑 npm install，它想读你的 .ssh 就能读——"这居然是默认值，疯了"；对模型产品同理，"最安全的是什么都不做"，而用户要么没能力判断 Python 脚本是否安全、要么根本不会读（`01:06:45–01:10:40`）。

Cowork 的未来三件事：每周都有新特性；继续加码"你的电脑"（remote control "coming soon"）；以及持续爬坡——让习惯了问答的用户一步步走开，让 Claude 在时间与范围两个维度上接管越来越大的任务。他不喜欢提前 vaguepost，但乐于指出：两位主持人一天里提的每个"显然该有人做"的点子，都大概率在路线图上——"我们的功能越是不让你惊讶，对我们越好"，因为这意味着没有做进过度特化、难以上手的死胡同（他不点名地说"认识几家'只支持 React+T3 栈的 Claude Code'那样的创业公司"）。至于给自己积攒的复利，他的职业建议与自我总结一致：他造过最受欢迎的东西是 Electron——Loom 的圆形摄像头、1Password 都跑在上面——"投资工具还很烂的那一层，因为那里的杠杆最大"（`01:10:40–01:15:27`）。

### Windows 95、Slack 与 Chromium 赞歌

作为彩蛋，Felix 讲了两段渲染栈往事。他的"在浏览器里跑 Windows 95"名项目其实一晚写成、本质是玩笑——真正的英雄是 Fabian（GitHub: copy）的 V86，在 JavaScript/WASM 里模拟 x86；让他至今不平的是：在虚拟化的 Win95 里启动 Excel 干活的整条链路，比很多传统 SaaS 应用还快。更硬核的是 Slack 时代：他加入时 Slack 桌面端还在用纯系统 WebView 的壳（MacGap 一类的方案），"因为太多原因不成立"，团队决定"要更大的枪，把渲染栈控制权拿回来"。他给的理由在 2026 年依然成立：系统自带的渲染引擎不够好、只能随系统升级，"如果你的关键 bug 出在 WKWebView 里，你唯一的办法是告诉客户：对不起你太穷了，没买最新 MacBook——这对用户和开发者都不可接受"。于是要么下潜找最好的引擎自带，而"Chromium 是其中最好的，大到 Unreal Engine 渲染文字都用它"；打开 chrome://gpu 往下滚，那一长串 workaround 全是为了保证"开发者说这里要一个红像素，它就真的出现"，在冷门 GPU 的 Windows 机器上清单会更长——"Chrome 之伟大在于在你扔给它的任何机器上都能跑，跑不动也多半 24 小时内修好"。swyx 总结："这就是那个到处都能跑的超级操作系统。"Felix 补了一个 humility 故事：Slack 的 NVIDIA 客户遇到 YouTube 视频渲染伪影，追到 Chromium 巨型线程里，看到芯片和驱动层的神人们也在说"我们不知道为什么，翻转这个 bit 就好了——每一层都这样"（`01:00:47–01:20:13`）。

最后的多人与未来话题收束全场：Alessio 问 Cowork 的多人模式——subagent 是单人拆上下文，那多个人的 Cowork 怎么交接？Felix 的开放问题是"什么时候我们直接给这些 agent 发一个 Gmail 账号、一个 Slack handle，让它们用人类 already 在用的工具协作"——财务团队的 Office 集成已经做到"Claude 直接在 Google Doc 里留评论"的程度；Alessio 展示了自己的 PiQ 实验（把任意 repo 和 Pi agent 丢进 VPS，开公共 webhook 收任务、看板审任务），想象未来组织里"销售 Cowork 找工程 Cowork 排队等审批"。Felix 还抛出一个"强大与诡异并存"的点子：两台电脑靠蓝牙感知彼此相邻，Cowork 互相询问"你有处理这个任务的 skill 吗"——"你大概不会在 Cowork 里看到这个，但我们真的还没试过这些有创意的解法。"至于 Anthropic Labs，他确认那是真团队且刚扩编（Mike 刚以 IC 身份加入），信条是"只做对其他任何团队都不合理的事"——极度天马行空、大概半残的原型。swyx 的送别词是本期最好的注脚："感谢 Claude Cowork——这是我今年感觉最接近 AGI 的时刻。"（`01:21:36–01:26:48`）
