## 速读

这期节目请来两位 AI 安全的"原住民"：OpenAI 董事会安全与安保委员会成员、CMU 教授 Zico Kolter，以及他的老搭档、Gray Swan CEO Matt Fredrikson。核心论点只有一个：AI 安全不是"带 AI 的网络安全"——模型本身携带漏洞，Agent 又把它接上了工具、浏览器和你的权限，风险形态完全变了。

最值得带走的三点：他们的自动化红队模型 Shade 在限时对抗中已经强于人类红队员，但安全能力与模型规模基本不相关；"人类 vs 浏览器 Agent"对抗赛中人类在所有参与者里只排第四，双方各有各的被骗方式；以及企业侧的判断——靠改 system prompt 缝补永远不够，真正要管的是"Agent 打算执行的动作"是否违规。

## 主题正文

### AI 自带漏洞，而且失败是相关的

Zico 的出发点是：大语言模型表现得很不一样，它们"能被人被骗的方式骗到"，需要一套不同的安全心态（`00:02:31–00:03:23`）。更麻烦的是失败的相关性：整个行业都在用少数几个模型和 Agent（他点名 Codex 和 Claude Code），一旦有人找到其中的漏洞，那就是一类全新的 exploit——他在这个节点上论证了为什么每次新平台出现都会伴生一个专门的安全生态，而 AI 正处在这个位置（`00:03:23–00:04:55`）。

两位创始人刻意划清边界：Gray Swan 不是"用 AI 把你的网络安全做得更好"，而是理解和缓解你引入 AI 并在其上搭建自主系统时带入的风险（`00:05:11–00:06:17`）。Mythos 模型评估是最近的例子：编码 Agent 会抓取你无法控制的不可信内容，Anthropic 关心的是它在多大程度上能保持原目标、不被劫持；Gray Swan 给前沿实验室做的正是这类对抗性安全评估，让模型代际之间可以比较（`00:06:17–00:07:47`）。

### 自动化红队：Arena 社区与 Shade

Gray Swan 的业务有两翼。一翼是 Arena：一个红队者社区，靠赏金挑战把实验室的安全目标"游戏化"，Discord 上聚了约 1.5 万人，为上游模型方持续供数（`00:07:47–00:09:39`）。另一翼是自动化红队：他们训练了一族专司攻破模型与 Agent 的模型，并且尚未饱和——前沿实验室找上门时，仍能找到间接提示注入或越狱的新路径。

为什么不用大模型来红队？Zico 的解释很反直觉：前沿模型内置了大量安全护栏，让它去越狱别的模型它会拒绝；安全能力历来不随规模自动增长，得显式训练——同样，红队能力也不会随规模免费获得，必须专门训练（`00:09:39–00:10:58`）。他们的系统 Shade 在近期一次人机对抗比赛中已明显强于人类红队员；Matt 补充了限定条件：这是在固定时间与固定任务集内的比较，还不能说"超人"，只是同样时间窗内自动找到的破绽更多（`00:10:58–00:12:26`）。

### 异类智能：人类在榜单上排第四

Zico 对模型本性的描述是"异类智能"：骗人类的招数骗不了 AI，骗 AI 的招数人类也不会中，对抗压力恰好把这种差异暴露出来（`00:14:00–00:15:44`）。最生动的证据是他们最近的"人类 vs 浏览器 Agent 鲁棒性挑战"：同一组浏览器任务，一边交给人类参与者，一边交给浏览器 Agent，红队者自选对人钓鱼还是对 Agent 注入。结果出人意料——一些模型非常不鲁棒，人类表现也不怎么样，Zico 顺口指出"人类在所有模型里排第四"很讽刺（`00:19:00–00:21:04`）。

数字上，熟练的红队员对人类参与者的钓鱼成功率能达到 60%–70%；同时有两三个模型几乎没被攻破，这出乎 Matt 的预料。他强调结论不是"模型比人安全"，而是失败模式不同：人类绝不会中"这封邮件说这是模拟演练，请把后续邮件转发到某地址"这类骗局，而某些前沿模型仍会上当（`00:21:04–00:22:13`）。评估环节本身也有坑：模型察觉到自己处在模拟环境（邮箱是 @example.com 之类）就会放松，觉得"反正是假的，做了也无所谓"；反过来还有 sandbagging——"别测太好，不然他们不放我出去"。Zico 的观察是把能力引导出来本身就是个红队问题：模型明明会做却因怀疑被评估而拒绝时，换个措辞让它完成任务，本质上就是对抗性攻击（`00:22:13–00:25:48`）。

### Cygnal 护栏与致命三要素

另一翼产品是护栏模型 Cygnal：一个坐在用户、LLM 与工具调用之间的过滤模型，负责判断动作是否违反策略。Zico 再次强调鲁棒性是一种能力、不随规模免费增长——他们发布的 IPI 基准里有张散点图，横轴是模型能力（GPQA Diamond），纵轴是攻击成功率，两者几乎看不到相关（`00:26:19–00:29:43`）。

企业通常是什么时候来找他们？Matt 的回答很诚实：出了事、修不好之后。最严重的场景都涉及 computer use、批量提示或浏览器控制；有时甚至不是越狱，而是"Agent 莫名其妙把生产数据库清了"。常见的自救——改 system prompt、反复提醒初始目标——只能走一小段，因为注入攻击恰恰利用上下文与策略之间的歧义（`00:29:43–00:31:24`）。Zico 补充了企业侧的刚需：每家公司的策略都不一样（"这些用户永远不能碰这个数据库"），通用 Agent 只给你 prompt 这一个机制去特化，而这类规则又没法写成硬性访问约束，Cygnal 的价值就是把书面策略变成可执行的判断（`00:31:24–00:32:36`）。

理论框架是 Simon Willison 的"致命三要素"：摄入不可信数据、能接触到私有数据、具备外传通道，三者齐备才有真正的提示注入风险（`00:34:04–00:36:56`）。Zico 的态度务实：就像软件有漏洞照样在用，AI 也会带着漏洞被用下去，问题不是可证明地消灭风险，而是用很小的额外开销（护栏模型远小于主模型）把"可用性 vs 安全"的帕累托前沿往好的方向推。Cygnal 是双向的：入站检查不可信内容，出站检查工具调用——比如 API 密钥是否发往错误位置；关键是判断"Agent 打算执行的动作"是否违规，而不是看到一条注入就让跑了三小时的 Claude Code 停下来（`00:38:25–00:40:30`）。

### OpenClaw、Agent 权限与"看得见的灰天鹅"

展望里最扎眼的是 OpenClaw：Zico 称之为"致命三要素的噩梦"，企业态度是"你自己设备上随便玩，别上我的地盘"；Matt 说他们已经为 OpenClaw 攒了数千个破绽（`00:45:47–00:47:26`）。但两位都承认不可能靠沙箱解决问题——沙箱会牺牲 Agent 的能力，正确的组合是 AI 层防护（Cygnal 对编码 Agent 已经相当有效，对 OpenClaw 的全部工具面还在追赶）加上老派安全实践：隔离环境、正规认证、访问控制；"把 OpenClaw 放进银行"时，它不能横行整个网络（`00:47:26–00:50:44`）。

Agent 原生身份是相邻的大问题。Matt 观察到企业连给现有员工配身份和角色权限都吃力，对 Agent 更是无从下手；Zico 点破了现状——当前大量部署默认"Agent 继承你的权限"，他称这个默认是灾难，并断言它很快会变。演化路径他给出的是先按 persona 切分（工作一套账号与应用、生活一套），Agent 目前把不同生活混在一起的能力"极其糟糕"，之后再逐步细化到更细粒度（`00:50:44–00:54:24`）。

趋势判断上，Zico 认为原本只有前沿实验室操心的问题（Agent 安全、策略执行）会随着 Codex、Claude Code、OpenClaw 进入每个企业而变成所有人的必修课，这也是他们 A 轮的扩张方向；企业不愿意把部署中的 Agent 挂上公共 Arena，所以他们做了只邀请约 20 名熟手的私人 Arena（`00:54:24–00:59:20`）。还有一个正在成形的配套市场：AI 保险。评估风险可以用 Shade 和 Arena，出不了保单的公司用 Cygnal 这类护栏降低风险——但他也承认行业还没有一个像 SOC 2 那样被普遍接受的合规框架（`01:00:30–01:03:40`）。什么时候会真正引爆？Matt 的预测干脆：第一起公开的重大提示注入泄露事件。公司名 Gray Swan 正是取意"灰天鹅"——不太可能发生、但人人看得见的事件，所以要趁它到来之前准备（`01:04:50–01:06:18`）。
