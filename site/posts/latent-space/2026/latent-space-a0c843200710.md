## 速读

Google 首席 AI 科学家 Jeff Dean 做客 Latent Space。从 1990 年的并行神经网络本科论文，到重塑 Google 搜索基础设施、复兴万亿参数稀疏模型、与 TPU 团队做软硬件协同设计，他几乎摸过现代 AI 技术栈的每一层。这期节目试图回答的是他的招牌论题：如何"拥有帕累托前沿"——既有最强的 Pro，也有最快的 Flash，而且两者互相成就。

最值得带走的三点：蒸馏不是压缩技巧而是体系支柱——必须先有前沿模型，才能蒸出"新一代 Flash 胜过上一代 Pro"的小模型，这个趋势已经连续多个 Gemini 代际成立；能耗视角能重写一切系统直觉——乘法不到 1 皮焦耳，把数据从芯片另一侧的 SRAM 搬进乘法阵列要约 1000 皮焦耳，batch 的本质是摊销搬运成本，低精度是省比特即省能量的直接推论；长上下文的终局不是把二次方注意力硬推到万亿 token，而是"给出你能 attend 万亿 token 的幻觉"——像搜索一样用轻量模型从数万亿 token 里筛出 117 篇真正要读的文档。

## 主题正文

### 帕累托前沿的两端互相成就

开场把 Gemini 的产品哲学说透了：既要有推前沿的 Pro——"让你看到去年或六个月前的版本还不存在的可能性"，也要有一个能力很强、价格与延迟都亲民的 Flash，让 agentic coding 这类低延迟场景用得起。关键在于两者不是二选一：蒸馏要求先有前沿模型，才能把它压进一个小而强的躯壳。Dean 亮出的趋势线是：连续多个 Gemini 代际里，"新一代的 Flash 已经达到甚至大幅超过上一代的 Pro"，而且会继续追（`00:00:30–00:07:02`）。蒸馏的源头可以追溯到当年 3 亿张图像的数据集：按类别簇训练专科模型（哺乳动物专家、室内场景专家），比单一模型强得多；但 50 个专科模型的 ensemble 没法上线服务，于是"把它们压进一个可部署的形体"成了蒸馏的最初动机——与今天"大模型蒸小模型"一脉相承（`00:03:52–00:05:09`）。他补了一个机制层的洞察：小模型配大数据集，用大模型的 logits（软标签）反复过数据，能"哄"出硬标签哄不出的行为——这是蒸馏能逼近大模型的原因；至于 Flash 的经济学，swyx 报出的最新数字是 50 万亿 token 的处理量，而 Dean 一句轻描淡写把全景带出来：它已经进了 Gmail、YouTube 和搜索的 AI Mode 评论（`00:05:09–00:08:10`）。

延迟被提为第一等目标，理由是推理 workload 的演化：用户不再要"写个 for 循环"，而是"写个完整的软件包"——要生成的 token 多了几个量级，低延迟系统成了刚需，TPU 间的高性能互联也正是为长上下文注意力与稀疏专家模型准备的（`00:08:10–00:09:19`）。Alessio 追问：任务会饱和，Flash 两代之后不就什么都能干了吗？Dean 的回答是：前提是用户的需求分布静止——现实中模型一变强，用户问的问题就变难（"分析全世界的可再生能源部署并写份报告"），前沿模型永远在探"哪里开始崩"，而崩的地方就是下一代改进的地图（`00:09:19–00:11:26`）。

### 基准的保质期与"attend 万亿 token 的幻觉"

对外部基准，他的态度是承认保质期：最好的基准初分应在 10%–30%，逐步推到 80%–90%；过了 95% 就只剩边际收益与数据泄漏的风险。Google 内部保留了一批"确定不在训练数据里"的 held-out 基准，用它们定位能力缺口、反推需要什么数据或架构改进——长上下文能力（Gemini 1.5 首发）就是这样来的：needle-in-a-haystack 早已饱和，真正难的是"多针"与"从全部内容中综合出答案"（`00:11:26–00:15:01`）。他的长线目标说得很浪漫：不是百万 token，而是"能否在回答问题时 attend 整个互联网"——纯二次方注意力从百万推到十亿、万亿 token 不可能，所以真正的问题是"如何用算法与系统级改进，给出你能 attend 万亿 token 的幻觉"。用途清单随口就来：YouTube 全量像素与深层表示、个人 Gemini——经你授权后 attend 你所有的邮件、照片、文档与机票（`00:15:01–00:16:26`）。swyx 算了一笔账反驳"token 太多"：人一天说 8 小时也就 10 万 token；Dean 的回应是把视野推向视频与非人类模态——Waymo 的 LIDAR、机器人传感器、X 光、MRI、基因组，"有几百种模态值得模型见过"，哪怕只掺一点进预训练配比，也足以"勾起"模型对这类数据的意义感知（`00:16:26–00:18:36`）。视觉与运动被他并列为"王者模态"——进化独立演化出约 23 次眼睛不是没有原因；他还给了一个被低估的演示：把一段 18 个体育名场面的 YouTube 集锦丢给 Gemini，直接产出带日期与描述的 18 行表格（`00:18:36–00:20:11`）。

实现路径上，他给出的架构几乎就是搜索排序的翻版：轻量模型从数万亿 token 中筛出约 3 万份文档（3000 万 token），再由更强些的模型收窄到"真正该读的 117 篇"，最后由最强的模型仔细看这 117 篇——大量并行处理加上分层收窄，就是"attend 万亿 token 的幻觉"，正如 Google 搜索让你"搜了整个互联网"但其实只读了一小撮（`00:20:47–00:23:08`）。BERT 进搜索的意义也在此：摆脱"词必须出现在页面上"的硬匹配，走向"这一段与查询在主题上高度相关"。

### 2001 年把索引塞进内存：一个设计决策的教科书

Dean 翻出了从未发表成论文的搜索演进史（2009 年 WSDM 演讲）：1999–2005 年间搜索检索系统经历了四到六代重设计。2001 年的算术至今是系统设计的范文——60 个分片、每片 20 个副本意味着 1200 台带磁盘的机器，他们算出"一整份索引刚好能摊进这 1200 台机器的内存"，于是当年就把全索引搬进内存。质量的跃升来自一个意外的解锁：以前查询里每多看一个词，都要在 60 个分片上各做一次磁盘寻道；进了内存之后，完全可以把用户的 3–4 个词扩成 50 个词——restaurant、restaurants、café、bistro——"在 LLM 之前很多年，我们就在软化用户输入的严格字面定义、去够它的含义"（`00:24:06–00:26:47`）。设计原则被总结为：先想清楚最重要的设计参数（QPS、索引大小、流量翻倍会怎样），按 5–10 倍的可扩展性设计而不要按 100 倍——"当某样东西变成 100X，一个在 X 规模下毫无意义的全新设计点会突然变得合理"，磁盘索引进内存正是流量副本攒够后的"免费"跃迁。变化最剧烈的参数出人意料是更新率：从每月一次到任意页面一分钟内更新，因为新闻类查询对旧索引零容忍；后台另有一整套按页面重要性决定重爬频率的系统（`00:26:47–00:30:06`）。

### 皮焦耳经济学：batch 的存在理由

他那页著名的"每个程序员该知道的延迟数字"（荷兰之所以入选，是因为那里真有个数据中心）在今天有了 AI 版：把训练或推理看成"数据搬运 vs 乘法"的账——一次乘法视精度约在 1 皮焦耳以下，而把数据从同一颗芯片另一侧的 SRAM 搬进乘法单元要约 1000 皮焦耳。"这就是加速器需要 batch 的原因"：搬一次权重要摊给尽量多次乘法，batch=256 时还好，batch=1 等于花 1000 皮焦耳做一次 1 皮焦耳的乘法。swyx 说从未见过有人从能量角度解释 batching——Dean 答得很平静："大家 batch 就是为了这个。理想情况当然想要 batch=1，延迟最好，但能量与算力的浪费太大。"（`00:30:06–00:34:04`）由此展开的是一整套 TPU 设计哲学：芯片要提前两年设计、服役三到五年，所以必须"预测 2–6 年后大家想跑什么 ML 计算"——让对研究方向有判断的 ML 人员参与 TPU N+2 的设计；可以放"投机特性"（占一点芯片面积，赌对了快 10 倍，赌错损失甚微）；反过来，模型架构也会迁就未来芯片（比如按下一代才支持的更低精度直接训练）。他是低精度的忠实信徒——"皮焦耳是按 bit 收费的，减 bit 就是减能量"——低比特权重配缩放因子是已被反复验证的路线（`00:34:33–00:39:15`）。投机解码在这个视角下同样清晰：一次预测 8 个 token、接受 5–6 个，等于把搬权重的摊销改善约 5 倍；模拟计算有趣但数模转换的边界会吃掉大部分功耗优势——"距离今天的位置，专用硬件还有巨大的能效空间可挖"（`00:39:50–00:42:05`）。

### 从 GSM8K 到 IMO：统一模型的胜利与一页纸备忘录

开放问题里他点名两个：长程多子任务任务的可靠性、让 RL 在不可验证领域生效——"如果能做到，数学与编码上的进步就能外溢到其他领域"。他的乐观有实证：两年前大家还在为"GSM8K 小学应用题"挣扎，如今模型在纯语言下做 IMO 与 Erdős 问题——一年半的跨越。技术上，用另一个模型（甚至同一个模型换个提示词）当评审给检索结果打分这类方法"相当有效"（`00:42:21–00:46:13`）。IMO 的故事被他讲成范式注脚：前年是 AlphaProof+AlphaGeometry（翻译成 Lean 加专门的几何模型），今年直接用一个"约等于生产模型、多一点推理预算"的统一模型拿下——"这说明通用模型的能力已经大幅改善，不再需要专门的模型"。他把这比作 2013–16 年：那时候每个问题训一个模型（路牌识别一个、语音一个），如今统一模型的时代真正到来，唯一的问题是它对新任务的泛化有多好。"通用模型将在多数场景胜过专用模型。"人类操纵符号但脑中并没有符号表示——只有分布式激活模式——所以"另立一套离散符号系统"从来就不合直觉（`00:46:13–00:49:10`）。swyx 转述了一位 IMO 团队成员的话佐证：不知道比赛在哪办、不知道规则，"我就是训了模型"。

但通用化有一道算术约束：参数空间有限，把宝贵的容量花在"能查到的冷知识"上并不划算——不过模型仍该有足够的世界常识（知道金门大桥大概多长，才有"桥"的尺度感）。出路是检索加推理的多阶段组合：个人 Gemini 不会把你的邮件训进权重，而是把邮件、照片当工具检索，再推理。对垂直模型他的态度是"有意思，但要从好基座出发"：医疗或机器人数据会把基座的配比挤占（多加 200 种语言的数据，Perl 的水平就会掉），所以垂直化更适合作为"增强数据分布"的后训练；他期待的未来是模块化的"可安装知识"——200 种语言、机器人模块、医疗模块按需拼接，其中一部分靠检索，另一部分"确实应该预载千亿到万亿 token 的医疗数据再训练"；与大型医疗组织合作训练私有模型，可能胜过通用模型（`00:50:38–00:55:21`）。低资源语言那段的案例很动人：Kalamang 语全世界只有约 120 人使用、没有文字，把整个语料放进上下文就能学会（`00:56:09`）。他还翻出了自己早期的工作：把词向量与 ImageNet 图像模型的顶层融合（DeViSE 一系），显微镜不在图像训练类别里，模型却能借助语义空间给它正确打标（`00:57:58–00:59:07`）。

### 一页纸备忘录、50 个实习生与 1 万 token/秒

两段职业往事值得原样记录。其一，他的 1990 年本科论文做的就是并行神经网络训练——当年系里那台 32 处理器的并行机只能训出"稍微有趣"的模型；他始终相信神经网络是对的抽象，只是缺算力。2008–09 年摩尔定律与大数据到位，2011 年底他在 Google 重启神经网络工作，把本科论文里的模型并行与数据并行（当年叫"pattern partitioned"与"model partitioned"）想法复活——论文至今挂在网上（`00:59:22–01:01:40`）。其二，Gemini 的诞生源自他写的一页纸备忘录：当时 Google Research、Brain 团队的 LLM 工作、其他部门的多模态工作与老 DeepMind（Chinchilla、Flamingo）各自为战，"我们不仅在碎片化算力，还在碎片化最好的人"——合并成一个"从头多模态、什么都好"的统一训练项目，就是 Gemini 的起点。名字也是他起的：两个组织像双胞胎合体，而且 NASA 的 Gemini 计划正是通往 Apollo 的中间站（`01:07:10–01:09:27`）。

谈编码 Agent 时，他把当年与 Sanjay 的结对编程哲学平移了过来：你与模型沟通的方式会塑造它的行为——让它写测试、陪你头脑风暴还是放手让它跑，没有唯一正确风格。他给了个管理学的换算："50 个 AI 实习生"该怎么管？答案大概率是让他们组成 5 人小队，你只对接队长。而 Alessio 担心的"50 个实习生的上下文让人类之间难以同步"，他的反直觉回应是：5 个各管 50 个虚拟 Agent 的人之间，沟通带宽可能反而高于 5 个还要协调 50 人团队的人。被低估的老手艺"写清晰规格"被他正式加冕为新核心技能——"从来没人真信过写 spec 这件事，现在你给 Agent 的 spec 直接决定产出质量"；把分布式系统的 20 条常见技巧（Paxos 式复制、双写容忍单点失败等）写成通用指南放进上下文，就能显著提升 Agent 造出可靠系统的概率（`01:10:07–01:18:57`）。他甚至给出了自己想看的实验设计：三次廉价的快速模型调用加人类居中纠偏，对比一次巨型 prompt 交给最聪明的模型——差距到底是能力问题还是规格问题？他的信念押在延迟上：未来会有 20–50 倍低延迟的系统；DeepThink 若不是贵与慢，谁不想天天用——但到那时又会有更强的模型慢 20 倍，"帕累托前沿就是这样不断向外爬的"（`01:18:57–01:21:00`）。收官的两个预测：其一，经你授权、能 attend 你见过的一切（每封邮件、每张照片、每个视频）的个人化模型将极其有用；其二，专用硬件将让低延迟与强能力同时变得可负担。当 swyx 问"1 万 token/秒有意义吗"，他答得斩钉截铁——因为思维链与并行 rollout：而且"最终交付的可能不是 1 万 token 的代码，而是 1000 token 的代码加 9000 token 的推理，那样的代码反而更值得读"。Alessio 的收尾借了那句话："如果我有更多时间，就会写一封更短的信。"（`01:21:29–01:23:11`）
