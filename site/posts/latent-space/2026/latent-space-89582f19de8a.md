## 速读

这是《Inference Engineering》一书作者、Baseten 的 Philip Kiely 与 Ali Taha 做客 Latent Space 的近两小时大师课（节目页称公司刚完成 130 亿美元 Series F）。从"一条 20 万 token 请求进来会发生什么"讲起，覆盖缓存感知路由、PD 分离、投机解码、量化、并行策略、GPU 内核，一路谈到 Rubin 硬件周期、视频生成的 token 数学与持续学习。适合正在做推理服务、模型部署或 GPU 成本优化，想系统补齐词汇与直觉的工程师。

全期最有原创性的观点是量化误差可以互相抵消（更多层用 FP4 反而吞吐更高、质量更好，有论文与 KL 散度验证背书）；最有警示性的是同一份权重在不同推理引擎、不同集群上行为不同（竞态条件暴露与否取决于互联带宽）。数字与结论均为受访者陈述或其团队发布内容。

## 主题正文

### 一条 20 万 token 请求的旅程：先问缓存，再谈算力

Philip 的开场回答把推理系统的第一性原则摆在最前面："你之前发过这条请求吗，或至少发过一部分？"缓存感知路由优先把请求派给已有相关 KV cache 的副本，能省掉大段 prefill；没有命中则交给专职 prefill 的 GPU 组，生成 KV cache 后传给 decode 组——这就是 PD（prefill/decode）分离。编码类流量还会前置一个投机解码用的 draft 模型，命中率高则显著加速。（`00:01:26–00:03:18`）

公共按 token 计费 API 与专属部署的取舍也有清晰判据：Ali 的经验是流量到每小时数百万 token 量级时按小时租整机通常更便宜；专属部署的意义在于流量定制的 speculator、自定义批大小与并行策略、更高精度的量化选择，以及"不会有人在你的专属端点上跑一亿 token 的基准测试"。（`00:03:18–00:05:40`）

工具调用这条支线的结论偏保守：JSON 至今没有被替代，难点在训练与量化后模型读不好 JSON、在流式中校验困难；推理侧的答案是约束解码——用状态机把输出限制在指定格式（他们约两年前发布），但它只保证结构，不保证调对工具；MCP 在他们看来只是工具的一种形式，Philip 的提醒是"LLM 本身什么都做不了，只能提出格式正确的建议，由知道的系统去执行"。（`00:05:58–00:10:25`）

### 新模型上线：从"能出一个 token"到生产可用

新开源模型发布当天的"推理大战"（Philip 提到某模型发布次日各家速度从 90 tokens/s 跳到 150）背后是大量隐藏工作。Philip 的区分很关键：借 vLLM/SGLang 出一个 token 不难（维护者常提前拿到权重或合并 PR），难的是自有技术栈里的生产就绪——重新做量化校准、用真实模型权重训练 speculator（需要 hidden states 作训练数据；由于模型 API 实行零数据保留，他们用公开数据集模拟编码与 Agent 流量）、再搭起全部基础设施。架构最前卫的 DeepSeek 系最难伺候，GLM-5.2 的稀疏注意力（DSA）也要专门在运行时实现。（`00:11:26–00:15:01`）

最能体现开源"嫁接"文化的是他们把 Kimi 的视觉编码器接到 GLM-5.2 上：只训练几百万参数的投影层，"大脑和眼睛都冻住，训的是连接"；训练数据从"描述这张图"升级为对每张图回答一组判定问题后出现明显的 grokking。成品是个研究性质的项目（Philip 印象中 MMLU Pro 约 56%），但文本质量零损失——没有图像输入时直接跳过编码器，而视觉编码器通常不足十亿参数。Ali 补充的另一类嫁接更偏工程：MiniMax M3 的全注意力头让投机解码遭遇 KV cache 平方级瓶颈，他们直接换成其他模型的 GQA 层再训回同样的接受率。他的结论是"训练与推理正在熔合：没有好的训练就做不出快的推理"。（`00:15:01–00:20:21`）

上线后的第一个月同样是工作：GLM-5.2 曾在部分提示与温度下模式坍缩、反复输出同一 token。他们的端点对同一 token 连续出现四次以上就直接切断重试（排除表格线等特殊字符）。Ali 的归因很有信息量：这通常不是权重问题——同一权重换推理引擎或换集群就消失，而是内核级竞态（缺失的屏障、线程提前读寄存器），甚至取决于集群间 KV cache 迁移所用互联的快慢；温度 0 的输出不可复现同样源于硬件。"这更像传统软件工程问题，而不是模型问题。"（`00:20:26–00:24:52`）

### 量化误差可以互相抵消：更高吞吐、更高保真

对"量化是不是必然更差"这个问题，Ali 给出了他们研究团队的反直觉结果：研究实习生 Joshua 的论文证明，不同层的量化误差方向可以互相抵消——可以预测哪些层的误差会相消并优先量化它们。方法是用量化后模型与全精度模型 logits 分布的 KL 散度（而非基准分）验证保真。结果是在 GLM-5.2 上比 NVIDIA 的配置多量化约 20% 的层，吞吐高出 20%，质量反而更好。经验法则还包括图像模型不量化调制层与输出投影。这篇论文最初 72 页，删到 45 页才发布。（`00:25:00–00:32:15`）

对质量本身，Philip 的定义是"对原始模型黄金实现的保真度"：大多数优化（KV cache、投机解码）是无损的，量化是主要的有损环节，靠数据格式、层选择与校准控制。行业里 Kimi 发布过 vendor benchmark（Kimi Vendor Verifier）来约束下游供应商的量化质量——Ali 指出这很合理，因为用户只会骂"Kimi 不行"，而不会知道是某家供应商量化坏了。（`00:25:00–00:28:30`）

提速的量级感也值得记住：万亿参数模型在无优化基线下大约 30 到 50 tokens/s；叠加 NVFP4（约 2 倍）、speculator（约 2 倍）、PD 分离（约 2 倍）与更好的内核（两位数百分比），10 倍是激进目标、4 到 6 倍更常见。Ali 在单节点 B200 上的经验是投机解码加量化贡献了约 95% 的收益；各项优化对专家而言"各自数小时到数天"的一次性工作，且社区已有现成的 FP4 权重与 speculator 可取用（GLM-5.2 自带 MTP 可做自投机）。基准测试本身则要警惕：TPS 一词混用了吞吐与延迟（后者应叫 ITL），NVIDIA 的 Dynamo 是"在集群里搬运 KV cache 的工具包"而非 pip install 就提速的魔法。（`00:32:25–00:42:23`）

数据中心与本地推理则是两个目标相反的学科：Philip 的概括是本地 AI 在解决"把模型塞进硬件后让它没那么笨"，数据中心推理在解决"加载模型后让它没那么慢"；本地社区擅长的动态量化、剪枝与蒸馏并不都适用——Ali 举例 TurboQuant 类优化在内存带宽受限的 MacBook 上收益巨大，在 3.5TB/s 带宽的 B200 上反而被反量化开销吃掉。（`00:46:45–00:50:16`）

### 并行策略、硬件周期与 Rubin 时代的"系统问题"

并行三件套的直觉：专家并行把整个 expert 放进 GPU、路由器复制多份，通信少、吞吐高；张量并行把模型切到所有 GPU、每步做 all-gather/all-reduce，吃互联带宽但利于延迟；流水线并行只在被迫跨节点时使用（H100 只有 80GB 显存，万亿参数 FP4 约 800GB，节点间互联慢，只能节点间流水线、节点内做张量与专家并行）。B200 单卡 180GB。配置选择没有可推理的最优解，行业做法是用真实流量影子采样，在 TP/EP 组合空间里自动调优。（`00:50:25–01:00:55`）

对"兆级内核"（mega kernels）Ali 明确看空：非线性操作需要完整行数据，张量并行下半个矩阵在一块 GPU 上也必须通信；而且据他了解，做融合兆内核的公司大多没在生产中运行它们——逐组件优化的内核反而更快；他还转述 NVIDIA 人士关于 Rubin 架构设计"让兆内核不再必要"的说法。（`00:54:32–01:00:55`）更大的判断是：GPU 正沿着通用计算到 ASIC 的光谱向专业化移动，但"把权重烧进芯片"不实际（要微调、要量化、要出新 checkpoint）；Rubin 更像"可编程 ASIC"——张量核、TMA、张量内存都是围绕当今模型的头维度设计的。对垂直整合实验室做专用芯片（如 OpenAI 与 Broadcom 合作），swyx 引用 Martin Casado 的算式：五千亿美元训练里拿五百亿做 ASIC 换 10% 以上效率是划算的，但真正的 10 到 1000 倍瓶颈在互联通信。（`01:00:55–01:06:41`）

显存数学决定了模型形态：Kimi 2.8 万亿参数在 FP4 下约 1.4TB，只有 GB300（单卡 288GB×8）或 AMD 大显存方案能单节点放下，而且还要给 KV cache 留空间——参数与上下文长度在争抢显存，这正是 KV cache offloading 越来越重要的原因。DeepSeek R1 的 671B 当年就曾倒逼行业快速掌握 Blackwell。模型寿命比想象的长：4o 和 Llama 3 仍有工作负载，企业要的是可靠与可预测；但开源生态的优势在于"不需要一场拯救 Llama 3 的运动，有一台 H100 就行"。（`01:07:01–01:12:42`）

### 视频、扩散与自回归：另一个世界的推理问题

视频扩散模型的推理形状与 LLM 几乎相反：不做批处理、不切分片，一个请求占一张 GPU，模型小得多（Wan 2.2 约 200 亿参数）。但开源与闭源的差距在视频领域远大于 LLM（后者按 Ali 的说法已接近抹平）：Wan 2.2 与 Kling/Veo"差得不是一星半点"，于是媒体公司宁可多付百倍成本用闭源——需求少导致开源投入少的循环，Wan 2.7 已经闭源。根本约束是 token 数：480p、16fps 的五秒视频压缩后仍有约 3.5 万个 latent token，注意力是平方复杂度，一分钟镜头在全注意力下不可行。出路只有两条：稀疏注意力（只算 top 12.5%，质量受损）或自回归视频——Ali 押注后者，但坦言现有开源自回归视频模型质量"都很差"，闭源方案靠分块拼接（如 Grok Imagine 的 7 秒块）维持一致性，开源只能用"末帧+提示"续写并承受逐渐发黑的漂移。Philip 补充了原理：扩散的注意力是双向的，可以回头修改过去让未来自洽；自回归只向前，这正是文本可以流式生成而长视频难以流式生成的根源，未来大概率是两者的混合架构。（`01:12:46–01:21:47`）

最后的主题是训练与推理的合流：RL 训练的 rollout 依赖快速推理（推理引擎不支持就要退回旧引擎、拖慢整条训练管线），而量化感知蒸馏等训练技术反过来服务推理（NVIDIA 已有以全精度模型 logits 蒸馏 FP4 模型的论文）。Philip 设想的生产级闭环是：推理产生轨迹、持续后训练、A/B 验证、动态调整胜过任何静态配置。Ali 已经见过现实的循环——他们把 GLM-5.2 接进编码 Agent 的 harness，让它读自己推理节点的 profile trace、找出 SGLang 的瓶颈内核、写出新内核再上传镜像，"GLM-5.2 在优化 GLM-5.2"；当然模型还会 reward hacking、决策能力仍不足，至于"它会不会暗算 DeepSeek 的内核"，Philip 的回答是不信，但"试试就知道"。（`01:27:43–01:33:47`）

结尾的两个开放判断：Ali 认为推理的下一个数量级在更快的网卡——KV cache 目前要在节点内存与 GPU HBM（约 4.5TB/s）之间多级搬运，如果 NIC 能追上一个量级，跨节点 disaggregate 解码理论上能有约百倍提升；持续学习则取决于走哪条路——把知识写回权重只能修"一跳"事实（改了"最好的大学是 Waterloo"也推不出"该从哪招实习生"），而 KV cache 压缩可以在不动权重的前提下承载持续学习，他在这场与朋友的公开争论后认输了后者。（`01:33:58–01:40:06`）
