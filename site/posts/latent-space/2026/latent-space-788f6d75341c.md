## 速读

OpenAI ChatGPT Work 上线约一个月即宣布 Codex 与 ChatGPT Work 合计用户破千万。这期节目请到领导该产品的 Core Product Engineering 负责人 Akshay Nathan，讲清"合并"背后的产品判断：Codex 在非开发者中的内部扩散让他们确信 Agent 的能力不属于开发者专属，于是把同一套 harness 同时供给两个界面。主持人 swyx 与 Vibhu 还现场用两个模式跑了对比 demo。

最值得带走的三点：Codex 与 Work 共享 harness、只在 Git 状态暴露与 diff 呈现上有观点化差异；Sites 正在取代幻灯片和表格成为团队协作的"正典产物"；以及结尾对生产力度量的讨论——提交数、故事点这类代理指标在 AI 时代失效，"at-bats 质量"与"动作 vs 进展"的区分值得每个管理者记住。产品数据与规划均为受访者口径。

## 主题正文

### 合并的由来：Codex 先在非开发者中扩散了

Akshay 的职业生涯从消费金融科技到"让不懂代码的人用上代码的能力"（创业项目、Airtable），2023 年加入 OpenAI 时公司约 500 人。合并的直接起点是内部观察：Codex 发布后在战略财务、市场等非工程团队里出现采用拐点，而且用户"为自己在用 Codex 而骄傲"，感觉像获得了超能力。团队意识到 Agent 的能力远比想象中早地超出了开发者人群，问题变成如何借 ChatGPT 的分发把它带给所有人——这就是内部的"Merge/超级应用"决策，最终以 ChatGPT Work 落地。（`00:05:27–00:07:36`）

定位上，他刻意用"生产力"而非"企业"或"工作"命名团队：既有工作场景，也有个人生产力——他举了有人让 Agent 从快递照片反查出包裹所在公寓楼的例子。Codex 作为品牌会长期存在并继续为开发者深化，但原则是"不让用户被困在某个标签页里"：两个界面共享同一 harness（为知识工作强化了插件、computer use、artifacts），差异只在观点化的 UX——Codex 模式默认暴露 Git 状态与 diff、面向仓库，Work 模式隐藏这些并配不同的沙箱默认值。他对合并的根本论证是：AI 正在快速模糊写代码、写战略文档、做活动策划、做播客之间的边界，"按身份划硬边界会越来越难，应该让用户选，而不是把他们框死"；插件也因此跨产品统一。（`00:07:36–00:13:45`）

### 两代 harness 与"32 个选项"的默认值哲学

swyx 把这次更替称为"幻觉工程口述史"的一章：ChatGPT 经典 harness（新开聊天即即时模型）仍在，多年优化集中在延迟与"个性"；Codex harness 的洞察是"给 Agent 一台无限灵活的计算机"。Akshay 用"发散—收敛—再发散"描述两者关系：知识工作选择计算机环境更自然，但要向不习惯它的用户抽象掉细节。何时把你从聊天推向 Work 模式，是模型自己的路由决策（比如你开始要它做表格）。（`00:13:45–00:16:24`）

面对"32 个模型选项"，产品答案是把默认值做到对绝大多数人最优：推理滑杆把多维权衡投影成一维（一端速度与成本，一端质量与彻底性）；Ultra/多 Agent 模式适合极复杂或可并行的任务，goal 模式适合可逐步验证的持续推进，但对多数任务两者都不沾——先用默认，遇到效率或质量不满再调。上线后他们还把 Ultra 改成需在高级设置中主动开启，因为它消耗更多额度，属于"明白会发生什么"的 Power User。（`00:16:24–00:20:04`，`00:54:12–00:54:39`）

### Artifacts 与 Sites：交付物正在从幻灯片变成网站

这轮发布在模型侧（GPT-5.5 到 5.6 的 artifacts 质量"显著提升"，且 5.6 与 Work 同日发布）和产品侧同时投入。Vibhu 现场演示的退休金计算表格"看起来像 Excel"，Akshay 强调这是"第一阶段"：关键是渲染结果与同事看到的足够一致，用户才敢在它上面迭代。多人协作在规划中，他自嘲自己常充当"AI 与 AI 之间的转发服务"——把同事问题丢给 Agent 再转述答案，既损耗上下文，也有权限层问题（我看不到我不该看的），而 Agent 连接插件与本地文件后的上下文"深度涉及个人"，必须守住。（`00:20:04–00:24:41`）

Sites 是他最想强调的新格式：它既是原型工具（本期讨论的模型滑杆本身就是在一个 Site 里由设计、工程、产品协作打磨的），更是知识工作的"正典产物"——他提到公司财务团队的月度报告已从幻灯片和表格迁到 Sites，理由是网站"带宽更高"：PowerPoint 和 Excel 有功能边界，而"你什么都能要求"。swyx 的案例更夸张：把一个实体桌游拍 30 张照片丢进 ChatGPT，17 亿 token 之后得到一个可 3D 摆放的完整游戏网站，再用 Sites 生成训练自博弈 AI 的研究仪表盘——"我已经不读 ChatGPT 的输出，我读 Site 的输出"。代价是冗长与蔓延，需要继续修剪；Akshay 的回应是 Markdown 本就不适合人读，不如直接产出网站。（`00:24:41–00:30:07`，`00:26:02–00:29:05`）

### 采用路径：开发者 → 知识工作者 → 所有人

Akshay 把扩张描述为三段接力：从开发者（能忍受摩擦的早期采用者）到"通用知识工作"（artifacts、computer use 等对此人群更关键的能力），再到所有人——他自己在家全时段使用 Work，连膳食计划都存在它的持久计算机环境里。给进阶用户的建议是"不断拓展想象力的前沿"：他举绩效评审季为例——半年前用 AI 写评审"全是 slop"，现在模型能拉取代码、Slack、历史评审来汇总一个人的贡献，"做得比我好"；同时他把底线划得很清楚：绝不直接用 AI 生成评审文本，AI 的角色是 agentic search 和上下文收集。另一个建议是投入更多上下文——保存在库里的 artifacts 会让模型以意想不到的方式主动关联。（`00:33:50–00:41:43`）

里程碑方面，swyx 称这是"很长一段时间里最成功的发布"：千万用户的数字是 Codex 与 Work 合计（同一 harness 无法分开计数），目前仅限付费用户、不设默认，教育用户仍是过程；Akshay 的心态是"开始"而非"终点"。（`00:41:43–00:44:38`）

### 记忆、Chronicle 与"个人 OS"

OpenClaw（独立的开源个人 Agent）是这期反复出现的参照物。Akshay 自己的"OpenClaw 时刻"是和妻子用它管理家务、写日历事件，直到笔记本坏掉；这直接启发了 ChatGPT Work 的持久计算机环境——文件跨会话留存，团队成员已用它替代 OpenClaw 做训练计划与饮食记录。财务场景他实测过：ChatGPT 不托管资产，但退休规划、预算等 Wealthfront 的核心功能已被插件覆盖；他的论点是传统 UX 靠堆筛选器和搜索框给用户权力，而现在"连接对的数据，问什么都有答案"，还免于在十几个健康/财务应用间分散。（`00:44:38–00:49:08`）

数据工程出身的 Vibhu 追问：仅靠 MCP 的即时拉取是否需要语义层或数仓？Akshay 以访问模式回答：Work 的多数任务不需要即时答案，programmatic tool calling 与子 Agent 并行已大幅抬高了调用外部服务的天花板。记忆方面，ChatGPT 的 Memory V3 是 Work 的默认继承项——所有会话读取并回写你的 ChatGPT 记忆，"你的 ChatGPT 认识你"是用户调研的第一名；难点是双向的检索问题：既要记住，又要有情商在恰当时刻主动提起。实验性的 Chronicle 则把你对计算机的使用本身变成记忆来源，他承认不可能捕捉全部意图，"但它会找到你不知道自己知道的东西"。（`00:49:08–01:00:44`）

### 度量生产力：代理指标失效，"动作"不等于"进展"

对管理者最有用的部分在最后。Akshay 认为团队不会变小——"个人能做更多，但可做的事也更多，团队反而更有野心"；角色边界（EM/PM/工程师/设计师）在模糊，每个人会被 AI 推成"有专长的通才"（T 型），而瓶颈变成想法与品味。他坦承有一件事 AI 做不到："给我带来新想法"——想法来自用户交流与摩擦反馈，接住这个闭环的仍是通才。（`01:00:44–01:04:41`）

度量上，他承认还没解决：每个人的目标不同，真实度量是"我们是否帮你达成了目标"，而点赞点踩无法区分你不满的是内容、氛围还是目标本身。过去用提交数、代码行数、故事点做代理指标，AI 时代这些与"是否接近目标"不再强相关——token 用量、PR 数量同样失效。他给出的替代关注点是"at-bats 的质量"：团队能否高效走完"想法→构建→反馈→验证或推翻→下一个"的循环，以及支撑它的文化韧性；最大的陷阱是"把动作当进展"——工具让动作空前容易，而进展要求对目标极其明确和刻意。（`01:05:29–01:09:09`）
