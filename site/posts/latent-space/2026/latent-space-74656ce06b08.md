## 速读

两年前 Latent Space 采访 Modal 时它还是一家刚拿 A 轮的小公司；这次以 3.55 亿美元 C 轮回归，CTO Akshat Bubna 把公司逻辑讲得很清楚：传统云为"人会读文档、填上下文"的世界设计，而 AI 工作负载的形状完全不同——需要爆发式伸缩、专用环境，现在还要让 Agent 自己来操作基础设施。

最值得带走的三点：SDK 团队已经从开发者体验（DX）转向 Agent 体验（AX），两者余弦相似度约 0.9 但观测重心变了；RL rollout 一次可能要十万个沙箱、是所有负载里最 bursty 的；以及对"让 LLM 做权限中介"的明确怀疑——沙箱级别需要硬边界，否则就是数据外传通道。

## 主题正文

### 起点是一个更好的运行时，不是 GPU 公司

Modal 的起点是 CEO Eric 对工作流编排产品的追问：为什么这些产品都这么难用？因为它们跑在 Kubernetes 上，而 K8s 不是为 bursty 负载设计的，自定义镜像麻烦、开发者体验糟糕（`00:00:39–00:03:13`）。他们的答案是先把"更好的运行时"本身做成原语——serverless 函数天然解决 ETL、任务队列、爆发式处理这些每家公司都有的需求——再在其上做垂直产品。容易被忽略的时间线细节：他们在 ChatGPT 发布前一年就给产品加了 GPU，当时以为只是"顺手加个 A100"。配置全走代码内装饰器（decorator）而不得不用 YAML，这套"软件定义基础设施"的思路从一开始就是核心；面对"你这是个 DSL、锁定供应商"的质疑，Akshat 的回应是你带来什么代码就是什么代码，DSL 只覆盖硬件与伸缩配置层（`00:03:13–00:04:32`）。

### DX 到 AX：Agent 不读文档，但需要更好的可观测性

这轮最大的叙事转变是：Modal 把 SDK 团队的目标从开发者体验改成了 Agent 体验。论证很朴素——DX 的好处对 AX 原样成立：与其让 Agent 翻几百个 Kubernetes 文件、写没有类型检查的 YAML，不如让它改两行装饰器、立刻看到变更生效。客户侧的反馈是 Agent 用 Modal 比用其他底层快得多（`00:04:32–00:06:21`）。swyx 抛出反面论点——"没人看代码了，所以这些无所谓"——Akshat 的回答是观测性反而变得更重要了：他们把大量调试能力推进 CLI 让 Agent 自查，但人仍然要解释发生了什么、做判断，"现在这可能比读代码本身更重要"。一个有趣的反馈回路：他们做了 Modal Bench 基准去找 Agent 做不好的事（比如从日志推理出该改哪里），发现 Agent 会"幻觉"出不存在的功能——而那正是产品信号，"它伸手要的东西，也许就该做成 CLI 命令"；日志和指标也从 UI 搬进了 CLI（`00:55:52–00:57:28`）。

### AI 工作负载的真实形状：定制模型、昼夜错峰与十万个沙箱

Modal 今天最大的用例是弹性推理，而最早找到产品市场契合的是"自定义模型"推理：刻意避开 LLM 市场，服务 Suno（音频）、Runway（视频）、机器人、计算生物这些在别处训练模型的团队，把部署和伸缩当黑盒交给 Modal。这些公司的流量是昼夜规律的、发布日会陡增，而且同时部署大量模型于多个区域、各区域周期错开——autoscaling 因此比想象中难，也成了 Modal 的专长（`00:12:12–00:13:36`）。技术抓手是 GPU 快照：把 torch.compile 之后的 GPU 状态快照下来，下次冷启动快得多（`00:13:36–00:14:28`）。

burstiness 的极端形态是 RL：rollout 说来就来，"有时你需要十万个沙箱"，训练前的编码预处理也动辄要几千 GPU（`00:14:28–00:15:32`）。LLM 推理侧他们选择把模型层的能力补上并全部开源：DeFlash 是块级投机解码器（draft 模型按块预测、大模型批量验证），开源版即可拿到与专有供应商相当的性能。Akshat 给了一段教科书式解释：单 token 生成受显存带宽限制，批量验证 draft 的 token 能大幅提高算力效率；只要接受长度够高就是数倍加速——调内核只有几个百分点的收益，而提高接受长度是乘法级的，且大模型会验证每个 token，质量无损（`00:15:32–00:18:08`）。新的 Auto Endpoints 让人从 UI/CLI 直接建一个把 DeFlash 等优化预置好的端点，代码全透明、随时可以"弹出"到完整的 Modal 代码模式去微调。至于和 vLLM/SGLang 自建的区别：他们的改进都开源并上游化，增值在专家团队、真正的缩到零与爆发伸缩，以及生产级推理本身的难度——尾延迟控制、至少一次送达，这些把伸缩性刨掉也依然是硬问题（`00:18:54–00:22:00`）。

### 不建数据中心的"超级云"：17 云容量池与借用来的网络原语

Modal 没有自己的数据中心，而是在 17 家云/裸金属供应商之上建了统一容量池。理由是差异化在软件层、保持资本轻才能跑得快，反正有那么多人在建数据中心；他们自己则重投了可靠性层——GPU 掉线时用户负载不受影响（`00:24:08–00:25:41`）。客户也常要求把 CPU/GPU 钉在特定区域，动机是数据本地性或延迟，比如沙箱和模型要贴在一起（`00:25:41–00:26:40`）。

网络侧的几个原语颇有启发：沙箱现在支持 sidecar——一个沙箱是容器 pod，可跑多容器、挂中间代理，用来做 RL 日志、控制出站 egress 到哪些域名、注入凭证；跨节点的沙箱互联用 I6PN（工作区内的私有 IPv6 overlay 网络，容器间可用私有地址互访、外人不可见）。有意思的是这些原语都是为别的需求造的：I6PN 本来是给分布式训练做 RDMA 密钥交换的 TCP 底座，用户却把它翻出来当私有组网用——"字面上连文档里都没写，他们自己发现了"（`00:26:40–00:28:59`）。多节点训练产品给函数加个装饰器就得到一组带 RDMA 的 GPU（内部网络 3 Tbps），定位不是大训练，而是中小规模 post-training 和"大集群里研究员的小实验"（`00:31:40–00:33:59`）。Agent 侧对应物是 auto inference：内部用它把前置部署工程自动化——Agent 自己起 sweep、跑 Nsight profiler、调配置、把 GPU 从 H200 换到 B200，效果很好（`00:34:01–00:35:02`）。背后还有个叫 compute strategy 的团队专门做容量规划：一年期与三年期预留怎么配比、跨 GPU 型号与区域的容量互换建模、对供应链演化的判断下注——swyx 类比航空公司的燃油对冲（`00:37:36–00:39:47`）。他们也在做面向延迟不敏感任务的 batch 档：便宜得多、24 小时内返回，需求主要来自计算生物的大批处理而不是 LLM（`00:39:18–00:40:35`）。

### 生产级 Agent 需要硬护栏和专用沙箱

对当下流行的"LLM 中介权限"（让模型自己决定能调什么），Akshat 表态很直接：在沙箱级别他持怀疑态度，"你需要硬边界，否则就有人能把东西偷出去"，正确组合是硬护栏加软护栏（`00:43:06–00:44:00`）。对基础模型厂managed agents 的进军，他不认为冲突：托管 Agent 适合起步，但像 Ramp 把对外会计 Agent 跑在 Modal 上这样的生产级场景，需要控制持久化哪些文件、快照与恢复、网络策略、要不要 GPU——这是专用沙箱供应商的位置；至于 harness 跑在云侧还是沙箱里，Modal 没有立场（`00:44:00–00:45:57`）。

他对"模型 API"商业模式的警惕来自 Replicate 的倒下：模型 API 服务的是粘性很差的爱好者市场，Modal 所有示例都是代码起步、可以随意改，为的是服务"在造产品、需要超越 API 的灵活性"的公司——Suno 因为完全自定义的模型架构，必须在代码层改东西，所以推理全放在 Modal（`00:48:31–00:50:41`）。展望上，他看好的方向包括药物发现与计算生物、把机器人放进真实部署的公司，以及"视频 Agent"——给 Agent FFmpeg 不够，"你得给它 Adobe"（`00:50:56–00:51:46`）。还有一个被低估的机会是 CI：编程 Agent 会跑多得多的 CI，而大量时间浪费在准备依赖和构建产物上，内存快照与恢复的原语恰好能复用到这里；Gitpod（现 Ona）团队技术很强，输在"构建时沙箱"没赶上"运行时沙箱"的时代（`00:51:50–00:54:15`）。SDK 策略维持 Python 加 TypeScript 双语言——推理与训练仍然属于 Python，而 Agent 场景的用户大量使用 TypeScript SDK，因为他们的工作负载不需要 ML（`00:54:30–00:55:52`）。
