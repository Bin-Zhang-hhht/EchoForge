## 速读

Latent Space 编辑 Richard MacManus 在 AI Engineer New York（AIE NYC 2026）大会现场，对话 AI 原生财富管理公司 Arca 的 AI 平台负责人 Aman Singh：Arca 不是向顾问卖软件的 SaaS，自己就是那家公司，用 agent 承载横跨十天的金融工作流。最值得关注的三点：分析环节全自动，而资金移动、资产清算与直接接触客户强制人审；每个客户的持久记忆系统加每日「做梦」式反思，让 agent 中断数天后仍能接续任务；安全护栏全部确定性实现、可审计性默认存在，外加每夜分析真实 trace 的 meta agent。（`00:00:10–00:01:05`）适合做 agent 基础设施、评估闭环与高合规行业落地的工程师。

## 主题正文

### 定位：AI 取代的是顾问周围的工作，不是顾问

Arca 开场被介绍为一家近期融资 6400 万美元的 AI 原生财富管理公司（`00:00:10–00:00:41`）。Aman 自述领导 AI 平台团队，负责建设底层 harness 与各项能力，目标是用 AI 运营整家公司（`00:00:41–00:00:52`）。服务覆盖财务建议、资产财务规划、税务规划、保险与遗产规划；客户从刚卖掉公司的企业主、规划提前退休的大型科技公司高管，到想买首套房的小家庭（`00:00:52–00:01:40`）。

核心理念：AI 的角色不是取代顾问，而是取代顾问周围的所有工作。客户并不直接与 AI 交互，他们体验到的是通过人类顾问的共情与关怀交付的、此前这个行业做不到的服务水平（`00:01:51–00:02:14`）。在每个客户背后有一套持续运转的「机器」：市场在发生什么、对这位客户意味着什么、客户生活里哪些「纹理」会影响其财务——AI 承担全部后台工作，让服务更主动、响应更快（`00:02:14–00:02:42`）。

商业形态是这一切的前提。Aman 强调 Arca 不是 SaaS 公司，自己就是那家公司本身，因此可以规定这类工作以什么标准流程发生，让 agent 以标准化方式参与（`00:13:26–00:13:45`）。这也是他区分「AI 原生的公司」与「用上 AI 工具的服务公司」的落点：后者需要用户 prompt agent 才产出工作，而在 Arca 是「Agents prompt people more than people prompt agents」——服务全天候主动运行（`00:15:20–00:16:04`）。对于 Anthropic 近期推出金融服务、与多家机构合作，他认为这对行业是一种验证（validating）（`00:15:06–00:15:26`）。

### 十天级工作流：分析全自动，资金动作强制人审

他在大会演讲中举的税单案例横跨十天，由 agent 负责交付最终结果，但流程中有明确的分工（`00:05:45–00:06:07`）。客户来信说收到一笔税单、需要筹出 10 万美元——这位客户的资金现在如何配置、最优的清算路径是什么，这类分析最适合交给 agent 承担（`00:06:07–00:06:32`）。

边界画得很清楚：分析环节完全自动化，但 agent 不能自动执行任何资金移动或资产清算。Arca 与托管方（custodian）有很深的集成、对方提供的 API 具备执行能力，但对资金移动、清算以及直接与终端客户沟通，都设置了严格的人审护栏（`00:06:32–00:07:08`）。agent 会拉入合适的人来执行交易，并给出一份可审阅、可调整的计划（`00:07:08–00:07:21`）。目前不做自主交易：agent 只提议交易，是否执行、如何执行完全由专家决定（`00:20:13–00:20:33`）。

「拉谁进来」也是 agent 的工作。Aman 把这类比作行业里的人类协作：十天的流程有多个参与者，第七步的执行者此刻未必需要知道这件事，会在恰当时机被拉入；agent 依靠长记忆加每日反思判断世界状态，当某个信号意味着必须拉入某人时才拉入（`00:12:27–00:13:13`）。这背后是把「这个行业如何运作」以及「Arca 希望它如何运作」的知识操作化的成果（`00:13:13–00:13:26`）。

### 跨天接续：持久记忆系统与每日「做梦」反思

任务一放几天，agent 恢复时如何确认计划仍然成立？信号分两类：同一封邮件线程的新回复，会路由回正在读这条线程的同一个 agent；而中途插入的一通电话是全新信号，不附着于任何进行中的流程，会唤醒一个新 agent，它靠内部记忆系统理解当前局势（`00:07:42–00:08:25`）。

记忆系统为每个客户持久化一整套状态：现在在发生什么、我们在服务什么、谁负责什么、到目前为止发生了什么、接下来几天要立即处理什么、长期在跟踪什么、每个行动由谁负责——所有 agent 都向它贡献信息（`00:08:25–00:08:51`）。另有一个他称为「做梦」（dreaming）的过程，持续反思与客户相关的世界状态并更新记忆，让长时程任务得以持久化；新唤醒的 agent 因此能迅速上手，识别出自己正在处理一笔大额税单，并把自己的信号归入这个世界状态（`00:08:51–00:09:22`）。

主动性最终落到具体客户身上。一位尚未签约的客户（Arca 已拿到其全部文件、账单与持仓）原本另有一位顾问：agent 读完所有材料、分析了客户自述目标与原顾问的收费后发现，对方在收一些客户本人不知道的费用，而且那位顾问甚至不是 fiduciary（受托人）、法律上并不义务为客户利益行事；Aman 把这种分析颗粒度归为 agent 分析财务图景时的细节注意力（`00:24:12–00:25:33`）。更多例子是期限类提醒，比如客户面临错过 RMD（最低要求提款）的风险；这类事对人类来说难以规模化跟踪，但在 Arca 是 agent 的默认行为（`00:25:39–00:26:02`）。

### 模型策略：内部基准、分层路由与自研 harness

模型栈用的是 Anthropic、OpenAI 等前沿实验室的模型，Claude 一直是主力；几年间经历过 Gemini、OpenAI、Anthropic 的多次迁移，而所有决策由内部基准引导——针对自家通用 harness 运营业务所需各项能力的自建评测（`00:02:52–00:03:28`）。最近的例子：某个外部基准宣称很强的模型，在他们内部却没有达到预期——太慢、成本太高；模型选型因此始终由内部基准说了算（`00:03:28–00:03:50`）。

原则是 model-agnostic：不对单一供应商或某个实验室的 harness 形成依赖，保留可选项；harness 完全自研、模型无关（`00:03:40–00:04:13`）。路由按任务复杂度分层：税务规划、税务分析这类任务用最重的一档模型（档内保持弹性，可以是 Opus 档、Sonnet 档或重量级 GPT 模型），而 agent 参与的大量后台活动用低档模型（`00:04:26–00:05:04`）。这些决策对顾问完全不可见——被整体抽象掉了，顾问只照常与产品交互（`00:05:04–00:05:15`）。

对大会上 Anthropic 介绍的 managed agents 基础设施，他的态度分两层：对 Anthropic 和 OpenAI 的模型非常看好，但对依赖 managed agents 这类产品没那么看好——因为它的核心之一是模型如何持久化、如何为世界状态贡献记忆与运营知识，把这部分交给外部供应商是一种风险：拥有自己的智能，才拥有影响业务的能力；交出去，就失去了打造深度贴合自身业务的东西所需的控制权（`00:13:45–00:15:06`）。

自研 harness 的另一处价值是纠正模型对金融知识的过度自信：模型回答金融问题时对自己已有的知识非常自信，节目里的例子是会直接拿 2025 年的税级来做分析——而这显然是错的；decision models（决策模型）在模型即将给出金融建议或任何需要金融严谨性的动作时介入，推动它改用知识库中「今天为真」的已验证事实，或者做网络搜索（`00:18:42–00:19:51`）。他把这归结为拥有自己 harness 的意义：让模型在关键之处准确（`00:19:41–00:19:51`）。

### 安全、合规与评估闭环：确定性护栏、默认可审计与夜间 meta agent

安全限制全部是确定性（deterministic）的，把决策从 agent 手里拿走：简单的记录类工具 agent 可直接执行；而每一次写数据库的工具调用，都要过一层基于 LLM 的快速验证（`00:09:33–00:10:05`）。系统吞入的外部信息（邮件、文档、电话）是提示注入的目标，因此在边界处跑注入检测；数据离开系统时——最明显的是网页搜索，也包括给客户发日历邀请——先做 PII 的确定性检查，再由一组小模型共识判断是否存在数据外传企图（`00:10:05–00:10:52`）。护栏的总原则是卡在能力边缘（edges of capability），而不是更早（`00:10:52–00:11:02`）。

合规方面，他的概括是「行业关心结果，合规关心可审计性」（`00:11:18–00:11:32`）。系统里可审计性是默认的：agent 的每一个动作都产生 change log——改了什么、谁改的、从系统哪个部分、何时；这不只针对 agent，人类在 UI 上做出影响客户的改动同样被记录（`00:11:32–00:11:52`）。同一份日志还反哺 agentic loop：可以用来告知 agent「UI 上刚发生了这个变化」（`00:11:52–00:12:15`）。

沙箱的用法也有讲究：沙箱是 harness 的一个组件，agent 本体并不待在沙箱里，而是用沙箱卸载计算（`00:16:14–00:17:02`）。为让沙箱内代码安全访问数据，agent 写的代码会被翻译成系统期望的严格格式、原代码被丢弃，在这份格式进入后端之前施加护栏；agent 因此可以用代码查询、聚合、清洗数据，产出财务计划 PDF 这类可交付客户的产物（`00:17:02–00:17:26`）。产物一旦生成，立刻跑一组验证：确定性检查（比如是否混入了原始账号），加小型快速模型分析是否存在不合规内容——比如不得在产物中承诺回报（`00:17:41–00:18:17`）。他称这让合规比纯人工做得更好，因为 AI 在发现最细微的不合规措辞上不知疲倦，Arca 会继续投资这类能力（`00:18:17–00:18:42`）。

评估闭环从产品内开始：主持人在提问中引用其幻灯片——每次员工编辑或取消都带着一个原因，并成为一条 eval；Aman 补充这是自己身为业务方而非 SaaS 的优势，Arca 可以要求员工给出反馈（`00:20:33–00:21:02`）。反馈连同产生它的 agent trace 一起存入数据存储；每晚跑一个 meta agent，基于来自真实世界的 trace 提出 harness 修改建议——误导性的工具、报错、知识库缺失（`00:21:02–00:21:48`）。目前上线 prompt 变更前仍保留人类工程师审核：他观察到 agent 无人看管时会做出很糟糕的 prompt 修改，每个小修补都会变成整段 prompt，无法保持 meta、把修补泛化（`00:21:48–00:22:22`）。

把公司运转知识变成 agent 上下文的办法是：知识库以文件形式组织，交给专家在产品内维护——产品左侧有 Knowledge 标签页，承载 agent 使用的全部运营上下文；agent 工作时会引用知识，错误的知识会在 trace 分析中浮出，专家直接在产品里修改（`00:22:47–00:23:38`）。
