## 速读

"localhost 之死"是 Ivan Burazin 喊了十几年的口号：他做过最早的浏览器 IDE CodeAnywhere，如今 Daytona 成了 Agent 基础设施热潮里增长最快的公司之一（月增 74%，最大客户一天跑约 85 万个沙箱）。这期访谈把 Agent 计算这门新生意讲得非常透。

最值得带走的三点：Agent 需要的不是"代码执行盒"而是可组合的完整计算机——有状态、可暂停恢复、秒级启动、能动态 resize 到几乎无法 OOM；RL/evals 负载几个月内从 0% 涨到约 50%，其"方形脉冲"式的用量形态是基础设施行业从未见过的（平均利用率仅 15%）；以及 computer use 背后的十万亿级判断——遗留 Windows 应用锁死的知识工作，只有给 Agent 一台真电脑才能解锁。

## 主题正文

### 十六年后的同一颗子弹：localhost 之死

Burazin 的创业史是一个论点的三次执行：2000 年代做服务器虚拟化服务，随后做了最早的浏览器 IDE CodeAnywhere（早于 Cloud9 与 Replit，约 300 万用户，太早，天使钱都还了），中间办了 Infobip Shift 大会，三年前再出发做 Daytona——起初仍是"给人类工程师自动化开发环境"，去年一月硬转向 Agent 沙箱（`00:02:05–00:04:01`）。转向的契机很有戏剧性：他们拿 OpenDevin（现 OpenHands）套自己的基础设施做了个 SaaS，用的人不多，但大量 Agent 开发者找上门说"我的 Agent 需要一个计算沙箱"。他们给了，然后所有早期用户都说"这不是我们要的，会崩"。于是非 AI 出身的他花一个季度听遍所有播客补课，然后在除夕夜半 vibe code 出了 Daytona 今日形态的第一个 MVP——凌晨三点睡下，CTO 早上看到评价是"绝对的垃圾，千万别给人看，但想法是对的"，花两周重写（`00:07:06–00:10:09`）。回访一季前说"不行"的客户，每通 15 分钟的演示电话都聊到 25–30 分钟，第二天所有人追着要 API key。"我做过好几家公司，从没见过客户因为你不给访问权而打电话来。"他们当场 all-in，并看清了市场的量级差异：人类工程师市场是 GitLab，而"每一个未来会存在的 Agent"的市场没有上限。

### 产品哲学：Lambda 与 EC2 的合体

Daytona 拒绝"沙箱"这个词的窄义（demo/测试环境的暗示），定位是"给 AI Agent 的可组合计算机"——正如人类有不同的电脑配置（他妻子的 Windows 3D 渲染机），Agent 执行不同任务也需要不同组合的计算机，通过 API 供给（`00:04:58–00:06:19`）。技术路线从第一性原理推出：主流方案跑在 Firecracker/VM 上、状态不随沙箱走、且是可抢占的短命的；而 Agent 像人一样需要"合上盖子再打开还是原样"的有状态长跑，又需要极速启动——"把 Lambda 和 EC2 合起来"。他们最终跑在裸金属上、用自研调度器（CTO 把 CodeAnywhere 时代的手艺带了回来，第三位联合创始人评价"这像 2008 年的东西"——"没错，就是要回到那个时代"）：快照与模板预载在裸机的 NVMe 盘上，启动沙箱即定位到对应物理机直接开机，没有网络存储延迟（`00:12:02–00:15:02`）。三个关键指标：单个沙箱启动 60 毫秒（含网络往返）；并发启动 5 万个约 75 秒（有公开数据的别家要约 2000 秒）；最大客户每天跑约 85 万个沙箱，另有 50 万并发的请求在谈——"基本上无上限，因为我们有自己的金属"（`00:16:40–00:17:44`）。

### 两种负载形态与 15% 利用率的新难题

访谈里对基础设施从业者最有价值的洞察是负载形态的分类学。第一类是 background agents / 长跑 Agent（Cognition、Lovable、Harvey 等）：用量像人类一样 follow-the-sun——正午最高、午夜最低、工作日高于周末，可预测、可规划容量。第二类是 RL 与 evals，几个月内从零涨到约 50% 的用量：形态是"方形脉冲"——给定一万个 CPU 的并发额度，一开跑就 100% 拉满，跑完归零，研究者还会在午夜睡前点火，完全不可预测（`00:18:15–00:22:09`）。后果是 Daytona 的平均利用率只有 15%（峰值 90%），必须让这类客户锁定承诺容量来保峰值；Neon、Parallel 等同行在最近的计算大会上确认了同样的痛点——"这种振幅在人类计算时代从未出现过"。缓解思路也有限：Cloudflare 式的跨地域腾挪只对 follow-the-sun 有效；对 RL 负载，真正的约束是"GPU 不能等"——推理 GPU 满转的成本远高于 CPU，CPU 侧环境准备必须瞬时完成，否则等于让昂贵的 GPU 队列空转，而即时向其他云租机器的"just-in-time compute"省钱但太慢（`00:22:09–00:27:43`）。

对 RL 客户为什么弃 EKS/GKE 而来，他的答案有三层：人体工学（API/SDK 的消费体验更像 Twilio/Stripe 而非 AWS）、速度与规模、以及"几乎无法 OOM"——CPU/内存可以在飞行中动态 resize。底座是 Sysbox 加固的 Docker（容器形态、VM 级隔离），支持 Docker-in-Docker 和沙箱内起 K3s，解锁了大量训练类工作流；快照用声明式镜像构建器现场生成再传播（`00:28:05–00:31:29`）。

### Computer Use：十万亿 TAM 与 Apple 的许可证墙

公司最大的未公开押注是 computer use。他的 TAM 推演：美国约 1 亿知识工作者、全球 10 亿，薪酬总额 10 万亿/50 万亿美元；医疗、政府、金融五大行业占一半以上，而这些工作大量锁死在遗留 Windows 应用里，没有企业会重写它们。RPA 时代自动化了其中约四分之一，更聪明的 Agent 若能做到 40%，就是每年 10 万亿美元的市场——"那是模型的 TAM，不是我们的，但要解锁它就必须给 Agent 配真的电脑"。现状是 Windows 沙箱只有 EC2/Azure 可选，启动要 3–5 分钟；Daytona 做到了秒级，且带快照与分叉（`00:33:31–00:36:06`）。他自己的实践很有说服力：做董事会报表时先接 ClickHouse/PostHog/QuickBooks 的 API 给 Claude Code，数据总缺一角；最后他给一台 Mac Mini 装上 OpenClaw、配只读账号"当实习生"，让它直接登录各服务网页导出数据端到端完成——"连我们这种用最热工具的初创都需要 computer use，Goldman 怎么可能做到纯 headless"（`00:36:45–00:38:22`）。

macOS 侧则是 Apple 的许可证地狱：每台物理机最多两个并行 VM、许可证 24 小时才能换一个用户（按秒计费的商业模式直接被废掉）、且内存快照只允许留在同一台物理机上——无法跨机迁移做负载均衡。"从安全角度我理解，但它让可扩展的 Agent 工作负载没法做"；他的判断是实验室会为了 RL 硬着头皮用，而"Apple 正在亲手放弃一笔可观的 compute 授权收入"（`00:38:39–00:41:26`）。

### 生态观察、开源策略与刺耳的热点

对生态趋势的几个一手观察值得记录：CLI 比 MCP 给 Agent 的能力强——MCP 是对 API 的接口，CLI 是真的能在沙箱里跑脚本做分析（类比 agentic search 之于 RAG）；Anthropic 的 Agent SDK/Claude Code 让大量应用层 Agent 公司"用 Claude Code 塞进沙箱就开张"，间接拉动了沙箱需求（`00:44:50–00:46:29`）。GitHub 正被 Agent 用错位：它是内循环（笔记本上）之后的外循环工具，而 Agent 把它当沙箱内的版本控制用——有客户干脆把整个代码库周期性 dump 成 JSON 推上 S3 当版本控制，"如果人们这么干，说明这个问题需要新解法"；另一侧 CI 成了新瓶颈，有客户一天 1000 个 PR 在队列里排着（`00:53:11–00:57:45`）。开源策略上他们选了 AGPL 3 加企业功能开关，Ivan 坦言开源对增长的直接拉动有限，真正的价值意外出现在 Agent 集成时——"你可以把代码仓库直接喂给你的 Agent，它因此更懂上下文"（`00:49:15–00:52:37`）。

热点观点部分火力全开：转售 token 的 AI SaaS 正被市场给予不该有的溢价——"那不是旧收入的重新加速，利润率更差，而且 Agent 给你的数据仍然是孤岛"；正确姿势是 Benioff 刚做的——把 Salesforce 全部产品 API 化、按消费收费（`01:04:11–01:07:05`）。对"AI 云长什么样"，他的回答是"会更像 Stripe 而不是 AWS"：一个为 Agent 专建的云，沙箱、网络搜索、SQLite/Neon 式数据库都是它的原语，"而 Agent 的基础设施原语远没有到头，我们手里还有没时间做的想法"（`01:09:48–01:13:07`）。至于增长——整个 Agent 基础设施市场都在以约 40% 的月环比增长，"如果你没涨 40%，那不是你的问题，是市场本身；半开玩笑地说，你都不用来上班了"（`01:09:48`）。创业观则苦行僧式：25 人团队里 13 人共事超过七年、约 1000 个 Slack Connect 频道、客户要求五分钟上 huddle；在克罗地亚与旧金山之间两头飞，"一切都必须疼——你得享受这种疼，享受不了就别干"（`00:58:26–01:03:21`）。
