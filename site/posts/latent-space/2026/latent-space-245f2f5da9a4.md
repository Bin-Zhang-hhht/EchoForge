## 速读

Supabase 为何成了 Agent 时代的默认后端：Compute 让长时任务与数据库同网络，OrioleDB 全面 beta、Multigres 开源并收购 Turso 冲向“每月数十亿数据库”，再用声明式 schema 服务编码代理；两位创始人还谈 PLG 天花板被 AI 抬高、企业几乎从不迁移数据库与每月 30 万美元的 AI 编码开销。

这期录制于 Supabase Select 大会前、发布于大会后。主持人 swyx 六年前种下自己第一笔天使投资，如今把 Supabase 的势头概括为“六年估值从零到 100 亿美元、几乎成了托管 Postgres 的标准”，并称这是两位联合创始人首次共同接受的访谈（`00:00:35`–`00:01:04`，`00:05:07`–`00:05:20`）。他反复强调的一个判断是：这些改造其实不只是为 Agent，“我们一直就需要”，人类同样受益（`00:03:28`–`00:03:35`）。正文中所有规模、转化与开销数字均为当事人在节目中的说法；sharding 尚未发布，HTAP 与迁移议题上嘉宾保留了明确怀疑。适合正在为 Agent 应用选后端、做数据库产品或研究 AEO 的工程师与创始人。

## 主题正文

### Select 三连发：Compute、OrioleDB 与 Multigres

开场直接进头条：Supabase Compute 源于社区多年抱怨——Edge Functions 基于 Deno、只有约两秒的时长限制，大家想跑更长的任务（比如 embedding 分块）。新发布的长时、serverless 完整容器跑在与数据库同一私网里、可直接建 Postgres 连接，Rust、Python 都行，也能把 Agent 放进去跑；嘉宾把它类比成“容器版的 Lambda”（`00:06:21`–`00:07:26`）。开场导读里 swyx 补充了两个视角：不依赖 Docker 启动 Supabase 是给编码代理减重，而 Compute 与数据库同址“被严重低估”，应用再配一个 Supabase 库出的 MCP server 会非常顺（`00:02:04`–`00:02:30`）。

OrioleDB 被定位为现有 Postgres 存储引擎 Heap 的即插即用替代，宣称快 1.5–2 倍且其他一切不用改，还顺带免掉 vacuum、膨胀这类后台任务；过去一年做的是“过筛子”：全量 Postgres 兼容性测试、Antithesis、TPC-C 每晚基准与 Jepsen（逐字稿记音 pgregress、Jepson），目标是“基本不可能丢数据”；发布时改为 Apache 2 授权并附带专利授权——技术是买来的，专利是自费的，现在免费送出（`00:07:56`–`00:08:48`）。这些性能与兼容说法均为嘉宾口径。

Multigres 的起因更扎心：嘉宾团队测遍了 Postgres 生态里负责多节点、failover、备份的各类 operator，结论是“某些条件下每一家都可能丢数据”——主持人对此表示难以释怀。于是他们从零重写，最初目标是给社区做 sharding，做完发现成了“一套完整操作系统”：1000 次连续 failover 未丢数据，发布时完全开源、平台上以邀请制开放给跑严肃负载的客户（`00:08:48`–`00:10:24`）。Vitess 原作者（逐字稿记音 Suku）这次把头号目标定为兼容性优先——sharding 上线时“你的代码零改动”；sharding 本身尚未发布，部分设计预计明年年初落地，研发周期约一年（`00:10:33`–`00:11:38`）。主持人称这是“Postgres 全面统治的最后一环”，并提醒 Vitess 支撑着 YouTube、GitHub；设计伙伴名单里有 Booz Allen、Postman、Perplexity（`00:11:46`–`00:12:32`）。

swyx 在导读里把大会归纳为 build、operate、scale 三主题；operate 那部分是“给更多上下文”：更多日志、检查、连接、SQL 的 markdown 文件、知识与 skills，加上自家第一方 ETL（Stripe 等来源接入）——他认为通用 ETL 问题正随 AI 工程生涯变成数据工程栈的一部分（`00:01:37`–`00:01:47`，`00:03:45`–`00:04:24`）。声明式 schema 则被单独点名：比起“建库然后 migrate、migrate、migrate”的传统范式，一切进 Git 当唯一事实源，Agent 才能爬取、fork、自行搭建（`00:02:41`–`00:03:15`）。

### 收购 Turso：为“每月数十亿数据库”准备 scale out

嘉宾给出的底盘数字：平台目前每月新启动约 500 万个数据库，而他们判断终局是每月数十亿（`00:12:44`–`00:12:59`）。为此他们宣布收购“agentic 数据库”做得最好的 Turso（`00:12:59`–`00:13:24`）。技术逻辑：SQLite 本质是单写者的文件格式，Turso 为它造了 MVCC 以支持多写者，并因 SQLite 授权问题分叉出 Libsql（`00:13:40`–`00:14:09`）。行业背景也随之点出：对象存储的新特性正在让它变得“可以当数据库用”——11 个 9 的耐久性（他们特意区分：是 durability，不是 reliability）、相当于给你垫了一层“集群底座”（`00:14:16`–`00:14:51`）；但事务负载不适合放到对象存储上大规模跑，那是 Multigres 的活，数十亿小数据库要的恰恰是“一个文件格式”，这正是 SQLite 有趣的地方（`00:15:02`–`00:15:20`）。Turso 的 Glauber（逐字稿记音 Glover）发布的博客给出了用其文件格式实现 Postgres 兼容的路径：Turso 品牌保留、继续专注 SQLite，Supabase 侧则推出更小的实例类型 Supabase Spark，兼容全部现有库——从一个想法一个库开始，起量后一路升级到完整 Postgres 直至 Multigres（`00:15:33`–`00:16:14`）。

主持人补充的用户侧观察：这些数据库其实都很小、都是 vibe coded 的小应用，但“上了 Hacker News 首页之后你得能撑住”，所以后端之间的零停机迁移是必需品（`00:16:45`–`00:17:01`）。嘉宾举的典型客户是非技术 builder：Magic School 的创始人本是老师，看到教学里大量可自动化的低效环节后直接开公司——“没有技术联合创始人、没有 CTO 的创业已经不再是孤例”；过去 18 个月的增长“疯狂”，而更大的“消费者级 builder”市场还在后面，“如果人人一个专属 Postgres 集群，全世界的物理计算机都不够用”，算力容量确实成了今年要正面应对的问题（`00:17:12`–`00:18:26`）。具体应对是更紧密地与云厂商规划、加价、合作，以及新增投资伙伴 CapitalG——借 Alphabet 生态走向多云（GCP 是显然的选择），并加深与 Gemini 等产品的嵌入（`00:26:12`–`00:27:04`）。节目里还顺带聊了两句存储创新：S3 三年前免费开放的强一致、后来的 S3 Express（1–2 毫秒写入、可当“临时持久层”，后台再落 S3），“你还需要 Redis 吗？——要，还远不够快”（`00:27:25`–`00:28:28`）；期间有人提到 DigitalOcean 股价一年三倍、市值约 160 亿美元（节目内说法）（`00:25:54`–`00:26:04`）。

### 从“real-time Postgres”到“开源 Firebase 替代品”：launch 史与 Hacker News

发射日的故事值得整段复述：HN 帖子是别人代发的、当时他们还没准备好；同一天他们把 tagline 从“real-time Postgres”改成“open source Firebase alternative”——因为创始人当年在上一家公司做过 Firebase→Postgres 迁移、为实时功能自建了实时引擎，深知“Firebase 替代品”才是别人听得懂的话；“real-time Postgres”没人理会，改名后约 12 小时帖子就上了，如今仍是 HN 全站历史第一（节目内说法）（`00:22:59`–`00:23:57`）。当时的架构是 DigitalOcean 上两个每月 5 美元的 droplet（一个跑库、一个跑 API，为了独立升级），全站只有 8 个用户；那次发射从 8 涨到 800，1 万美元的 DigitalOcean 学分 48 小时烧光，靠 AWS 给 YC 公司的 15 万美元学分才接住——于是 YC 的第一周全在迁移 800 个数据库（`00:23:57`–`00:24:54`）。两位创始人至今认为 DigitalOcean 因“太严格”（1 万美元计划用完就不肯给 30 万那档）错过了日后最大的客户，但也承认 COVID 当口情有可原（`00:24:58`–`00:25:45`）。

与 Hacker News 的相处之道自成一段：早期增长大多来自 HN，“必须一直泡在上面”；他们被 Dang（HN 运营，逐字稿记音 Dan G）多次告诫“一周内发布太多东西”，也理解他要保护 HN 与 YC 互不捆绑的独立性；某次 launch week 每个发布都上了首页，因为发推炫耀被严厉警告——给所有人的建议是“永远别截图自己上了 HN 首页”，而且“说实话那确实是在炫耀”（`00:20:57`–`00:22:40`）。营销侧的低成本神话同样有细节：他们几乎不花营销预算、主要靠 meme（`00:32:38`–`00:32:47`）；2022 年有人写过 4 万字长文拆解他们的 meme 策略，团队发现“对方把我们没写下来的策略写了出来”，直接拿来当市场新人的入职材料（`00:20:05`–`00:20:26`）；每周开 meme workshop，而且这类人极难招——“既要懂技术，又要懂开发者觉得什么好笑”（`00:19:04`–`00:19:20`）。swyx 还打趣 Turso 的 Glauber 也是 meme 高手，嘉宾开玩笑要给他 Supabase 推特账号的权限（`00:18:26`–`00:19:04`）。

### AI 三章、变现速度与被模型点名

嘉宾把 Supabase 的 AI 之路分成三章。第一章是 embeddings：各家向量数据库扎堆发布时，他们借独立开发者 Andrew Kane 的扩展推“Postgres 可以当向量库”、做市场教育，成了重要的增长引擎，也利好 Postgres 生态（`00:30:47`–`00:31:30`）；他还点名 Turbopuffer 借鉴了 Turso 的创新、是这类做法的出色用例（`00:31:40`–`00:31:49`）。第二章是 2024 年底的 vibe coding 浪潮（Lovable、Bolt 等，逐字稿记音 Bold）：团队内部大辩过“要不要服务这批人、要不要自己做 vibe coding 平台”，最终按“存下全世界的资料”的使命决定服务，并选择相信工具会越来越好（`00:31:49`–`00:32:24`）。第三章是今年年初：模型变好，注册漏斗开始暴涨，而他们“几乎不花营销费用”（`00:32:24`–`00:32:47`）。反直觉的是：消费级流量涌进来时激活率与付费转化通常会被稀释，这次两项都涨了——注册到激活由 Agent 一步完成、近乎 100%，且这批用户的付费转化率高于传统开发者用户（`00:32:57`–`00:33:38`）。

变现速度的变化被反复强调：以前是“选库、做产品、再接计费”，现在 Agent 层接上 Stripe，客户当周就有像样收入；决定 all-in 的触发点是看到有人的产品上线几天就赚了 1 万美元——“这回是真需求”。对照 NFT 波（只顺手做了 Ethereum/Solana 登录、没敢投入）可以看清判断标准（`00:29:05`–`00:30:15`）。同期公司把两件事并行：往下做原型场景、往上做更大的客户，因为当时最大的客户已经在撑爆他们的上限（`00:30:15`–`00:30:37`）。今年定下的激进收入目标也被提及：“有人担心达不到，结果四个月就完成了，从今年年初起的增长曲线简直离谱”（`00:57:43`–`00:57:58`）。

AEO 一节由主持人现场出题：他的 AEO tracker 显示，所有前沿模型都把 Supabase 列为 integrated backend（auth、functions、数据库、API 一体）的首选（`00:33:47`–`00:34:04`）。嘉宾的归因有两层：其一，LLM 爆发前他们已在市场里站了三四年、且一直以“当红品类的开源替代品”姿态出现——“时机完全是意外，不可能更好了”（`00:34:04`–`00:34:30`）；其二，他们今天也重度投入 AEO——同场对比了 Resend 的做法（swyx 追问“为什么我的 LLM 老推荐 Resend”，答案是大量优质 AEO 实践）（`00:34:34`–`00:34:54`）。更底层的原因是社区多年产出的“我怎么用 Supabase 做了这个”博客、视频、播客“都被模型吸收了”，开源本身也加分（`00:34:54`–`00:35:25`）。

社区运营有两件实事。一是众筹改“送股”：去年 Select 宣布众筹后，律师说想引入大量非合格投资人没有合规机制，直到他们问出“那我们不卖、直接送股票呢”才打开口子；现已预留约 100 万美元等值股票分给社区成员，首位是 Discord 传奇 Gary（Discord 名 Gary Austin、本名 Gary Abbott）：六年答了 2 万个问题、其中 1.3 万个在一小时内回复，退休人士、用 Supabase 给自己做红酒侍酒应用、圣诞树上挂 Supabase logo（`00:35:33`–`00:37:30`）。二是平台选择：Discord/Slack/Reddit 之争的结论是“Discord 用户用 Discord、Reddit 用户用 Reddit，全都要做——用户在哪我们就在哪”（`00:38:03`–`00:38:24`）；再把问答爬进 GitHub Discussions、镜像到官网，等于“把 GitHub 当 CMS”，因为“大家问的其实是同一批问题”，每次 surface 一下即可（`00:38:52`–`00:39:26`）。

### 企业侧：product-led sales 与“几乎没人迁移数据库”

先是一个反差事实：开源版里刻意不放任何埋点，所以他们“不知道自己的开源市场占有率”，倒有大药企主动找上门——“我们跑了 100 个实例，能不能卖我们点东西”（`00:39:42`–`00:39:58`）。Control Tower 就是为这类企业准备的“机队视图”：明天发布、官网还看不到，本质是把服务 AI 平台客户的 Supabase for platforms（2025 年 12 月上线、为这些公司每月启动数百万数据库）重新打包给单个企业，让企业为内部员工批量开库并统一管理（`00:40:10`–`00:41:21`）。

销售打法是 PLG 基因的延伸。嘉宾自称“每期 YC 批次有 60% 的公司在用 Supabase”（当事人说法），对标本是 Stripe——“唯一穿越十多年市场迁移还保住开发者热爱的开发者工具”（`00:41:27`–`00:42:01`）。具体机制是产品触发式销售：每周约 1000 个 product triggers（重要 logo、接近限额、报错、付费档位等），发 1000 封邮件、约 500 人回复；不回复者当对照组，其自然增长约 25% 月环比；对回复者，销售只被要求“上门帮忙”，这批账户增长 125%——平台自然增长之外的 100% 增量就是销售的提成基数（`00:42:01`–`00:43:35`）。

迁移议题上的立场非常明确：企业来找他们几乎都是开新库，“几乎从不”迁移生产库；他们的核心论题从第一天起就是“所有押注迁移的数据库公司最终都失败了”，正确姿势是 day one 进入、陪到 day 1000、day 10000（`00:43:35`–`00:44:30`）。未来五年企业侧重心是 greenfield——如今企业内部“让所有产品人放开创新”本身就是海量新库场景；Multigres 是“万一要迁移”时的选项，但“至少未来五年不会是核心”（`00:44:30`–`00:45:30`）。新变化是 CPO 级 champion 的自然出现：有 CPO 十年没写代码，如今靠 Lovable+Supabase 在公司内部搞建设（`00:45:41`–`00:46:08`）。被问“Lovable 和 Supabase 谁更黏”时，嘉宾的答案很实在：跑数据库太难、迁库又比换前端工具难，黏性自然在数据库侧；他同时表扬 Lovable 是第一家写出高质量 skills 防止 agent 乱来的——早期 agent 会往 Postgres 里塞图片数据、为跑通项目直接关掉 RLS，“Lovable 先解决了，这就是秘方”；如今模型自身也不再这么干（`00:46:22`–`00:47:17`）。

### 迁移为什么难：OLTP、HTAP 与 sharding 路线

“你们不只是替代 Firebase，还是 Amazon 的新 RDS”——这是 swyx 转述一位 Supabase 董事会成员的论断（人名记音无法核实，正文不具名）（`00:47:38`–`00:47:56`）。至于“迁出 Oracle”的白鲸叙事，嘉宾引述的听来数据是：约一年前按收入算只有约 5% 的 Oracle 工作负载跑在云上，人人都在喊“ rip out Oracle”（`00:48:14`–`00:48:35`）；但他对迁移战略泼了冷水：让 Oracle 黏住的是上百万行的存储过程——不过如今重写它们大概容易多了（`00:49:00`–`00:49:31`）。真正难的从来不是重写：OLTP 库撑着最赚钱的应用，一分钟停机就是真金白银；双跑又容易闹 split brain、调和极难，所以多数人最后选择把新负载开在新库上、寄望日后迁过去——“那样你就有两个问题了”（`00:49:31`–`00:50:19`）。

HTAP 方向，swyx 提到 Databricks 两位联合创始人（逐字稿记音 Matei 与 Reynolds）来节目时宣称解决了 HTAP——数据库人的白鲸（`00:50:28`–`00:50:48`）。嘉宾的回应是对 DuckDB/Duck Lake 感兴趣——“分析界的 SQLite”、列存、可直读对象存储、也能读 Postgres，像“分析生态里的 Postgres：努力让谁都不拥有它”，团队远在荷兰（`00:50:56`–`00:52:00`）；但立场是“用对的技术做对的活”：HTAP 恶龙被屠了多年，对象存储也许有戏，可 OLTP 到了一定体量就得 sharding——NVMe 有上限，跨机事务迟早要碰对象存储、最终拖慢数据库，所以“sharding 是通向 PB 的正道，分析另走一路”，把两者硬捏在一起“在我看来没什么道理”（`00:52:00`–`00:52:56`）。持久化工作流（Temporal 世界）的答案也落在 Compute 上：社区曾试图在 Supabase functions 上搭工作流引擎、败于两秒超时，“我们缺的那块就是 Compute”，如今原语补上了（`00:53:36`–`00:54:28`）。

### Code-first、Git native：为 Agent 重排 Postgres 体验

嘉宾的“水晶球问题”是两个：开发会怎么被做、人们会开发什么（`00:58:07`–`00:58:20`）。路径在他口中已经清晰：Supabase 起家是 dashboard 公司（当时最好的 DX），而 API 驱动的 headless 形态第一天就有——这也是它能成功的原因之一；今年的重心是 code first、Git native——本地启动时生成 Supabase 文件夹，以虚拟文件系统表达整个数据库，“就是基础设施即代码”（`00:58:28`–`00:59:14`）。压轴的是声明式 schema 的收官改造：把 schemas 文件夹变成数据库的完全声明式状态——表、策略、数据库注释全在文件里，并发布可用于任何 Postgres 库的新库 pgdelta（`00:59:14`–`01:00:15`）。理由是给 Agent 的：传统 migrations 文件夹是历史日志，让 Agent 穿越上千个文件去猜“这张表长什么样”，等于让它重新编译；声明式文件让它直接在文件系统上快速迭代——“Agent 主要在代码上作业，不想伸手碰别的东西”（`00:59:32`–`01:00:46`）。

他自己的体感是在手机上开发已经顺畅（当然，他知道背后该配哪些基础设施）；再往前想象，“对手机说一句 I want to build X，一秒后应用就上线”的世界里，该备好什么用例、怎么保证自己是那个世界的默认供应商（`01:00:46`–`01:01:22`）。配合这条路的还有实验室联盟：P1 是尽可能多地与前沿实验室和模型合作、把 attach rate 做上去，争取在模型 artifact 场景里当默认提供方——过去卡在承载不了对方规模，“ChatGPT 12 亿月活、每人每月启一个库，就是 12 亿台 Postgres 服务器”；公司 P0 则是“赢下战略实验室与模型、继续 PLG、在企业侧赢新负载”（`00:54:28`–`00:56:38`）。PLG 的天花板也被 AI 抬高了：创业时估计 PLG 能做到 1 亿、顶多 2 亿美元就得换打法，如今“天花板不知道被抬到哪里去了”（`00:56:38`–`00:57:02`）。swyx 的担忧是 mode collapse：agent 会不会收敛到唯一一种写软件的方式、连那些著名的工程界圣战都消失了；嘉宾的回应是“怕也没用，不在你控制内”——随便玩玩的大众会收敛到均值（“也就是你们”），讲究的高手仍会在意细节、并最终自上而下过滤下来（`01:01:54`–`01:03:17`）。

### 开源未来与 AI 编码开销

收尾前的两段起源故事：三位当事人当年同在新加坡 Entrepreneur First，结业后合住一栋七人全是 builder 的房子，发现“技术人配技术人”做开发者工具效率远高于加速器推崇的技术配行业专家的组合，后来把半个屋子的人都雇了进来（`01:05:12`–`01:06:12`）；YC 时期导师劝“拿了钱别雇人”，他们坚持要雇 Postgrest 首位维护者 Steve Chavez，YC 合伙人的反应是“忘掉建议，马上雇”，入职后的安排是“别管 Supabase，专心把 Postgrest 做到极致”（`01:06:29`–`01:07:30`）。

商业开源的未来，swyx 的提问是“slop 泛滥，而且依赖正在被 vibe coding 变成可选项——想 vibe code 什么就写什么”。嘉宾的答案是 Rust 重写是有效机制：重写会分层发生，多数工具最终会坍缩进“更快、更正确”的语言，然后出现少数赢家——Postgrest 用 Haskell 写的、难维护，若重写大概会有一个 Rust fork 胜出；基础设施侧 Elixir/Beam 又是另一番考量；Vercel 的 Malte（逐字稿记音 Malta）“出钱把 C/C++ 依赖重写成 Rust”的提议他们“100% 支持”，但也预判不会发生——“人们太爱自己动手了”（`01:07:41`–`01:10:28`）。

内部 AI 编码政策则高度去中心化：公司“像一串初创粘在一起”，auth 等各产品线自选工具、自定规范，只在成本上开始收敛（`01:10:47`–`01:11:34`）。swyx 想给公司管理者一个市场基准：普通人每月约 20 美元、员工约 200 美元、OpenAI 的第 50 百分位每月 3000–5000 美元、头部是数十万美元；他给的指标是 token 支出/人力支出之比——0.1 常见、到 1 都算安全、超过 1.5 大概有麻烦（`01:11:34`–`01:12:23`）。Supabase 自己的数字（远程公司万事皆文档，直接问自家 AI）：每月约 30 万美元、约 450 人（`01:12:23`–`01:12:43`）。他们还强调焦点不应是“花了多少钱”，而是“多少端到端流程不再需要人在环”；内部用排行榜让落后者害臊，同时把全量文档史喂给“公司 harness”——让 AI 从整个公司历史里整理决策原则（`01:13:22`–`01:14:11`）。招聘上：约 50 个开放岗位、全球远程同酬，最缺 SRE；筛选标准是“真心想在远程优先、全异步的环境里工作”，“这不是所有人都能适应的”；swyx 补刀自己一贯认为 AI SRE 是 agent 创业最难的品类，嘉宾认同“AI 还没攻下 SRE”（`01:14:19`–`01:16:03`）。
