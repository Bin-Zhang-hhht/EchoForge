## 速读

NeurIPS 现场的 Latent Space 特别节目，嘉宾是从 OpenAI 推理团队转到 Cursor（入职约三个月）的 RL 研究者 Ashvin Nair：伯克利 Sergey Levine 组的机器人学博士、2017 年在 OpenAI 实习、2022 年 9 月在 ChatGPT 发布前加入 Codex/CodeGen 团队，此后经历了 o1/o3 推理范式的全程。

最值得带走的三点：他对 RL 用于 LLM 的定性是"一个古怪的工具"——能把训练分布杀穿（IMO/IOI 金牌），却几乎不向分布外泛化，模型因此"很尖"：竞赛金牌与"只能当初级工程师"并存；对策不是等更好的算法，而是把经济上有效的任务拉进训练分布，这要求产品与模型协同设计——编码之所以先行，正因为它的全部上下文（代码库+终端）恰好能装进产品；以及在 Cursor 可见的另一种可能：Tab 每 2 小时一次策略更新的在线 RL，靠的是"产品的人坐在 ML 的人旁边"的组织形态。

## 主题正文

### 从机器人学到语言模型：一条越来越常见的路

开场先认门：Nair 的履历是"机器人 RL→语言模型"迁徙潮的标准样本——伯克利博士师从 Sergey Levine（2017–22），2017 年就在 OpenAI 实习过（那一年公司里只有 Dota、机器人加约 15 个暑期实习生）；2022 年 9 月、ChatGPT 发布前几个月正式加入，本想找个"清闲的研究实验室"喘口气，结果一切炸开了（`00:05:58–00:06:37`）。他加入的是发布过 Codex 的 CodeGen 团队——ChatGPT 团队的姊妹团队，做编程竞赛与工具使用。机器人背景为什么好迁移？他引用主持人转述的 Lex Fridman 饭局观察：机器人方向的人是 NeurIPS 上最好聊的，因为他们没法躲开真实世界；而"最脱离现实的是做仿真的人"。他自认两边都做过，补了一句冷判断：机器人恰恰是"最感受不到 AGI 的领域"（`00:00:25–00:02:43`）。

对 robotics 的热闹融资他也泼了冷水：Physical Intelligence 现场演示（在别人客厅叠衣服）确实让人眼前一亮，OpenAI 重启机器人团队"应该是认真的"，但他的个人判断是"LLM Agent 会先成为一个万亿美元市场，AI 机器人可能还不到百亿"——机器人此刻连"有用"都难证明，有用之后还要过单位经济与可靠性（维修）这两关；行业所处阶段大约是"GPT-1 到 GPT-2 之间"：偶尔能看到新场景下泛化的火花，但"此时投资机器人，投的不是技术，是团队"（`00:03:47–00:05:46`）。

### IOI 金牌本该意味着"收工"，为何什么都没变

这期节目的核心命题在他反复咀嚼的一个悖论里：当年如果告诉他模型能拿 IOI 金牌，"我会以为我们可以直接休假了——AI 已经解决，没必要再干了"。现实是拿到金牌之后"生活照旧"。他的两层解释：一是社区确实在持续移动门柱，而且某种程度上这是对的——大家会默契地涌向最重要的基准（SWE-bench Verified 被点名）；二是 AGI 的定义本身就坏掉了（`00:07:08–00:09:11`）。最锋利的表述是这组对照：世界上大多数程序员根本打不到 IOI 的水平，而我们仍然自动化不了大多数编程工作——模型的能力曲线因此长成一条"尖峰"：在 IOI 上飙升，在初级工程师水平上徘徊（`00:08:44–00:09:11`）。

这个"尖"字的根源，他把账算回了博士时代。2015 年 DQN 之后的 RL 热潮里，学术界最兴奋的是 off-policy 学习、价值函数这些方向——"不知为何没有成"，回看时他的结论很不留情面：整个社区严重过拟合了基准。"我们给自己发明了一堆新旋钮，然后潜移默化地把旋钮拧到拟合基准上去"——这不是某一篇论文的问题，是社区级的元问题；结果那个时代产出的大量 RL 研究"如今没怎么被用上"，随后就是 RL 寒冬：基于那些前提成立的创业公司或死或转（`00:09:11–00:10:38`）。更深一层是学术激励的病：学界奖励"更数学的想法"而非"简单有效的想法"，而数学的想法天然附带可过拟合的旋钮，真正有效的往往是没有秘密配方、只有"多堆算力"的笨办法（`00:10:52–00:11:45`）。

### RL 是个"尖峰工具"：把世界拉进分布里

由此他给出本期最重要的一组判断。第一，scaling 没有结束——各实验室的新预训练模型仍在明显变强，只是形式在变；媒体看到的是大起大落，大实验室内部的感觉是"匀速前进"，一堆结论不确定的实验堆叠着往前挪（`00:11:42–00:13:08`、`00:25:31–00:26:34`）。第二，RL 用于 LLM 的真实画像："一个有点古怪的工具，对训练分布之外的泛化非常有限——它能用不多的力气把训练分布彻底杀穿、做到世界最好，但它不往外长。"所以出路只有一条：把经济上有效的任务拉进训练分布。这立刻变成一个产品命题：编码是最好的第一步，因为它需要的上下文（代码库、终端）恰好能被一个产品完整承载；而其他职业的上下文"疯狂"——同事对话、Slack 消息（`00:12:17–00:13:32`）。他拿自己的旧工作举例：在 OpenAI 做超参数的 scaling 研究，一年里跑 sweep、看超参之间的相互作用、攒下满脑子的图——"模型要替代我，得把这些全放进上下文，而那些图只存在我脑子里"（`00:15:17–00:16:48`）。主持人提到的 GDPVal（白领取向、贴近原始文档的任务评测）在他看来正是"该有的形状"：不给清洗过的数据，给 PDF，让 Agent 上（`00:13:32–00:14:54`）。

第三，一个行业内幕式的观察："OpenAI 有按组织架构出货的倾向。"从 Codex 到 o 系再到 GPT-5 又拆出 5 Codex 的"合久必分"，与其说是科学结论，不如说是组织形态：特别在乎编码的团队没有数据把所有领域都做好——"如果数据全都有，一起训肯定更好，只是很难找到一个同时在乎所有事的组织"（`00:16:48–00:18:36`）。推理团队的人数也让主持人大吃一惊：约 300 人，而且自 o3 作为产品立项以来只多不少（`00:21:26–00:21:58`）。

### o1 到 o3：信念、demo 与"内部很平滑"

讲 o 系的起源，他把功劳记在 OpenAI 的"第一性原理式信念"文化上——尤其 Ilya Sutskever 与 Jakub Pachocki，血脉可以追到 2017 年的 Dota：那批人"骨子里相信 AGI"，长期确信 RL 是通往更强智能的路，缺的只是训练本身好起来（`00:22:06–00:23:52`）。RLHF 在这个叙事里只是支线——人类反馈灌不进多少算力，本质是把模型的性格调好一点（`00:23:16–00:23:34`）。决定性的内部原型很简单：在一个不大的模型上跑 RL，产生了非常新颖且准确的推理 trace，数学分数好得不可思议——不需要更多预训练就能拿到。看到这个，资源就开始全力灌入（`00:24:55–00:25:31`）。被问及"内部领先外界多久"，他给出的现状是一到两个月——竞争压力下没人敢让领先期拖长，Nano Banana Pro 就是例子：极好，但只领先一个月（`00:26:34–00:27:23`）。

对 DeepSeek 时刻他的回答是"内部毫无波澜"：OpenAI 当时本来就有更好的模型；真正让他们困惑的是市场反应——"DeepSeek 证明 NVIDIA 芯片比想象中更有用，结果 NVIDIA 股价大跌"。更实在的行业观察是收敛：各家实验室的 RL 做法已经殊途同归，大家又回到了同一条前沿线上（`00:30:36–00:32:27`）。还有一则关于预测文化的趣闻：o1 发布前他在 The Curve 大会看到人们下注"2027 年 Epoch AI 数学与 Humanity's Last Exam 到 10–20%"，而当时内部模型已经超过这些估计——同一批人还在预言 2035 年戴森球。他的总结是"短期太悲观、长期太乐观"，但他真心欣赏那个 EA 邻近的预测社区"提前登记观点"的习惯——2015–2020 年间他们的能力预测大体是对的（`00:28:04–00:30:22`）。访谈还短暂回到 2023 年感恩节的 OpenAI 宫斗：他在场、签了那封 95% 员工联署的信，理由是治理——"无论 AGI 是两年还是十年后，我们都没有一个好的治理结构"；事后他甚至觉得，一家利益相关者是"全世界养老金持有人"的上市公司董事会，可能比七个人组成的非营利董事会更民主（`00:18:45–00:21:23`）。

### 为什么是 Cursor：把测试分布装进训练分布

转向 Cursor 的动机，他讲得非常工程化。第一层是显而易见的：不必事事依赖外部实验室。第二层才是重点——既然 RL 尖而不广，理想做法就是"把整个测试分布装进训练分布"，而 Cursor 的产品恰好就是这个分布本身。他点了 Jacob Jackson 那篇关于 Tab 在线 RL 的博文：大约每两小时做一次策略更新。"这很难想象发生在 OpenAI——产品太复杂，而且产品的人和 RL 的人分属组织两端。"在 Cursor，产品的人就坐在 ML 的人旁边（`00:32:27–00:34:53`）。

至于他在 Cursor 的具体工作：只有 Composer。Cursor 的 ML 组约 20–25 人，主线就是"把 Composer 越做越好"。他对这个规模的产出感到惊喜——Composer 的受欢迎不只是分数，而是协同设计的雏形：它聪明到你想用它，又快到你能始终留在循环里；其他聪明模型都太慢，逼你切走再切回，"那对程序员来说太糟糕了"（`00:36:20–00:37:44`）。下一步的目标也因此清晰：现在模型擅长"回答用户提示"（Composer 1 已经很好），但他们真正想做的是让模型接管软件工程的整个流程——写代码、看 Datadog、形成假设、再跑一遍；"如果工程师工作的大部分内容都流经产品，我们就能用它在'不只写代码'上越做越好"（`00:38:02–00:39:09`）。工具与数据 side 也有一段内行话：Cursor 的内部工具很好，因为大家愿意随手 vibe code、测自己的东西——SSH 进真实用户环境看代码是否照跑；"ML 最大的经验就是贴近你的数据"，而做代码产品的人天然看得懂数据——他在 OpenAI 看到一道生物学问题就完全不知所云（`00:39:11–00:40:22`）。

### 持续学习与"权重即硬盘"

收尾的展望给了两个研究方向。一是持续学习：他把问题提得很朴素——人类看到一个错误就不会再犯（摸过炉子的人不是"过滤掉"这个行为，而是真心不想再摸），而模型哪怕在同一个上下文里也会重复同一个 bug；人类与模型之间隔着"几个数量级的数据效率"，他怀疑这个方向会在一年左右出范式级的进展，但不知道具体是什么（`00:34:54–00:36:19`、`00:40:58–00:41:29`）。关于容量，他的算法是：预训练消化了数万亿 token，部署中一年不过遭遇百万级 token，还有"一个 epoch 就够"的特性——把它压进权重不会撑爆容量（`00:41:29–00:42:17`）。二是更基础的科学问题：Jacob 在 Cursor 提过"神经网络的硬盘视图 vs CPU 视图"——权重到底在记忆，还是少数电路在做大量的功？他承认这类问题短期不产出、又缺算力的学术界也难推进，但"很想在某个时候回去做这些根本性的东西"（`00:42:21–00:43:51`）。

招聘环节的一条实用信息：Cursor 面试靠两天的 work trial（"更有代表性"）；他出的 RL 面试题是"为什么 off-policy RL 不稳定"——一听就知道你是不是 2017–22 那个时代过来的。招人最缺的方向是"代码的数据与奖励"（`00:43:55–00:44:54`）。
