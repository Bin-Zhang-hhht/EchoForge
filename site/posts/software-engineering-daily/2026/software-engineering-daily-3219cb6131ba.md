## 速读

Docker 总裁兼 COO Mark Cavage 这次带来的产品是 Docker Sandboxes：一条 `sbx run` 命令，给每个 Agent 一个秒级启动的专用 microVM。这期节目的价值在于它把"给 Agent 做隔离"讲成了一个威胁模型问题，而不是一个产品介绍：Agent 天然要下载依赖、写文件、联网，打破了容器十年来"不可变"的默认契约；防御的手段是确定性的边界——文件挂载白名单、网络代理与"假密钥"注入。

最值得细读的是两段：凭证代理的机制（真密钥永不进箱、代理在出箱时换真、回程清洗）及其明确的局限（Agent 仍能以你的身份调用服务，"转账这种事今天挡不住"）；以及 Mark 主动交代的"不防什么"——对数据语义的细粒度授权（哪个 Agent 能写哪个 Slack 频道）全行业都还没解决。公司数据与攻击归因均为受访者说法。

## 主题正文

### Agent 打破了容器的不可变契约，所以边界要重造

Mark 对产品逻辑的出发点是行业背景：开发者笔记本成了"地球上最多汁的攻击目标"，因为拿到钥匙就能借开源生态大规模分发恶意软件；过去六个月的供应链攻击，用他的话说几乎都是从拿到 GitHub Actions 或笔记本访问权、再拿凭证开始的。（`00:08:35–00:09:21`）

而容器生态十年前就定型在一个关键默认上：不可变。镜像从 A 点到 B 点，任何漂移都告警甚至直接杀掉重建。Agent 恰恰相反——Mark 的描述是"它要下载 17 个 Python 包、写一堆临时文件"，本质上必须变异环境。Docker Sandboxes（`sbx` 命令）的回答是保留 Docker 的人机工学（秒级启动、和容器一样的观感），但底层换成 microVM：模拟硬件、自带内核，而不是共享宿主内核的命名空间隔离。他承认 microVM 一词有营销成分，"本质还是虚拟机，只是内核由我们定、极度精简和快速"，最底层原语启动低于 100 毫秒，对外呈现是"减肥版 VM"。（`00:09:56–00:16:45`）

一个坦率的补充是攻防现状：对这一代模型，"让 Agent 做不该做的事"对他来说四分钟以内就能做到——所以思路不是让模型更可靠，而是用确定性边界包住非确定性。（`00:09:56–00:14:15`）

### 控制面三件套：文件、网络与"假密钥"代理

沙箱内部是完整 Linux 系统（可基于 Docker Hardened Images 或任意发行版），外围是三层控制。文件层面默认不挂载任何宿主资源，按需挂载项目或 worktree；网络层面由 L4 代理与 HTTP 代理强制执行允许/拒绝清单。（`00:17:04–00:20:01`）

凭证机制是全期最具体的设计：真密钥放在箱外的 OS 钥匙链/保险库，箱内只有一个"看起来像密钥的占位符"。Agent 每次调用 api.anthropic.com 之类服务时带上假 bearer token，外部代理拦截请求、换上真密钥发出，回程再把响应清洗后送回箱内——Mark 自嘲这是"健康意义上的中间人"。这样密钥在密码学意义上不可能被箱内进程读走或贴到 pastebin。（`00:35:16–00:37:20`）

但他紧接着给出了同样具体的局限：占位符仍然"有权限"，代理既然放行了调用，Agent 就能以你的身份做事——"如果它接管了你的银行凭证对应的会话，它没有你的钥匙，但转账这种事今天我们挡不住"。吊销凭证可以止住后续损害，已发生的损害仍在。这是对"沙箱=安全"最必要的祛魅。（`00:35:16–00:37:20`）

### 威胁模型：两进两出，以及明确"不防什么"

个人场景的威胁模型被压缩成两条：一是防 Agent 伤及宿主（经典入口是提示注入——他提到去年通过 Google 日历邀请投毒的案例），沙箱内的卖点是"可以放心开 YOLO 模式"，因为读钥匙、删文件系统这些事在边界外根本不可达；二是防数据外泄，靠网络与 HTTP 代理的确定性规则。企业场景叠加 AI 治理包：谁能用什么 Agent、能调哪些 MCP 工具、哪些数据类别永远不允许发往模型供应商，外加集中式可观测与审计。他还提到有安全人员在播客直播中持续尝试突破 SBX 而未成功（受访者口径）。（`00:26:45–00:31:42`）

同样重要的是"范围外"清单，Mark 说得很直白：对数据语义的细粒度授权——"允许这个 Agent 写这个 Slack 频道、给这些人、只能发这类数据"——是行业还没解决的问题，"我不认为有任何人解决了"；他自己的多工作区 Slack Agent 靠每周人工检查边界来兜底。他用一个 Reddit 案例说明失控的荒诞面（一个 OpenClaw 用户的 Agent 连续四个月买菜正常、上周突然买了 50 磅大蒜），并强调共同责任模型：沙箱给你一个有界的运行方式，但"你的 Agent 能碰什么"仍需你自己做常识判断。（`00:32:05–00:34:54`）

### 路线与组织实践：remocal、computer use 与"瑞士"立场

产品路线图的骨架：云端版本（面向突发、临时的程序化扩缩容，把启动进一步压向 100 毫秒级）、"remocal"——同一个沙箱契约在笔记本与云之间可携迁移；以及安全地约束 Agent 对宿主资源（麦克风、摄像头、本地文件）的 computer use 访问。他强调对开放模型的支持是重点投入，"开放模型的年份已经来了"。企业侧的深水区是治理：Agent 身份、与 SSO 和访问控制系统的对接、给上万人推广时的表达力更强的策略。（`00:20:29–00:25:22`，`00:42:26–00:46:03`）

开放性立场上，他把 Docker 定位成"瑞士"：任何模型、任何 harness、任何 Agent、任何操作系统、任何云。SBX 本身大量开源但并非 100%（核心 VM 暂未开源，理由包含竞争与"我们正在被 AI PR 淹没"），但对用户完全免费。Docker 内部把 dogfooding 推得很深：多数员工日常在沙箱里跑编码 Agent，CISO 乐见其成，内部 MCP 网关承载全公司工具调用，GitHub 触发器的自治 Agent 负责安全扫描与测试覆盖并自动开 issue 或发 PR——但合并仍保留人工评审，因为"我们的契约是确定性"。移动端"不在下个季度"，但被认定为大概率终将到来，只是形态会不同。（`00:25:22–00:26:24`，`00:37:20–00:41:56`，`00:46:25–00:47:38`）
