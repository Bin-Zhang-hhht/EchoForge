## 速读

New Relic 首席技术战略官 Nic Benders（在任 16 年）接受 SED 访谈（主持为 Lee Atchison），把可观测性划成四个时代：插桩 → 数据平台（NRDB）→ 智能 → 行动。他判断"智能时代可能已在走向终结"，下一个是行动时代——若能以机器时间尺度检测-响应-纠正，on-call 会变成像"K8s 节点消失自动重排 pod"一样无聊的自愈机制。

最值得记的是告警膨胀的根因重构（每次事故复盘结尾都是"再加告警"，几年跑下来"宇宙中一切都有告警"）与"AI for observability"对"observability for AI"的术语区分。文中多处为前瞻性判断，已标注。

## 主题正文

### 四个时代与 dashboard 的尽头

New Relic 的历程：插桩时代（从 Ruby 扩展到 Java、.NET、Python、浏览器、移动端）→ 数据平台时代（约 2013、2014 年推出 NRDB，所有数据入库、事后可交互式提问）→ 智能时代（数据多到"不知道该问什么"）。他预测智能时代"可能已经在走向终结"，行业需要进入"行动时代"。Dashboard 的本质未变：今天的 dashboard 更花哨，但与他在 90 年代用 Tcl/Tk 做的监控 dashboard 本质相同——区别只是从三四个图变成 300-400 个图。因果断言：造不出小到能看下系统一切的 widget → dashboard 加告警作为可观测性方式"已走到尽头"；这是公司约两年前的认识，并预计将席卷全行业。（`00:02:48–00:08:23`）

### 统计、机器学习与神经网络的三桶分类

他给"AI"做了三桶分类：纯统计/数学（基线偏离等，"this isn't AI, it's just math"）；机器学习（把参数换成超参数，两三年前很多所谓 MLOps/AI 功能属此类）；神经网络（因 transformers 架构等优化加大量资金才真正可用）。层级比较留有余地："也许五年后我们对神经网络的看法会不同"；好产品应三者兼用。当前的架构观点：基础模型 API 是"老板"，传统 ML 与统计工具应作为它可调用的工具。（`00:08:23–00:12:08`）

### LLM 与大规模系统理解

主持人示例的递进：静态阈值 80% → 每小时 50 条告警的噪声；ML 动态调阈值降噪；LLM 则试图回答"这个模式意味着什么"。NB 完全同意 LLM 的价值在"广度"——现状是 K8s 集群有数百节点、数千 pods，人不可能搜完。方法论因果链：不会把 PB 级数据 tokenize 喂给 LLM（调侃"不至于把 Anthropic 变得更富"）→ 先用成熟的统计方法找异常 → 把异常与时间范围送进推理系统问"哪些有趣"。前置条件是数据必须有结构——按时间组织加按空间组织（用户浏览器→服务→依赖→基础设施的图）。规模鸿沟：LLM 上下文是 10 万到百万 token 级，而数据世界是十亿级，必须降三个数量级才可处理——需要大量 MCP 工具。（`00:12:08–00:17:10`）

### 告警膨胀的根因与重新设计

告警疲劳至今仍是每个客户的头号问题；因果是复盘机制导致告警膨胀——每次事故复盘结尾都是"该为 X、Y、Z 加告警"，几年跑下来"宇宙中一切都有告警"。引述原同事的演讲：增加告警不会提升响应速度，反而训练用户"等一分钟看看会不会自愈"。智能化两层：通知人之前先判断告警严重性；审视告警设置本身（清理从不 actionable 的告警）。未来是对每个异常自动分流——可自动行动（回滚并通知）/需人处理/有趣但未过阈值（进累积器）。理想形态：用户只声明"最重要的信号"，系统自己走一遍并在故障前预警；他认为可观测性应叫 "understandability solution"——"没人想 observe，人想要 understand"。（`00:17:10–00:22:27`）

### toil 的重新定义与保留意见

云与 K8s 自愈成立的原因是那些问题已被清晰定义；剩下给 SRE 的是模糊问题（IP 耗尽、上游证书问题），永远不会写进 runbook。条件性断言：若靠写软件穷举所有故障情形，"一辈子也只能覆盖很小百分比"；推理系统具备模糊接口后，就能把问题分组到已知修法、对有趣但不关键的自动建单、只在真正紧急且不知如何处理时才 page 人。主持人的保留意见（与"减负"直觉相左）：toil 减少的同时系统更复杂，toil 总量最终可能持平甚至增加；NB 佐证：New Relic 的部署方式已好到"几乎认不出来"，但大家仍然辛苦——"我们就是做得更多"。（`00:22:27–00:26:25`）

### AI 对职业的影响与两个方向的区分

NB 不想对整体经济过分乐观：AI 不会减少工作但可能"移动"工作；类比 200 年前的工业革命——经济总量大增，但对被直接冲击的个人，"对他们来说结局并不好"。AI 改变的是"思考的层次"——高级语言、虚拟机、云的演进早已如此；这解放了大脑去装更大的架构模式。术语区分："AI for observability"（用 AI 做更好的可观测性产品）vs "observability for AI"（为构建非确定性 AI 系统的人服务，是全新工具链）。历史类比：云、Web、NoSQL 都曾要求重新定义"什么才重要"；正在与 OpenTelemetry 工作组协作开发 AI golden signals，让每个新框架"出生即被观测"。（`00:26:25–00:34:06`）

### 非确定性、幻觉与业务信号

AI 系统需要同一可观测性模型、不同触发器；有专属语言与指标——tokens、sentiment、judges、成本。幻觉监控示例：把问题喂给快而便宜的模型，抽样千分之一跑在更贵的模型上评判"这个回答好吗"——相当于给由"不可靠演员"组成的呼叫中心配 supervisor 模式。NB 明确：认为可观测性正在进入所有这些领域。最重要信号的回归：约 2000 年代初在创业公司时，墙角一台电视显示"每分钟销售额"——它不告诉你坏了什么，它告诉你是否达成业务目标；"做到这一点，其余一切都是诊断"。（`00:36:13–00:42:57`）

### 给新入行者的建议

现状判断（条件性）：现在是很难的入行时点——公司不愿冒险招人。建议：工作会有的，但"很可能要像 30 年前科技不火时那样跑现场、经营人脉"；花时间用新工具链构建软件、让工具解释它在做什么（类比《钻石年代》的"年轻女士的插图入门书"）；不要用 AI 写文章，要用 AI 在发送前读你写的东西——问哪些问题没回答；预期管理：新人不会再从汇编、编译器内部构建软件，"时代颠簸，我同情你们"。（`00:42:57–00:45:51`）
