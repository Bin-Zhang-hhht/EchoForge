## 速读

Grafana Labs 联合创始人 Anthony Woods 接受 SED 访谈（本期主持人为 Matt Merrill），讲 AI 原生可观测性的来龙去脉。最有趣的观点是：Grafana 的开源生态本身就是 AI 的"免费训练数据"——2500 万+ 用户写的博客、教程与公开 GitHub 仓库正是基础模型的训练语料，所以模型"开箱即懂 Grafana"，让他们无需训练昂贵的专有模型。

对做可观测性、或考虑让 AI 处理运维的人，这期值得听的三点：从"人看仪表盘"到"agent 消费数据"的转变；知识图谱（从遥测动态构建实体关系）而非静态 CMDB 作为根因追踪的基础；以及"信任但验证"——AI 会出错，图表仍是解释推理的最佳方式。文中数字与判断均为受访者口径。

## 主题正文

### 开源语料优势：模型开箱即懂 Grafana

Anthony 的自我介绍：Grafana Labs 有 3 位联合创始人，他驻澳大利亚珀斯，职业路径是系统/网络工程师转自动化工具转全职开发者；约 12 年前与 Raj Dutt 基于 Dutt 创建的开源项目 Grafana 创办了公司。软件运营的最大变化是"变化的速度"本身：微服务让更小团队更快行动，但后果是复杂分布式架构下"没有任何人知道系统整体如何协同"；可观测性把微服务这个"小黑盒"变成玻璃盒——"它们总会坏"，尤其在 AI 生成代码时代。（`00:02:00–00:06:23`）

AI 的转折点：他自述 18 个月前被问"AI 会如何影响运营"时答案是"我没看到什么有用的"，转折发生在 2024 年底一批新模型出现时。Grafana Assistant 的 MVP 由 2 人团队在一次季度黑客松中做出，效果好得惊人；问他们为什么有效，回答是"我不知道，它就是能行"。他的推断：Grafana 拥有 2500 万+ 用户，用户写的博客、教程与公开 GitHub 仓库（含 dashboard 与部署配置）正是 Anthropic/Google/OpenAI 基础模型的训练语料，因此模型开箱即懂 Grafana 及其用户意图——这给了他们竞争跳板：无需训练昂贵的专有模型，直接用基础模型加更紧密的产品集成。（`00:08:25–00:11:11`）

### 从"人看仪表盘"到"agent 消费数据"

Anthony 承认存在风险、不能"坐着祈祷"：Grafana 的声誉建立在 dashboard 与可视化上，但现在越来越多是 agent 而非人类在与数据交互（做查询、找洞察），"仪表盘本身变少了"。受访当周 GrafanaCON 发布 GCX 项目：统一命令行工具，专为让 agent 能访问 Grafana Cloud 服务与全部数据而设计。AI 需要"信任但验证"：它会出错，所以用户需要能看到"你如何得出这个结论"；"图表仍是解释推理的最佳方式"——Grafana Assistant 做调查时会解释"我看了这些数据、看到这个趋势/尖峰，所以追查了这个问题"。（`00:11:31–00:13:41`）

### 知识图谱：把关系交给 LLM

LLM 强在给足上下文时，但"垃圾进垃圾出"，需要内部用多种非 LLM 的 AI 实践保证数据质量。知识图谱从全部遥测构建实体关系图（应用 → pod → 节点 → 集群 → 区域）；LLM 看到延迟尖峰后可沿图追踪，发现"节点资源争用 → 吵闹邻居"这类根因。对比静态 CMDB："每次更新完就过时了"；图谱由实时摄入的数据动态生成，始终反映环境现状。数据策展是关键，OTel 的语义约定是公开信息、LLM 能据此理解数据含义。（`00:13:41–00:16:28`）

### Agentic 应用的可观测性

Anthony 把"agentic"视为新的软件设计框架（主机 → 单体 → 微服务 → agentic），"引入了理解上的新问题，但现有工具大部分够用"。要收集的新数据类型是 agent 对话内容——用于跑 evals（"你的回答是否正确"）、出问题时回溯"是什么输入导致它跑偏"。受访当周宣布 Grafana Cloud AI 可观测能力：在 OTel 之上收集遥测加对话等数据，当前关注点是可靠性、质量与成本（token 用量）——"不久后人们会开始想怎么少花 token 钱"。（`00:16:28–00:19:59`）

工具调用与普通 RPC 调用并无本质区别：要测"是否得到有效响应"、测延迟；SLO 是最简单的运营思路——关心的不是 CPU 用了 100%，而是用户得到的服务质量。Agentic 模型下的 trace 挑战：对话数据量常超过单个 span 能承载的内容，需借助补充数据存储；Grafana 用"大帐篷"哲学把 SQL 式数据库中的对话/上下文与传统 trace 数据拼接、在同一处可视化。（`00:19:59–00:22:36`）

### 内部实践：Assistant 与工程文化

Grafana 全公司授权"每个人都尽量用 AI"；Anthony 认为软件工程师角色正在变化——更少写代码、更多像产品经理，理解用户问题并描述给 agent。Grafana 的 bottom-up 文化（工程团队对路线图负责）让他们天然适应"mini 产品经理"角色。Grafana Assistant 用于内部事故调查"出奇地好"，"它并不总是对的"，但即使不对也能缩小排查面、排除若干可能，加速根因定位。"更吓人"的方向是 AI 从开发侧进入部署侧——"何时开始给 agent 钥匙，让它写完代码自己去部署？"（`00:22:36–00:25:40`）

### 让 Agent 部署：物理门禁与安全

主持人 Matt 明示不适："到了让我不舒服的地方。"Anthony 不认为离"agent 自主部署"很远，但人本就不该无条件信任 AI——"只要有机会犯错，它最终就会找到那个机会"。Grafana CI/CD 有"物理门禁"：限制爆炸半径（禁止全局性变更）；成本检查——CI 会拦截"将把开销提高 10 倍"的变更。门禁同时约束人与 agent，之后才可逐步放权；门禁成熟度是"组织成熟度问题"——人类动作慢可以承受，agent 动作极快、能快速犯很多错。正在自动化的小例子：小范围部署后由 Grafana Assistant 自动查"有没有新错误"，发现问题就自动开一个回滚 PR——但仍需人来审批 PR（"现在仍需要人在环里"）。他预测会有一批风险容忍度高的初创公司"放手让 agent 干"，"一些数据库会被删，但那没关系"。（`00:25:40–00:30:42`）

### SRE 角色与人才培养危机

当下 SRE 角色变大了（软件部署量增长太快），但剩给他们的是更难的问题：简单 toil 由 AI/agent 承担，SRE 转向诊断、可靠性策略、流程思考。Anthony 最怕的事是：简单工作正是给初级/新毕业生的"练手活"，从中学习系统如何运转；拿走这些机会，"10 年后可能发现没有具备所需技能的人——我不知道怎么解决这个"。主持人提议回归"学徒-工匠-大师"模式（software is craft），Anthony 回应这是可行但昂贵的路线、短期无直接价值，多数组织会指望"别人去培养人，自己继续用 agent"；开源是他看到的出路——年轻人贡献开源、社区负责带教。（`00:30:42–00:36:27`）

开源项目遭遇 AI 生成代码的挑战来自数量与质量两面："能跑通不代表是你愿意长期维护的代码"；AI 不在乎架构设计与代码一致性，维护成本工作增加。例子：有人提交 2 万行 AI 生成的 PR——"不会审的，太大了"；应拆成可审、可维护的小块，agent 必须适应协作心态。（`00:36:27–00:38:39`）

### 未来 2–3 年：AI 作为"第一响应者"

Anthony 的判断：AI 目前能做到"第一响应者"——SLO 燃烧触发告警时，在 Grafana Cloud 并行启动一次调查；on-call 工程师坐到电脑前时，可能已有初步结论或已排除大量可能。根因定位时间预期从"1 小时"降到"10 分钟"；"未来几年 60%–70% 的问题将在 on-call 人员到岗前被解决"（他的原话是"会有这样的预期"）。后续流程（SRE 的"不只是止血，而是修复问题"）依然重要。移动快 = 必然更快更频繁地破坏，"用速度换准确性"，因此更好可观测性的需求更明显。（`00:38:39–00:41:52`）

### Loki 架构升级与两大担忧

为适配 AI 查询场景，Loki（日志聚合系统）做了架构与性能改动：查询快 10 倍，且能减少需要扫描的数据量。技术细节他自谦"不确定自己是否像作者那样理解它"：Loki 原设计以成本效率为核心（不做索引、查询侧暴力扫描，为 grep 式排除的开发者用例优化）；新需求是"大海捞针"式分析查询（如事务 ID 过去 4 天内出现在哪），暴力扫 terabyte 级数据很慢；新方案类似 Bloom 过滤器，可快速判定哪些数据段需要看，把"拍字节"范围剪到"10 TB"；查询引擎并行化，作为云服务商靠统计复用（成千上万用户错峰）可租用千核级资源，某用户某秒可独占 1000 核。（`00:40:36–00:44:20`）

让他失眠的两大担忧：其一，当今 AI agent 多是黑盒，"没人知道它们在干什么，有时我们也不想（需要）知道"；从对话式到 agentic（让 AI 做事而非只回答问题）让系统可高速操作与变更，这吓到他。其二，问责问题——内部规则是合并代码的人对部署负责，他担心这种问责被侵蚀；"agent 与外部组织的 agent 互相对话时出事，谁来担责？"主持人回应会引出法律与合同问题，"最终还是要落到人——出事时找谁的脖子"；Anthony 半开玩笑：未来最赚钱的职业是"AI 替罪羊"，还有"AI 保险"。（`00:44:20–00:46:45`）

### 给听众的建议

Anthony 的强烈观点："不要去做一个 AI 解决方案，而要让 AI 成为解决方案的一部分"——AI 的价值在幕后、不显山露水时最大。类比互联网：曾经"everything internet-enabled"是卖点，现在只是理所当然的预期；AI 正处于同样的 hype 阶段，用户会越来越不在乎"AI"标签，只在乎"它是否好用、是否让我满意"。让 AI 融入现有工作流、"到用户所在的地方去"，加速他们正在做的事，而不是强迫他们改变。（`00:46:45–00:48:14`）
