## 速读

Cal.com 联合创始人 Peer Richelsen 做客 The Changelog，解释这家商业开源公司为什么自 2026 年 4 月 15 日起把运行在 app.cal.com 的商业版转入私有 fork：AI 把开源协作的两个支柱同时打掉了——维护者被 AI 生成的 PR 淹没，安全研究者被 AI 生成的漏洞报告淹没；而「开源因为更多人看代码所以更安全」的前提随之失效。社区版会以 Cal DIY（cal.diy）的名义继续存在。适合关注开源治理、供应链安全与 AI Agent 对协作模式冲击的读者。本文基于 ASR 转写整理，专名与归属以官方节目页核对为准。

## 主题正文

### 被淹没的开源维护

Peer 的出发点是 agent 时代协作信号失真：过去一千个贡献者意味着一千种观点，好 PR 和差 PR 一眼可辨；如今是一千个人用两三个编码助手，「最好的想法获胜」变成了「最好的大模型、或者最好的 prompt 获胜」。PR 看起来光鲜、测试齐全，剥开一层才发现连测试都是幻觉，代码里还有硬编码（`00:09:56`–`00:12:02`）。他观察到不少商业开源公司因此关闭外部 PR、只接受经过多轮面试的「担保人」提交（`00:12:02`–`00:12:35`），也提到 Adam Jacob 的 System Initiative 团队把遗产做成的开源但不接受 PR、只按 issue 贡献的 swamp.club 模式，以及 Mitchell Hashimoto 的 Ghostty——开源，但不开放贡献（`00:13:14`–`00:14:31`、`00:55:16`–`00:55:35`）。求职侧同样变形：有人编排十几个 agent 扫热门仓库、自动提交 PR 当求职简历，Cal.com 的 open PR 一度在 356 个上下（`00:19:47`–`00:21:17`）。

### 钟摆摆向另一端：开源不再天然更安全

Peer 说自己在今年一月之前一直坚称「开源比闭源更安全」，理由是存在真实的安全研究者报告文化；现在他认为这个文化已崩塌——发到 security@cal.com 的漏洞报告 99% 是 AI 生成的，其中约一半是幻觉，复现不出来或用错了 API（`00:23:22`–`00:24:47`）。与此同时，攻击门槛被拉平：过去挖漏洞要花 8–20 小时读代码，现在「会跑一条 shell 命令」就够；他转述 AI 工具已在 Firefox 报出 12 个 P0 级漏洞，React、Next.js 也被报出漏洞（`00:24:50`–`00:26:41`、`00:33:52`–`00:34:03`）。他由此给出这期最抓眼球的判断：多数开源仓库可能已被入侵，只是我们尚不知道（`00:27:00`–`00:27:08`）。他转述安全研究者的话称，开源仓库被攻破的难度比闭源低 5–10 倍——不是 10%–15%，是倍数级（`00:32:49`–`00:33:20`）；而且黑帽比白帽更快，因为 extortion 的激励就在眼前（`00:34:37`–`00:35:00`）。

### Cal.com 的答案：内部 fork + Cal DIY

具体动作：自 2026 年 4 月 15 日起，运行在 app.cal.com 的商业版本转私有，不再与公开仓库同源；社区版继续完全开源、可自托管，「理想情况下放在多重防火墙后面」（`00:31:52`–`00:32:30`）。他给同类公司的建议很具体：任何会碰数据库和加密的开源项目，把敏感路径重写后转私，前端组件之类留着无妨（`00:35:00`–`00:36:01`）。社区版将更名为 Cal DIY（cal.diy），标注「自担风险、非生产就绪」；他甚至论证了一种「安全靠分散」：自托管的小装机量让它不值得被攻击（`00:42:53`–`00:44:22`）。关系不切断——社区的好功能会被吸收并署名，自家的功能也会反哺社区版（`00:44:33`–`00:44:49`）。

他特别强调这不是商业决定：Cal.com 月增长约 7%–12%、现金充裕、投资人是「最开源友好的一批」，还是他们说服了董事会——「这对商业开源是核弹级的问题」（`00:45:08`–`00:46:00`）。许可走向也随之明确：社区版保持 AGPLv3、甚至可能改 MIT（因为官方不再商用它，它更像公共品）；原先 source-available 的商业组件直接转私有（`01:44:17`–`01:45:24`）。

### 更进一步的威胁模型与 GitHub 之问

Peer 还描述了一个更阴险的攻击面：攻击者会用 AI 扫描你的公开 PR 流，一旦识别出「这个 PR 在修一个漏洞」，就在修复发布前抢先用它并发勒索信——所以他的建议是修复先转私有做，最后以单个 squash 提交合并回去，「别给机器递路径」（`00:52:34`–`00:54:26`）。由此延伸到平台层面：第三方 Action 自动关闭未验证用户的 PR 只是权宜之计，反 slop 护栏应该是 GitHub 的一等公民（`00:59:36`–`01:00:12`）。两位主持人随后和 Peer 讨论了 GitHub 的处境：如果用户基数变成 agent，这将不是一个好生意；Mitchell Hashimoto 三月在 X 上给 GitHub 开的药方（转述：把「关键基础设施」定为北极星、关停 Copilot、收购 Cursor、推出 agentic 仓库托管、重估一半产品线）也被逐条过了一遍（`00:55:35`–`01:04:04`）。还有那条新界线：你的 Claude Code 为了修自己的依赖，完全可能自主跑到上游仓库开 PR——「那个 GitHub 用户一个字都没写过这个 PR」，甚至给 Cal.com 提交一个把产品变差的 PR 也并不违法（`01:13:07`–`01:15:59`）。

### 不卖 token 的生意反而健康

讨论的后半段聊到商业面。Cal.com 没有 AI 产品，意味着不烧 token、毛利率健康：ARR 刚过 700 万美元、目标每年 3 倍、随后冲击 1000 万（`01:17:41`–`01:18:04`、`01:32:29`–`01:33:14`）。Peer 对「1 美元的 AI 额度只卖几美分」的创业模式火力全开：这是 Uber 补贴时代的翻版，拿到大额融资才能玩下去（`01:17:54`–`01:19:00`、`01:20:10`–`01:21:13`）。他也承认 SaaS 正在经历「SaaS shock」——客户说「我们一个周末就能 vibe code 出你」，他的回应是：我们本来就是开源的，想省钱直接 fork 或自托管；但排程这东西连前 20% 都很难，他还留了一句玩笑——「能不 fork 一把梭出 cal.com 的那天，就是 AGI 实现」（`01:34:10`–`01:36:05`）。自托管侧的数字：Docker 镜像拉取超过 100 万次，但 99% 收入来自 SaaS（`01:38:29`–`01:39:16`、`00:48:21`–`00:48:30`）。节目录制中还有个应景的花絮：主持人的编码 agent 在节目进行中就把两人刚讨论的「改签日历」PR 交付了（`01:51:56`–`01:52:27`）。
