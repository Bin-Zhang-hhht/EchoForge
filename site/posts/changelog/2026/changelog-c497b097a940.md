## 速读

The Changelog 第 680 期（全长约 97 分钟）：主持人 Adam Stacoviak 对话设计师、数据可视化老手、前 GitHub Next 成员、如今在 Augment Code 设计 Intent 的 Amelia Wattenberger。核心论点：agent 把「项目的 70%」压进大约 10% 的时间，于是「最后 30%」（打磨、交付、真正完成）反而成了从未经历过的难关；随之而来的是开发者身份危机、工具链从 autocomplete 到 chat 到 CLI 再到 UI 的重新设计，以及以 workspace（而非聊天线程）为核心原语的重构。文章据此整理，专名与归属以官方节目页核对为准。

## 主题正文

### 被压缩的前 70% 与被放大的最后 30%

Amelia 用一条「0 到 1」的线性工作模型开场：过去每件事都要慢慢走完，现在一个足够好的 prompt 就能拿到「70% 的成品」，甚至 C、D、E 因为太容易而被顺手加进范围（`00:15:36`–`00:16:42`）。难点于是整体后移：把粗糙原型打磨成「经过深思熟虑、像样、行为可预期」的东西，比从前更费力——你从自动扶梯上下来，突然要重新慢下来，而这一步 agent 帮不了你（`00:16:58`–`00:17:22`）。她自称「基本上就是个原型设计师」，原型从不是终点，而是通往更好产品的探索方式；现在原型容易了，但「打磨和交付」成了新瓶颈，而这两件事恰恰是最难、最该珍惜的（`00:17:31`–`00:20:47`）。软件因此变成一种「囤积」：你舍不得扔掉那个 70%——哪怕它不完全是你想要的，因为从前这要花很长时间（`00:19:25`–`00:19:44`）。

### GitHub Next：Copilot 之前的世界

她 2021–2022 年加入 GitHub Next（Github 的研发团队，脱胎于 CTO 办公室，Jason Warner 离开前成立，约 15 人，由资深产品工程师和研究员组成，按兴趣组队探索「什么才是下一件事」），在 Copilot 发布前加入并参与了上线（`00:06:15`–`00:11:41`）。Copilot 起初被当成「更好的自动补全」，两天后人们才意识到它本质不同；她也记录了当年围绕「拿开源代码训练模型」的巨大内部与外部反弹（`00:08:25`–`00:09:54`）。她在 GitHub Next 的早期项目之一叫 Copilot for Docs（Dock Pilot）：一种早期 RAG 探索，索引开源代码库后让开发者以「我是这类人、擅长这些、不擅长那些」的方式提问；未来方向是让文档自动从代码生成、由维护者按需补答，让开源「发布后基本不用维护」（`00:22:12`–`00:24:58`）。她也谈过 GitHub Actions 的设计：把工作流配置文件放进代码库、把「平台」与「runner」分离，是她欣赏的设计（`00:12:31`–`00:13:52`）。

### 回到 UI：为什么 workspace 是原语

她把工具演进画成弧线：autocomplete → chat（ChatGPT 后问 LLM）→ 给工具、写代码 → CLI → 现在回到 UI 和「apps」（`00:07:14`–`00:07:50`）。她的判断是，IDE 围绕「代码」这个原语构建了半世纪，agent 时代我们的角色上移到「意图」这一层，因此工具本身需要重构（`01:20:05`–`01:21:11`）。Intent 的答案是：一切皆是 workspace，而不是 agent chat。每个任务建一个 workspace，它有自己的 Git worktree、自己的一组 agent、自己的 markdown 文档承载上下文与 spec；你可以在「给我的网站加暗色模式」和「加一篇博客」之间切换，两边的 agent 团队互不干扰（`00:39:45`–`00:40:47`）。这源自她在 GitHub Next 做的 workspaces 项目：软件开发从 PR 之前就没有协作——Slack 一段对话、Linear 一个 issue、本地一个分支，没有一个地方把「进展、对话、代码」放在一起；workspace 就是那个「房间」（`00:35:31`–`00:39:40`）。

### 按任务划分工作树，而不是按 agent

一个关键取舍：其他工具多是「一个 agent 一个 worktree」，Intent 反其道而行——「一个任务一个 worktree」，多个 agent 在同一环境协作。她同时跑过 8 个 agent，它们互相踩脚、互相指责对方改了文件（`00:43:18`–`00:43:59`）；但只要 agent 们知道彼此存在、知道「三个同事各负责哪个子任务」，同环境协作就相当顺畅。唯一反复踩坑的是自动提交——Git 的暂存与提交消息流程让它们互相干扰，于是他们加了一个「自动提交排队」工具（`00:44:10`–`00:45:43`）。默认编排范式：一个 coordinator 先写 spec，把子任务委派给 implementer（可配更便宜的模型），再派 verifier 实际运行测试、检查交付——因为「agent 不总是做了它说它做了的事」（`00:47:18`–`00:52:28`）。这带来一种全新的工作节奏：你只跟「chief of staff」对话，发现 bug 就随手丢给它，消息实时送达而不打断正在执行的 agent（`00:52:28`–`00:53:09`）。

### 身份危机：陶匠，还是陶器厂？

她提出一个存在主义问题：开发者有双重快乐——「代码的工艺」（掌握工具、知道能搭积木）与「让想法变成存在」（从想象到现实的奇迹）。agent 时代哪种快乐更核心、我们是否仍该亲手触碰泥土，是每个人的选择（`01:07:47`–`01:09:31`）。她借生成艺术类比：如果往盒子里输入 prompt 就吐出蒙娜丽莎，我们对「产物」的价值感会变化——人们珍视的是努力、思考与人性，所以关键是让 AI 当工具而非替代品，让人把成品再打磨成有意图的东西（`01:09:32`–`01:11:08`）。Adam 则给出他的答案：他把 AI 当工具而非魔法盒，坚持「感觉陶土的纹理」、在过程中学习——即使他的典型交互是「你怎么看 / 有什么建议 / 做吧」三连（`00:55:41`–`00:57:54`）。双方都认同：当我们几乎能在一周内清空 backlog，「你决定不做什么」成了新的能力，选择就是超能力（`01:16:03`–`01:17:41`）。

### 宏与微：像地图一样缩放

她把工具设计比喻成 Google Maps：从大楼内部无缝缩放到整座城市，是设计上的奇迹。agent 时代，代码库的「宏观表示」几乎还没人做过——目录树是唯一的伪空间表示，AST 或语义地图都远未成熟；她希望 Intent 能提供这种「缩放」，这也是产品下一步的兴奋点（`01:23:38`–`01:24:44`、`01:29:22`–`01:30:45`）。Adam 对此极有共鸣：他自称「软件工厂的渴望者」，不是要批量吐软件，而是想要同一个界面里既有微观代码、又有「我的所有项目」这张大地图（`01:24:46`–`01:29:14`）。

### 上手与去向

Intent 的入门方式：免费、bring your own agent（Claude Code / Codex / 推荐 Augment 自家的 agent），augmentcode.com/intent，目前有 Mac 版、Windows/Linux 在开发中；选一个 workspace 的起始 specialist——coordinator（编排）或单 agent（你写 spec 后边问边改）（`01:31:25`–`01:33:06`）。她开玩笑说自己的博客域名 wattenberger.com 已经「垄断了全家的姓氏」。临别时 Adam 预告了他正在重构的节目新方向，并确认 WorkOS 刚完成 1 亿美元融资、其创始人将做客（`01:14:48`–`01:14:58`）。
