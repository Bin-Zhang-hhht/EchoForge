## 速读

tldraw 创始人 Steve Ruiz 谈做 SDK 生意与做 SaaS 的差别：水印授权定价的教训、许可证即销售数据，以及 AI 时代客户为何转向自有的上下文与能力。

Steve Ruiz 把 tldraw 定位成一个「为第三方代码而建」的 SDK：公司把画布作为引擎交给别人，而不是把带水的成品交给终端用户。节目用「浓缩液」比喻说明这一点：SaaS 是整瓶饮料，SDK 是不含水、可自行勾兑的浓缩液。这一定位贯穿整期——从它如何定价、如何从授权中获取销售线索，到它为什么与 SaaS 的客户动机不同。（`01:01:02–01:03:55`）

真正值得看的，是这些经营决策背后的因果与边界。水印授权把价格锚定在「去掉一个角落 SVG 的痛苦」上，客户因此觉得不值；改用许可证密钥后，公司才第一次知道谁在真实使用 SDK，并以此找到组织内的决策者。节目没有把任何单一做法写成普遍成功模板，而是保留了他「谈下来的每单都是学习」「价格随客户规模调整并不合理」等经验性判断。（`00:51:06–00:54:08`，`00:55:14–00:57:35`，`01:11:46–01:13:22`）

## 主题正文

### 一个 SDK 公司，而不是一个白板应用

节目开始就进入核心分歧：Steve 说自己在「age of Claude」里试图搞懂如何运营软件公司，而他反复强调的一点，是 tldraw 不是一个普通开源白板应用，而是一个为第三方代码预建好的引擎。他在早期为 Excalidraw 贡献代码时感受到差别：那是一个按普通应用构建的完整应用，要添加功能很难；SDK 则从设计之初就假设别人会在其上构建，这种假设会彻底改变代码的组织方式。他明确说，出售的是源代码，而这份源代码从构建之初就预期用户会继续在其上开发。（`00:22:29–00:23:14`，`01:29:24–01:30:12`）

对公司内部，这也带来「叶子节点」与「核心」的节奏差异。他说，对不依赖任何东西的叶子节点（如 starter kit）可以全速、信任模型地做；越是核心、越被大量功能依赖的部分，越不能只靠模型快速生成。主持人因此把「必要减速」与「AI 加速」放在一起讨论，Steve 没有否认加速，而是补上了依赖与责任的那一面：你可以相信模型去改一个独立的模块，但不会用同样的信任去动画布最底层的结构。这一区分，也是他把 Agent 用在开发流程、但把核心质量判断留给人的具体说明。（`00:30:28–00:32:30`）

内部流程的变化同样具体。他用一个小例子说明 Agent 如何压缩交付：一个过去需要数周、需要一两名工程师集中投入的图像管线 starter kit，他在星期五把需求描述给 Claude，两小时后已完成了大部分，几天内就发布了。但这段描述带着「对个人工具链的个人经验」的限定，节目没有把它写成通用产能结论；他也同时强调，并不是所有部分都能这样快——恰恰是依赖最多的核心部分不能。（`00:15:59–00:18:37`，`00:30:28–00:32:30`）

### 从水印到许可证：定价如何反噬产品

授权策略是本期最完整的案例。Steve 说 tldraw 最初版本 MIT 授权，公司化重写后先在 alpha 阶段用 Apache 授权、公开声明到 1.0 会改，最终 2.0 改为非商业授权：学术、学生与非商业场景可免费使用，商业使用需要购买许可。第一年他们在没有成熟销售结构的情况下，靠逐单谈判做出接近一百万美元的收入；当时卖的是永久授权——买一年更新，之后可以一直用当年版本。（`00:48:40–00:51:05`）

接下来是失败的一步。他们一度转向「V3 水印授权」：任何人都可以免费用于商业应用，但画布角落会出现「made with tldraw」的标记，去掉它才需要付费。Steve 承认这是「坏主意」，因为它把价格锚定在「去掉一个小 SVG」的痛苦上，而不是画布本身的价值；即使客户团队在上面投入了远超授权费的开发资源，他们仍然觉得「为了一个角落小图付这么多钱」不合理。水印还带来另一个副作用——为了知道谁在使用 SDK，他们把水印 SVG 放在 CDN 上、通过请求记录追踪域名，但 Steve 说这种追踪最终没有带来足够的销售能力。（`00:51:06–00:54:08`）

随后他们改成更严格的许可证密钥系统：生产环境必须带有效密钥才能运行，否则 React 检测到生产模式后画布会消失。这个转变的价值不只是计费，而是数据——用户注册密钥时留下的邮箱和域名，让公司第一次可以定位「组织内谁在跑这个项目、应该找谁谈」，而不是追着水印在哪加载。Steve 也保留了一个重要的条件：拿密钥的开发者往往是技术专家，但不一定有公司信用卡，真正的采购决策者常常另有其人；因此线索只是「找对人」的起点，不是现成订单。（`00:54:09–00:54:25`，`00:55:14–00:57:35`）

### SDK 生意与 SaaS 生意的真实差别

Steve 用浓缩液比喻说明 SDK 与 SaaS 的商业模式差异：SaaS 是给你整瓶饮料，SDK 是不含水、可自行勾兑的浓缩液。他说 SDK 的利润率可以很高，因为不需要承担托管、运维、带宽等「水」的成本；但也坦言「如果你自己加水，你可以卖三倍的价格」——也就是说，把成品做好可能更值钱，只是需要解决基础设施、可靠性与安全这些「可以解决的问题」。这句话不是断言 SDK 一定优于 SaaS，而是区分两种生意各自需要承担什么。（`01:01:02–01:03:55`）

另一个重要差别是「离用户一步之遥」。Steve 说做 SDK 的团队不接触终端用户数据，也不替客户回答安全审查问题——当被问到安全时，他的回答是「我永远不会碰你的数据」，因为那不是他介入的问题。这也意味着客户需要自己搭建应用层，比如他们多次拒绝把评论等功能并入 SDK，让客户自己构建；Steve 承认说了四年「不」之后，他开始重新考虑这个边界。少承担责任，也意味着离现场反馈更远：这是节目保留的张力，而不是单方面的优点。（`01:03:55–01:05:28`，`01:17:46–01:18:21`）

### AI 时代，客户为什么转向「自有」

Steve 说，公司今天来找他们「要 tldraw 盒子」的理由几乎全是因为 AI：企业正在做内部工具和 Agent，但被两个瓶颈卡住——上下文（Agent 能访问多少信息）和能力（Agent 实际能做什么）。外部 SaaS 产品能解决日常问题，但 API 面、功能集和权限都不可控；他用 Notion 举例，说自己用了约八年，API 和 MCP 都不错，却拿不到页面历史，导致「总结这周 Notion 变化」这种需求必须每天爬取整站才能满足。（`01:20:21–01:22:42`）

因此，客户想要的不是又一个白板，而是能把数据与操作放到自己控制之下的底座。Steve 用 reMarkable 的个人项目说明「主权」：他喜欢那个设备，因为它运行 Linux，可以安装 Go 程序、给自己造一个 API，把笔记转成数据再交给模型处理，而不是依赖厂商的云；他也担心厂商迟早会改变开发者模式、把他锁在外面。主持人与他把「sovereignty、SDK、self-hosted」列为未来几年的关键词，但这是展望而非已证趋势。AI 需要的是既有上下文又有能力的画布，而 tldraw 的定位正好朝这个方向；节目把这种契合讲成机会，没有保证它一定会变成生意。（`01:23:43–01:26:54`，`01:26:59–01:27:26`）
