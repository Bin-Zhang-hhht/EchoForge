## 速读

The Changelog 第 682 期（全长约 107 分钟）是一期创始人访谈：来自奥地利的 Max Stoiber（react-boilerplate 与 styled-components 作者、Spectrum 联合创始人）回顾了从卧室里的开源项目到 GitHub、Gatsby、自创 GraphQL 缓存公司 Stellate、Shopify，再到 OpenAI 的完整路径。信息密度最高的三段：Stellate 几乎赢下全部目标市场、融资 3000 万美元后撞上「市场太小，撑不起风投公司」的天花板，最终拆成 Shopify 收编团队、The Guild 接手产品的双重收购；他在 Shopify 用九个月把一支一年没怎么发布的团队带成当时公司体量最大的 Horizon 发布；如今他在 OpenAI 负责 ChatGPT 插件目录与应用平台，应用本体就是 MCP 服务器。本文基于 ASR 转写整理，专名与归属以官方节目页核对为准。

## 主题正文

### 开源的运气结构：298 个没人记得的仓库

react-boilerplate 和 styled-components 都曾进入 GitHub 星标前 200，但 Max 开场就拆穿了幸存者偏差：这两者背后，是他做过、没人听说过也没人用过的另外 298 个开源仓库——关键只是「一直做东西，解决自己的问题」（`00:06:20`–`00:06:44`）。他做开源的原始动机非常朴素：不想把同一个问题解两遍，于是把可复用的东西放上 GitHub（`00:07:04`–`00:07:46`）。父亲多年追问「为什么不向每个 styled-components 用户收 1 美元」，他的回答是：一旦收费就没人用了；但正是这些免费项目塑造了他的职业——「我的整个职业基本上建立在它们之上」（`00:08:36`–`00:09:29`）。

AI 议题上他自称「AI maximalist」（`00:10:59`），并给出一个具体的个人现状：2025 年 12 月加入 OpenAI 以来提交了大量 PR，但「我没写过一行代码，我现在只是管理 Codex agents」，他还判断行业内很多人从 12 月起就有同样体验（`00:12:59`–`00:13:14`）。他如今花在「审查编码 agent 创造出的抽象」上的时间最多（`00:17:34`）。

### Spectrum：从播客社区到 GitHub Discussions

Spectrum 的起点是 Spec.fm 播客网络的两位创始人 Brian 和 Bryn：他们想给自己的播客建社区，产品构想是把公共论坛做出 Slack 式的实时感，同时保持可被搜索索引；Max 的加入契机是一次 styled-components 的 bug 私信——他进去排查才发现，他们正在做的正是自己管理开源社区时缺的东西（`00:19:24`–`00:21:44`）。三个人「在卧室里」做了一年半、服务了大量开源社区之后被 GitHub 收购（`00:28:02`）。进入 GitHub 后团队一度同时探索静态与实时两条路线，最终 GitHub 选择了静态路径，一年后以 GitHub Discussions 的形态落地；Max 的评价很客观：对 GitHub 的需求而言 Discussions 是合理产品，但它不是当初 Spectrum 想做的「Slack 加论坛」混合体（`00:30:10`–`00:34:38`）。

### Gatsby 的混乱与重返创业的三个理由

GitHub 之后 Max 加入了做静态站点生成器加云业务的 Gatsby：入职时 60 人，离开时只剩 25–30 人，换了 CEO，内部混乱与戏剧事件部分后来公开，公司「说实话自己内爆了」，几年后被 Netlify 接管（`00:40:21`–`00:41:04`）。他离开后决定自己创业，理由有三：证明自己能不带戏剧性地带好一支真正喜欢协作、能一起做出好东西的团队（`00:41:32`–`00:41:56`）；Spectrum 时期留下的「我能做成大生意」的心气（`00:41:56`–`00:42:07`）；以及渴望创业这种「高压锅」带来的成长速度——「公司的上限是创始人的成长」，而他观察到的极度成功创始人的共同点是极强的自我认知（`00:42:10`–`00:44:33`）。

团队建设的具体功课也来自痛处：Stellate 约 15 人时的一次领导层 offsite 上，团队排出的头号问题是「内部没人敢给彼此批评性反馈」，而原因正是他本人——天性内向的他害怕批评导致连接断裂（`00:45:38`–`00:47:07`）。他为此引入 COIN 反馈框架（Context、Observation、Impact、Next steps），把批评对准事而不是人（`00:50:17`–`00:52:07`），并推广「say the thing」文化，鼓励成员把真正想说的话说出来（`00:53:21`–`00:53:30`）。

### Stellate：赢下整个市场，然后发现市场太小

Stellate 的种子也在 Spectrum 埋下。起步时用 Firebase 频繁出事，整个 API 便转向了 GraphQL（`00:56:48`–`00:57:11`）；他对 GraphQL 的好感还有一段硬核背书——GitHub 收购 Spectrum 前雇了八名渗透测试员整整攻击一周，没发现重大漏洞，他把这归功于「每个查询与变更都带访问检查」的纪律加上 Vercel 托管（`00:57:40`–`01:00:00`）。真正的产品契机是一次运维噩梦：选用的 RethinkDB 虽以实时订阅为卖点，却撑不住暴涨的流量，每晚两次宕机叫醒他去重启数据库；换库是长期工程，他先给崩溃的数据库前面加了缓存当「创可贴」（`01:00:20`–`01:01:21`）。当时 GraphQL 服务端缓存并不存在，他在 Spectrum 手写了一个粗糙的 Redis 版本；几年后经朋友介绍，认识了已做出 GraphQL CDN 原型的 Tim，两人共同创立 Stellate（`01:01:52`–`01:02:35`）。

产品的核心竞争力来自 GraphQL 的字段选择：客户端必须在查询里写明要哪些字段，缓存层因此能理解数据结构，把查询在边缘拆成字段级片段分别缓存——命中部分直接流式返回，只向源站请求缺失片段；客户只需声明哪些字段可缓存（比如价格和库存是动态的），就能以极低成本拿到极高缓存命中率（`01:05:03`–`01:07:26`）。他至今认为这是「地球上最好的 API 缓存」，只是它只对 GraphQL 成立（`01:02:53`–`01:03:13`）。

商业曲线是教科书级的过山车：上线即爆，一个月做到六位数收入、企业合同接连落地，总共融资 3000 万美元；然后增长硬生生平台化（`01:08:02`–`01:08:47`）。复盘结论很冷：产品近乎零流失（离开的客户基本都是自己倒闭了）、几乎吃下所有需要 GraphQL 缓存的公司，但这个市场本身撑不起一家风投支持的公司——主持人补了一句：他收购了整个 TAM（`01:09:16`–`01:09:47`、`01:17:41`–`01:18:17`）。圣诞假期他想清楚了：「公司只有在创始人放弃时才会失败……在那一刻，我放弃了」；共同创始人 Tim 已先因倦怠离开（`01:10:04`–`01:11:11`）。

随后的出售流程本身值得记录：他列了约 70 家沾边的公司（GraphQL 公司、CDN 公司、API 公司），按企业销售的打法拿到创始人或高管的引荐、谈了约九成；九个月的谈判后达成双重收购——Shopify 以 acquihire 收编工程团队，产品、IP 与客户卖给以色列的 GraphQL 服务机构 The Guild，Stellate 产品至今仍在运营（`01:12:04`–`01:13:28`）。他还拆解了 acquihire 的法律机制：Shopify 实际购买的是公司 IP 的全球不可撤销独占许可，有了它，雇走整个团队才没有法律风险；整套交易承重的那行条款，是 The Guild 同意尊重 Shopify 的这份许可（`01:13:38`–`01:16:29`）。他自己留在 Stellate 三个月谈完第二笔交易，再去 Shopify 报到（`01:15:01`–`01:15:27`）。

### Shopify：一年没发布的团队与六个月的 Horizon

Shopify 吸引他的是创始人 Tobi 的理念：客户是创业者，公司里多些创业者才能真正理解客户的旅程（`01:20:09`–`01:20:45`）。入职第一周他甚至没有岗位，任务就是和经理、CEO、产品负责人一起找出适合自己的角色，最终定为 Liquid Storefronts 工程总监：带约 70 人团队，负责商家搭建在线商店的编辑器和 Liquid 工具链——Tobi 二十年前发明的模板语言、VS Code 扩展、CLI 等一整套东西（`01:20:54`–`01:22:24`）。

这支团队当时被视为缓慢：约 50 人的规模整整一年没有像样发布。他自认最独特的贡献是能量——Stellate 时期的匿名 360 评语若做成词云，最大的词会是「energy」（`01:24:46`–`01:25:40`）。结果：九个月后发布 Horizon，新的默认主题加上整套重构的主题平台——一个常规估计两年的项目，他和产品负责人定下六个月的死线并做到了，这是当时 Shopify 体量最大的发布（`01:25:53`–`01:26:33`）。

### OpenAI：给 ChatGPT 做应用平台

从 Shopify 去 OpenAI 是他「此生最难的决定」，纠结了整整三周：他热爱 Shopify 的团队与处境，是朋友们的反复劝说才让他开口去聊（`01:26:33`–`01:27:43`）。压秤的因素很个人：他做过的全是开发者工具，父母甚至长期以为他在 Spotify 上班；而 ChatGPT 是他孩子和父母每天都在用的东西，「我可以为他们改进它」（`01:27:36`–`01:28:59`）。

他现在负责 ChatGPT 应用商店（现称插件目录）：应用的本体是 MCP 服务器；他们与 MCP UI 的作者合作，把它演进为 MCP 应用规范，允许 MCP 服务器随工具调用返回 HTML/CSS/JS 编写的界面，ChatGPT 以 iframe 渲染——在对话里内嵌 Zillow 地图找房、Expedia 酒店卡片都是实例（`01:31:40`–`01:36:13`）。目录几个月内从几十个应用涨到几百个；它是完全开放、免费的目录，但像 Apple App Store 一样逐个审核质量——毕竟按外部最新口径，ChatGPT 有 9 亿周活用户（`01:33:01`–`01:37:14`）。

他对「ChatGPT 应用会不会取代网站」的回答相当克制：不认为有人会因为能做 ChatGPT 应用就不建网站，他更好奇的是那些「只有在 ChatGPT 里才做得出来」的体验（`01:39:25`–`01:39:48`）。他自己就是重度用户——正在用 ChatGPT 里的 Zillow 应用看房，让模型在地图和房源照片里帮他挑「值得先去看的那一套」（`01:41:26`–`01:41:58`）。
