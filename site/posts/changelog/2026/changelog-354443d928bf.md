## 速读

PlanetScale CEO Sam Lambert 隔四年重回 The Changelog，把这家 Vitess 商业化公司的三张牌一次讲清：一是面向个人的 $5 Postgres 和面向 agent 时代的数据库安全门（分支、deploy request、秒级回滚）；二是给 Vitess 十五年经验「一次重来」的分片 Postgres 产品 Neki——原计划两三年，一年就开始迁移客户；三是 Neki 是否开源的未决挣扎：坏玩家借 AI 抄近路的当下，「把牌攥在手里」还是把皇冠送出去。适合数据库工程师和关注基础设施商业化的读者。

## 主题正文

### 为「最飘忽的用户」建的数据库平台

Sam 在 Cursor 大会上演示了十个 agent 在 PlanetScale 平台上做性能优化并安全上线，他的一页幻灯片在推特流传：这平台是「为人类中最飘忽的 agent 建的」（`00:08:10`–`00:09:01`）。逻辑是：分支、在线 schema 变更、变更回滚、拦截会破坏查询的 schema 进生产、按工作负载做 QoS 的流量控制——这些为人设计的保险，恰好是 agent 需要的护栏（`00:08:29`–`00:09:01`）。支撑这套体验的是一条不显眼的洞察管线：平台对每秒数千万条查询采集 trace 与日志、流式进数据仓库，用算法判断索引使用，甚至为此改过 Postgres 与 MySQL 的内核——最后输出给 agent 的只是三行 prompt：「加这个索引、删那个索引、扩这个集群」（`00:11:40`–`00:12:34`）。

安全门的核心是 deploy request：和 pull request 同一批人设计的机制，展示 schema diff、设检查闸门。演示里他先让一个被下毒指令的 agent 去删生产表的列——被拦下，因为该列 24 小时内还有查询引用；再放行一次，异常检测立刻报警、秒级回滚、零数据丢失（`00:14:36`–`00:16:21`）。他说如今客户在 500TB 的表上做 schema 变更，而 500TB 变更的回滚速度与 1MB 变更完全一样（`00:17:17`–`00:17:29`）。

### Neki：给 Vitess 十五年经验一次重来

Neki 是 PlanetScale 的分片 Postgres，已对外宣布并随早期客户推进（`00:06:03`–`00:06:11`）。Sam 的定位：Vitess 是 YouTube 为自己设计的系统，十五年间演化为通用产品但带着超大规模的定制基因；Neki 则是「15 年 Vitess 知识 + 5 年 PlanetScale 云上运维」的 Union，从第一天就按通用系统设计（`00:23:11`–`00:24:28`）。进度超出预期：原以为要两三年，一年就已在把大客户迁上去；团队成员说这是他们职业生涯里最好玩的项目（`01:29:29`–`01:30:35`、`01:33:41`–`01:33:46`）。他并不讳言差距——Neki 尚无 Vitess 的完整功能对等，但会很快补齐；而 Vitess 本身仍在演进，2021 年以来使用量增长 65,000%，两者未来是「不同」而非「谁取代谁」（`01:30:19`–`01:30:35`、`01:34:09`–`01:35:34`）。

他由此给出对 AI 时代工程的经验之谈：代码只是「要啃下去的语法」，真正稀缺的是品味、偏见与经验——把十五年踩坑的判断喂给写代码的模型，才是速度的来源；公司的护城河是经验、文化与目标，而不是代码本身（`01:30:35`–`01:31:56`）。

### 开源还是闭源：一场未决的挣扎

Neki 是否开源，Sam 明说「还没决定」（`00:24:41`–`00:24:50`）。他的顾虑很具体：近年有数据库公司冒领他人开源项目的功劳、fork 之后雇一个维护者名单第十五名的人就宣称接手维护；亚马逊在开源上的表现更是「无可辩护」，Aurora Limitless 有史以来最大的数据库如今就跑在 PlanetScale 上，而它曾平均每天两次故障——亚马逊转头宣传新版会「更像 Vitess」（`00:25:29`–`00:26:55`）。更根本的是，AI 把「理解再复刻」的门槛打掉了：过去代码看不懂就是护城河，现在模型能替你解释权衡（`00:27:08`–`00:27:39`）。

但硬币有另一面：不开源同样有代价。PlanetScale 从未有企业客户流失，可大企业仍希望「万一你们被收购，我们手里有 plan B」——开源代码恰恰是这份保险；他说自己也在这场挣扎里，会持续公开更新想法（`00:41:51`–`00:43:03`）。主持人补上的观察是：行业正在分化出「开源但不接受贡献」「按贡献者资质准入」等中间形态，高利害开源的规则在重写（`00:39:56`–`00:41:10`）。

### 在超大规模云的地盘上竞争

澄清一个误解：PlanetScale Metal 不是自建数据中心——他们用的是 Google 和亚马逊提供的裸金属机，再把整套软件栈压上去（`00:53:46`–`00:54:23`）。这些机器是易逝的，所以真正的差异化是「在 Kubernetes 上跑状态」——他们自称是全球在 K8s 上跑状态最多的公司（`00:54:23`–`00:55:01`）。商业模式上则是 BYOC：直接跑在客户自己的云账号里，客户享受自己的承诺折扣，PlanetScale 的成本加折扣后经常比亚马逊还便宜（`00:55:54`–`00:56:40`）。他对亚马逊的批评毫不客气：350 个服务每个都冒出十个竞争者，而数据库正是亚马逊最赚钱的服务，Sales 会盯着你的用量去挖客户；相比之下微软 Azure 的销售对生态友好得多（`00:57:33`–`00:59:05`）。他还提醒：别让大模型公司重演这套剧本。

### 工程式的营销

Sam 的竞争姿态贯穿全场：发 Postgres 时用一篇纯基准测试的博客对标所有友商，为了把两家画进同一张图还得给他们双倍资源；被对标的 CTO 冲到展位前咆哮，而承诺的后续 benchmark 一年后一篇也没来（`01:16:50`–`01:18:09`）。官网是他深夜在 Google Doc 里画 ASCII 草图起家的，反而走红——他对「9 万美元网站」的判断是：打开页面让 MacBook 风扇狂转，就是坏工程（`01:18:28`–`01:20:06`）。对 Supabase 系的 Multigres（分片 Postgres 开源尝试），他的态度是欢迎竞争但划清事实：对方核心人物离开时 PlanetScale 尚无一个分片生产客户，「PlanetScale 的 DNA 没有被带走」，而规模上双方最大客户相差四个数量级（`01:24:01`–`01:28:20`）。顺带一提，他的推特成了销售线索来源，Salesforce 里专门有「来源：Sam 的推特」选项（`01:11:58`–`01:12:35`）。
