## 速读

嘉宾 Steve Klabnik 的履历很特别：Rust 官方教程《The Book》的作者、差点去读英文系学位的程序员、如今在做 JJ 版本控制工具的创业公司工程师。2025 年初他还自称「AI 黑子」,一年后却用 AI 从零造出了新编程语言 Rue。这期访谈的价值在于他复盘这次转变的每一步——从「回声室外的普通人」那里学到的容错心智，到「规格先行、验证闭环」的代理编程方法论，再到他对行业最大未答题的诚实陈述：当合并一百个 PR 只需扫一眼，质量如何守住？适合所有在 AI 辅助开发中调整自己位置的人。

嘉宾以自我剖析为主，多处属于个人经验与观点；涉及 OpenAI、Anthropic 的说法为转述。

## 主题正文

### 从「AI 黑子」到改换阵营：一次关于事实的挫败

Klabnik 七岁开始编程，今年四十岁，CS 学位读到一半差点转英文系——书架上全是「已故法国人的书」。这种「写作与软件的交叉」让他成了社区里的「文档 guy」,也在 Rust 社区写了十年书。转折前的自我认知是「AI hater」:他记忆犹新，ChatGPT 发布当天他问它认不认识自己，之后的判断是「有趣但没用的派对戏法」；周围朋友都持负面看法，他便默认了这套叙事。压垮叙事的有两件事：其一，他亲眼看到 ChatGPT 在界面里实时搜索网页，切到社交平台却刷到「ChatGPT 根本不能搜索网页」的热帖——「我们对事实本身都有分歧，还怎么讨论」；其二，他决定「做一个更知情的黑子」，认真试用了刚出现两个月的代理式编程扩展 Cline,发现「这东西真的能用」——那就不能再喊它没用（`00:05:26–00:12:17`）。

真正重塑他思维的是一位「回声室外」的普通人：妈妈的男友，一位退休的煤焦油行当管理者，完全不会编程，却是身边唯一对 AI 兴致勃勃的人。他的用法是写工作报告——「我最讨厌面对空白页；它写错 10% 无所谓，我反正要逐条事实核查，那是编辑过程而不是创作过程」。Klabnik 意识到：程序员被确定性驯化了一辈子——「电脑精确执行你说的，bug 只是因为你说错了」；而普通人一直把电脑当成「六成时候答对的魔法盒子」，在心理与方法上反而更擅长应对一个偶尔撒谎的工具。他还自嘲了行业傲慢：「从工具里获得价值就证明你蠢」——也许人家知道你不知道的事（`00:13:09–00:15:47`）。

### 谦逊、神圣母牛与「广告预算笑话」

英文系背景在此意外有用：AI 的本质问题是语言，甚至是「非人实体如何存在」的哲学问题——他提到《Alien Phenomenology》。对「对 AI 客气是否让它表现更好」，他的立场是怀疑但保持开放（他的证据学：看过太多「嘿你个蠢货」开头的翻车对话记录）；对「AI 没有意识所以如何」的断言，他只要求认识论谦逊——「心灵哲学自己还在吵意识是什么」。他把 2026 年软件工程师的处境概括为那句老广告笑话：「广告预算有一半是浪费的，问题是你不知道是哪一半。」我们行业的大量实践——代码整洁、缩进圣战、乃至更多架构教条——「有些有实证依据，有些只是 2002 年某个开了博客的家伙发明的，然后人人复述至今」。这不是说代码质量已死，而是「现在是重新检验信念的时期，需要大量实验、大量犯错」。他甚至为激进者辩护：如今大家谈论的「软件工厂」上个月还叫 Gastown——1910 年代往胳膊上绑翅膀往下跳的人死了不少，但我们今天仍在乘飞机；他本人不用 OpenClaw,但「欢迎他们的牺牲」（`00:19:47–00:22:53`）。

具体到动摇的「神圣母牛」：OpenAI 在博客里提到，代理式开发下给项目加人不降速了——这是自 Fred Brooks 以来最硬的定律；对裁员潮，他的判断一半冷静一半切身：一部分是后零利率时期过度招聘的遮羞布，「但失业的人听到这话不会好受」；他自己的信号灯很简单——「前沿实验室还在招软件工程师，我就不太担心；哪天他们开始裁，我再担心」。逻辑是：让个人更高效的前瞻公司不会想着「用更少人做同样的事」，而是「做更多的事」——他没见过哪家公司愁的是「积压清空、无事可做」（`00:24:19–00:28:48`）。

### Rue 的诞生：时间预算、验证闭环与 spec 驱动

Rue 的动机非常个人：他曾是想做编译器的人，但知道「如果所有代码都靠我亲手敲，永远走不到有趣的部分」——他不在乎解析器，在乎中端、后端与代码生成。人到中年，每周只有五小时自由时间，「花两个周末调试寄存器分配器」的大学式浪漫已经不复存在。2025 年 8 月第一次开工，模型能力和自身技巧都不足——PR 太大、为速度合并了质量存疑的代码、让 Agent 整夜空转——项目搁浅。11 月重启时他做了两件关键的事。第一，承认「用 AI 编程是一项技能，就像 Vim：学习曲线陡不代表工具差，只代表你要练」。第二，「规格驱动的开发」：先写语言规格，再用 Claude 写了一个把规格条目连接到测试用例的自定义测试框架——每个用例是一段示例程序，验证输出、错误信息与编译正确性。原理在于：Agent 是向「不动点」迭代的，而那个不动点就是「测试通过」——给 Agent 自我验证的能力，成功率与速度都大幅提高（`00:29:23–00:35:57`）。

### Rue 的定位与一次「训练语料」实验

Rue 要卡进的位置在 Rust 与 Go 之间：Rust 为性能与底层控制放弃一切，Go 为开发体验放弃编译优化；一个「比 Rust 高级一点、比 Go 快一点、编译瞬间完成、还带强类型系统」的语言存在真实需求。GC 问题的答案是「可变值语义」——沿 Swift 与 Hylo 的思路：如果根本没有引用，就不需要垃圾回收；代价是放弃在结构体里存引用等一点表达力，换来没有借用检查器、没有生命周期标注。他也坦承 Rue 尚未「适合普通程序员」——字符串放进数组还取不出来——距标准库完备只差最后几个问题。另一个隐藏动机是实验：一门训练语料里不存在的新语言，LLM 能写吗？他要证明 Agent 能写出「生产级编译器」，而不只是 React 应用（`00:38:42–00:44:16`）。

方法论的回响已经渗入日常判断——一个「异端」例子是 DRY:他现在看到代码库里有五份相同的函数，反应是「好，合并一下吧」而不是「这摊子完了」。他引 Gary Bernhardt 的老段子说明：DRY 的真正目的是「改动安全」——两份相同字符串两星期后改起来只要五个按键——那是人的约束；AI 不在乎重复，先提交小异端、以后再清理即可。「我们一直把一切左移，因为越早发现越便宜；但也许有些问题放到后面修才是对的」（`00:46:09–00:50:10`）。

### 最大未答题：一百个圣诞 PR 之后

对未来的回答分两半。Rue 是「车库里的那辆 '69 雪佛兰」——实验、玩具、点子的载体；如果别人从中受启发做出真正严肃的语言，他同样高兴。而整个行业的未来，他的答案是一个没解开的问号：圣诞节当天，他陪家人之余在 Rue 上合并了 100 个 PR——「每个我都『读过』，意思是扫一眼、不觉得明显糟糕、点绿」；如果对自己诚实一点，可以发 200 个。速度的诱惑是结构性的，「不然你解释不了为什么这么多人在不负责任地这么干」。他把它称为这个职业当下最大的问题：在允许这种加速的世界里，质量如何维持？不是取消监督，而是「我们如何信任这些不至于反噬的工具」——谁答出这个问题，谁就拿到了代理化编程的下一张门票（`00:50:54–00:54:04`）。
