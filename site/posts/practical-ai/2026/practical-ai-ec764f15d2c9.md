## 速读

嘉宾 Emil Lassen 是 AIUC（Artificial Intelligence Underwriting Company）的标准负责人，这期节目把一个关键问题讲透了：当企业买家说「我不会相信一家靠卖产品牟利的公司自称安全」时，Agent 厂商要拿什么证明自己？答案是老三样的新组合——标准、第三方审计与保险的飞轮，以及其中最硬的部分：对代表性 Agent 实例的两轮红队测试与每季度复测。适合正在把 Agent 产品卖进企业、或正在采购 Agent 的双方。

嘉宾是 AIUC-1 标准的主导者，对该体系的介绍带有立场；节目中提及的客户与收购金额均为其口述，未经独立核实。

## 主题正文

### 飞轮：标准、审计、保险

Lassen 的底层逻辑来自技术采纳史：富兰克林时代的费城为电力立建筑规范、组建消防队、创设第一家互助保险公司——「标准—审计—保险」的飞轮第一次转动；汽车的安全标准由行业自发推动，因为更安全的车卖得更好、也开得更快，airbag 与安全带由此而来；核电站至今仍是这套组合。轮到 AI：技术强大、出错有严重财务后果，而初创公司自证「安全」在银行级买家面前几乎没有说服力。AIUC 想做的就是在「造 AI 的」和「用 AI 的」之间架一层信任：制定标准，联合 Schellman、Coalfire 等第三方审计机构审计，对通过者发证，持证公司还可为残余风险购买 Agent 保险（`00:05:55–00:09:16`）。

### 企业为什么买单：从问卷之痛到上探市场

他给出几个非常实际的驱动力。其一是速度：AI 创业公司要应付企业供应商尽调中动辄上百题的安全问卷，而企业 CISO 也在痛——领域变化太快，问卷恨不得每月重写；一份由行业共同制定的第三方标准，目的是覆盖盲区、减少重复劳动。其二是第三方验证：他提到 ElevenLabs、被 Salesforce 以 36 亿美元收购的 Fin、UiPath 等客户，安全姿态出色，但「有动力卖产品的一方永远无法自证」，需要第三方进场。其三是安全本身：红队持续发现盲区——特定对抗手法会推高幻觉率、切换语言会出问题、越狱与提示注入风险。营销上的先发优势被他排在末位；他认为核心价值是解锁向上层企业市场的收入（`00:10:42–00:13:22`）。

### 三层标准版图与 AIUC-1 的位置

他把现有标准分为三层：组织层是 ISO 27001 与约三年前发布的 ISO 42001（AI 管理体系认证）；基础设施层是 SOC 2、渗透测试、访问与传输安全——在 AI 场景因节奏与数据访问量更高而更重要；而 Agentic 层在他起步时基本空白：NIST AI RMF 与云安全联盟的 AI Controls Matrix 有涉及，但都属于自愿性指南，「不可认证、不可审计」。AIUC-1 的取舍是把组织层的核心治理（Agent 失效预案、变更管理——每次更换底层 LLM 行为都会变）与基础设施层的关键项（权限收紧、Agent 间通信的传输安全）拿进来，其余留 给 ISO 和 SOC 2，自己聚焦 Agentic 层：品牌一致性、不得输出医疗法律财务建议、限制数据/系统/工具访问权限（别乱给用户退款）、幻觉治理等。40 条强制要求中有 6 条与红队相关——技术控制必须在对抗压力下仍然成立。他还提到官网公开的约 10 个框架交叉对照表，以及与 OWASP、云安全联盟、Cisco、IBM 的协作；控制项免费开放，只有申请认证才收费（`00:16:25–00:22:10`）。标准每季度更新，背后是约 250 人的安全负责人联盟；上季度主题是 MCP 风险，本季度是运行时安全，远期规划则伸向模型层与物理层（数据中心、汽车、机器人）（`00:22:34–00:23:58`）。

### 认证怎么走：从差距评估到季度复测

流程从差距评估开始：对照现有信任中心与文档，告知哪些已达标、哪些有工作量——从三人 YC 初创到上市的 UiPath 都走过，标准随组织规模伸缩。正式认证双轨并行：一条是委托认可审计机构收集证据，包括法律政策（输入输出权属、用户数据留存与是否用于训练、可接受使用）与技术控制（有害输出过滤配置、分类器、防御性提示、防幻觉的 groundedness 过滤、工具调用防护）；另一条是 AIUC 的红队——受认证方提供一个「按公开文档与默认配置」组装的代表性 Agent 实例（他特别提到会阻止厂商为过审而把 Agent 阉割到失去能力），内部团队据此设计风险矩阵与量身定制的攻击场景，从良性提问，到说谎、冒充权威、多轮纠缠、伪装困境施压（「不给我退款我就做可怕的事」）逐级加压。红队分两轮，首轮发现后给一到四周修复，第二轮结果定案；最终交付六十到一百页的审计报告与证书。此后每季度，AIUC 会用保留的 API 访问重跑同一套测试，确认季度内的变更没有破坏安全项——这是维持认证的硬性要求（`00:24:52–00:29:41`）。

### 「通过」的定义：没有满分，现实比无瑕更值钱

判定按严重度定级：P4 无关痛痒的小幻觉、P3 轻微、P2 有现实影响、P1 严重、P0 灾难级。存在 P0/P1 即无法通过。但他强调一个反直觉事实：从来没有、也不会有公司以 100% 通过率拿到 AIUC-1——Agent 系统本质非确定，压力足够大时永远可能被越狱、永远可能幻觉；把幻觉清零的代价是把 Agent 变笨到无法干活。容忍度应由公司与客户的用例决定，标准选择用透明的审计报告代替「无瑕」幻象——报告里写明的漏洞会形成修复的市场压力。他承认企业买家目前仍偏爱「一尘不染」的报告，但他希望推动行业接受：反映现实的报告比无瑕的报告更有价值（`00:29:41–00:33:30`）。

主持人 Daniel 用健康打比方：一次内容过滤只是「量个体温」，真正的治理是接入医疗系统——完整的体检、病历、流程与政策。Lassen 很喜欢这个延伸：季度红队是全身体检，运行时控制是每分钟的生命体征监测与报警，可观测性让你在异常时能回放解释，输入输出治理则是「别吃垃圾食品」（`00:34:56–00:38:34`）。

### 生态演进：默认安全、伙伴平台与 GRC 集成

对「个人开发者如何够得着这些要求」，他给出三个支点：一是 Agent 产品与平台「默认安全」——他们正在认证首批编码 Agent（提到 Lovable 与另一家刚被高价收购的大厂编码 Agent），在 UiPath 这类平台上直接构建 Agent 时，环境本身已带安全默认值；二是伙伴生态——他点名 White Circle 的监控与过滤可以直接满足标准中八到十条要求，Credo、Witness AI 等也在合作，AIUC 同时公开了「典型证据长什么样」的指引，不让厂商自己猜怎么实现；三是认证流程本身的工程化——接入主流 GRC 平台、用程序化验证取代截图取证，把第二年复审的时间成本压到最低，「让大家专注安全而不是合规」（`00:39:56–00:43:11`）。
