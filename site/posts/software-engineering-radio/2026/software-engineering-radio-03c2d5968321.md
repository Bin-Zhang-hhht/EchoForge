## 速读

斯坦福教授、GNN 先驱、PyTorch Geometric 合著者 Jure Leskovec 与主持人 Sriram Panyam 谈他正在 Kumo.AI 打造的新方向:关系基础模型(RFM)。他的诊断很尖锐——自然语言与图像视频已被 AI 攻克,而企业最有价值的表格/关系型运营数据却是"AI 缺失的模态";预测建模还停留在三十年前的人工特征工程时代,每个模型约两个全职人力、半年上线,大多数模型根本没见过生产。

最值得带走的三点:把数据库表示为图(行是带属性参数化的节点,主外键是边),用行内、列内、跨表三种结构化注意力直接读原始数据,免掉摊平与特征工程,精度反而"超人";这类模型不需要 LLM 级的数据与算力——单表模型约 2500 万参数,训练投入以百万美元计;预测自带校准置信与基于注意力回溯的自然语言解释,解释本身就是调试数据泄漏的"法证工具"。

## 主题正文

### 预测建模被 AI 革命落下了三十年

Leskovec 先把话题锚定在预测建模上:从历史运营与行为数据里找模式来预测未来——金融反欺诈、商品推荐、客户流失、下一步最佳行动、客户生命周期价值,再到医疗的再入院风险与 24 小时病危风险。人类天生有偏、不擅长估概率,所以需要校准过的模型。但他随即抛出诊断:AI 领域的高歌猛进集中在自然语言与图像视频两种模态,而预测模型学习的对象——存于数据库与数仓中的表格型运营数据(客户表、商品表、交易表)——今天的 AI 并不能真正推理。你没法把一张交易表塞进 ChatGPT 问"这像欺诈吗",得到的只是常识水平的低性能回答。于是企业只能退回"老式机器学习":雇数据科学家清洗数据、造特征、训练、部署——他给出的行业口径是每个模型约两个全职人力、约半年才上生产,而多数模型从未见到生产。（`00:01:02–00:04:49`）

### 特征工程的跑步机:为什么传统 ML 这么疼

以流失预测为例,数据科学家不能把三张表直接丢给模型,而要人工把客户的交易史聚合成特征:上周买了多少、上月买了多少、周几买、上午还是下午、价格总和、中位数、最贵最便宜的商品……再看商品侧的品类、星级、流行度——"信号的可能性是无限的"。真正麻烦的在生产端:每来一笔新交易,所有下游聚合都要实时重算。更本质的问题是摊平即失真——"原始交易序列里的信息,远多于'近 7 天次数'这个任意构造";特征是否有效只能先造、再训、再看效果,是一次次猜测。反欺诈还是场对抗游戏:对手摸清你的模型后绕着走,你再猜缺什么信号——永远慢一步。再加信息泄漏与时间正确性这类 Bug(不小心把明天的交易也统计进来,"用明天预测明天当然准"),他总结这门手艺"30 年没变过,极难产生价值"。架构不是问题,问题在人工摊平、造特征、实时更新特征这条流水线。（`00:04:49–00:10:31`）

### 关系深度学习:把数据库当图,让注意力读原始表

他的论纲分三步。第一,表格型关系数据是企业决策的关键、是最有价值的数据——即便在 agentic 世界,Agent 做决策也必须由数据与历史模式驱动,而非常识。第二,今天的 AI 不理解这类数据——"把数据库文本化塞进提示词,人们试过,烧得很惨"——这是 AI 缺失的数据模态。第三,解法是关系深度学习:把一组表表示为链接图,把文本 Transformer 里的注意力机制推广到"在数据库的表上做注意力"。收益有二:生产力(不再摊平表、不再人工造特征)与"超人精度"——注意力直接在原始交易序列上学习如何组合信息,是 7 天还是早晨还是晚上,让它自己从数据里学;而且这种注意力是递归的:人→交易→商品→别人的交易→另一个人,"买和我同样商品的人有什么特征"这类信号自动进入模型。（`00:10:31–00:14:12`）

主持人追问"token 是什么":可以把每个单元格视为 token,也可以把整行视为一个 token(用户、交易、商品);更准确的图景是注意力既落在单元格的值上,也落在单元格之间的指涉关系上——这张表的主键指向另一张表的外键。Token 空间因此是无限的(单元格可以是文本、图像,取值任意),没有 LLM 那种固定词表。注意力机制也随之重构为三种高度结构化的类型:行内(一行内全对全)、列内(一列参照其他行的同列值,了解取值分布)、跨表(只沿真实存在的主外键链接)——都不是"所有 token 对所有 token",复杂度分别受行数、列数与真实链接约束。他强调这是设计特性而非妥协:尊重数据的组织方式、计算有界、可扩展。（`00:14:12–00:19:10`）

### GNN 的过平滑教训与基础模型的数据饥渴度

作为 GNN 的开创者,他把图神经网络定位为"重要的第一步":较小的模型、预定义的聚合(求和、平均)。但 GNN 有过平滑/过挤压问题——在图上走太多跳,邻域里什么都平均了一遍,值都趋同了。他给的直觉来自 Pinterest(他在那里当了六年首席科学家,图学习系统带来核心指标 30-50% 的提升并伴随公司上市):预测一个用户,朋友的信息有用,朋友的朋友也有用,但沿友谊链走十跳,由于六度分隔你已经覆盖了全人类——全球信息来预测一个人,只会把模型淹没。GNN 时代的解法是人为限制深度("走三跳就够了");注意力架构则不需要这种拐杖——可以把"上下文窗口"开大,让训练过程自己学注意什么。这也连接到基础模型:上下文内学习需要大上下文。（`00:21:29–00:25:29`）

关于数据饥渴度,他的回答颠覆了 LLM 直觉:这里的信息就在数据本身,模型不需要记忆整个互联网,只需要学会"发现并注意模式"——所以模型可以很小。两条路线按需选择:高 QPS 的单一高价值任务(反欺诈、每秒百万次推荐)用微调过的小专用模型,便宜且准——这种场景里决策准确率提升 1-2% 就是数亿美元的营收差异;而基础模型路线带来"预测问题的 ChatGPT 时刻":不用训练,当场指定预测任务——"流失=未来 30 天无购买",几秒后得到预测、精度估计与自然语言解释;改口"流失=月消费低于 10 美元",又是一秒。模型与数据库无关、与任务无关。规模上,单表模型约 2500 万参数("能跑在我 iPhone 上"),多表关系模型更大但仍是十亿参数以下;训练投入是"数百万美元"级而非 50 亿美元——理论上一家银行可以自研专属基础模型再按用例微调,他的公司 Kumo.AI 正看到这类需求。（`00:25:29–00:31:45`）

### 时间序列也是图,瓶颈在 ETL 而非训练

主持人问时间序列:历史与演化怎么进图?Leskovec 的回答是"时间序列预测问题本质上也是图问题"——时间序列彼此相关(同品类商品互相竞争),只对单一序列做注意力,学不到"这个商品的销量与另一个商品相关"这类跨序列信号。今天人们把时间序列当独立对象,只因"现在的技术只有这把锤子";已有的时间序列基础模型是逐序列的 Transformer,天然受限。图方法在时间序列与供应链类数据上表现很好。（`00:32:21–00:34:58`）

计算资源的真相是:预测建模的瓶颈从来不是训练,而是跑在 CPU 上又慢又笨的 ETL 管线——"跳过 ETL,上一个大 GPU 模型,直接在原始数据上训练"。他承认这个主张听起来惊人,其实只是重演:计算机视觉早已走过这条路——没人再为"图里有没有牛"人工设计 SIFT、Gabor 特征了,卷积网络与视觉 Transformer 直接在像素上注意并组合。他做的事就一句话:把数据库想成图,节点是像素的对应物,关系就在那里——"注意它"。部署也变得平凡:训练完成后,事件到来时保持图最新,预测只需取目标节点的一个小邻域子图,推过 Transformer 即可——没有特征管线、没有特征存储。（`00:34:58–00:39:19`）

数据库本身怎么演进?低 QPS 场景照旧用 Postgres、MySQL 或 Snowflake,把取数下推成 SQL 即可;但现有图数据库是为查询型工作负载而建,支撑 AI 的读路径(大规模子图抽取)慢了一到两个数量级——Kumo 因此自研了专用的图式存储。硬件侧,图比文本和图像难一个量级:文本可切、图像是定长矩阵,图没有上下左右、处处互联,内存访问近乎随机;他们正与 Nvidia 合作定义未来芯片的基准与需求——超越序列式 LLM 之后,访存模式完全不同。企业数据规模也不可小觑:区块链全量交易、Reddit 全量点击评论、银行交易流水,轻易到 PB 级以上。（`00:39:19–00:45:31`）

### 校准、非幻觉的解释,与"数据即调试对象"

LLM 有幻觉,预测模型有吗?他的回答是:关系基础模型的输出是带校准不确定性的预测——因为损失函数度量的是真值与预测之间的距离,错得越多罚得越重;而 LLM 只惩罚"下一个 token 对不对",预测 200 与预测 2000 的代价相同。LLM 还需要后训练阶段"缝合"人类偏好,那会扭曲模型的自信;这里不需要,输出质量可客观度量,校准在训练中"免费"获得。上下文学习的形态是:给模型一批历史示例,问一个未知问题,模型会主动藏起几个已知结果、假装未知去预测、再对答案——因此它给出的精度估计是客观的、非幻觉的,"不可能过度自信"。每次预测返回三样东西:预测值、置信区间/精度估计、自然语言解释——解释靠回溯注意力实际看过的表、列、行,直接从原始数据合成。（`00:45:54–00:51:44`）

这段解释机制被主持人称为"调试踪迹",Leskovec 深以为然:它能暴露信息泄漏(某个不该在预测时可见的列被模型依赖了)、发现新信号(模型在看的表提示你可以再连入别的表)、甚至发现"好得可疑"的预测。销售线索评分的例子很生动:销售质疑"为什么给我这单的成单概率这么低",模型答—— deal 规模偏大、没有高管赞助人(Executive Sponsor)、而且这份数据已经三个月没更新;销售补上新信息重查,还能接着问反事实问题:"如果给客户 9 折,成单概率怎么变?"（`00:51:52–00:55:15`）

数据量从数千条到数百亿条都有成功用例,模型大小按需选择。与 Agent 的结合是他看到的大趋势:企业 Agent 要做的是决策——客服 agent 在开口之前要先回答"这位客户的 LTV 多少、流失概率多少、挽留的最佳行动与最优 offer 是什么";今天的 agent 还停留在"检索知识再改写"的阶段,而 A/B 测试显示,由预测模型指导的销售团队与用 LLM 加既有工具的团队相比,效能差出约 30%,预测模型比"常识水平的 LLM 或人类"准确 20-30%。给从业者的 hello world:研究者从 PyTorch Geometric 与 RelBench 入手;实践者可以直接玩 Kumo RFM 的公开 SDK,该技术也将预装进 Snowflake 等数仓。收尾他重复了那句总纲:"结构化的关系型企业数据,是今天 AI 缺失的模态"——关系深度学习与关系基础模型,就是预测建模的下一站。（`00:55:18–01:01:13`）
