## 速读

Meta 的 Sam Goldman 与 Danny Yang 做客 SE Radio,讲他们开源的 Pyrefly——用 Rust 写的 Python 类型检查器兼语言服务器。从 mypy 与 Pyright 各管一摊的"双检查器错位",到给函数参数默认 Any 的设计取舍,再到 laziness、并行、增量三大性能支柱,这期是 Python 类型检查生态的完整地图。

最值得带走的三点:Pyrefly 的架构是"语言服务优先"——把批量类型检查由内向外翻转成从打开的文件惰性展开,这才有了 IDE 毫秒级响应;函数参数不做推断是刻意设计,推断交给专门的 `pyrefly infer`;而"类型检查器能否帮助 Agent 成功"目前只是假设,团队正在搭实验框架验证——未来尚未写就。

## 主题正文

### 类型检查器+语言服务器:一个工具的两种身份

Sam 先给类型检查者下了个朴素的定义:帮程序员在代码里找错误的工具。与 Rust、Java 不同,Python 没有内置的静态类型检查器,mypy 或 Pyrefly 都是需要额外引入的工具;而 Pyrefly 同时还是一个语言服务器——实现 LSP 协议,一次实现即可在 VS Code、Neovim 等编辑器里提供跳转定义、悬停、代码动作。使用场景对应两个地方:IDE 扩展市场装上即用(诊断面板列出类型错误并可跳转),以及每次变更的 CI。类型注解源自多年前的 PEP 484:解释器运行时无视它们,类型检查器却靠它们工作;没有注解时检查器会做推断尽力猜,但有明确注解时表现更好。（`00:00:57–00:05:41`）

Danny 补上了推断(inference)与细化(refinement)之别:前者是无注解时猜类型;后者是根据代码结构收窄类型——Python 代码充满运行时类型测试(参数可能是字符串或数字,函数内部检查后分头处理),类型检查器必须能跟上这种逻辑,这正是 Python、TypeScript 这类动态语言的检查器才有的特性,Rust 里几乎不存在。一个日常例子说明价值:删掉函数的一个参数,检查器会在每一个调用点报错;没有它你只能 grep,而 Python 可以给函数起别名、把函数传来传去、还可能存在同名不同义的函数——grep 很容易漏。（`00:05:42–00:09:40`）

### 生态的"双检查器错位"与新学派

Sam 梳理了生态史:PEP 484 来自 mypy,它是 Python 类型化的开创者,用 Python 写、只做检查器不做语言服务;后来微软推出 Pyright,既是检查器又是语言服务器,而正是语言服务的价值让类型检查"与大众连接"。于是长期存在一种尴尬:IDE 里 Pyright 给语言服务、命令行里 mypy 报类型错误,两个检查器可能不一致。现在出现了新学派——Zuban、ty、Pyrefly 都瞄准"又快又兼容"的一体化方案,Python 类型化正处在拐点。（`00:09:41–00:12:08`）

主持人借机问清了四个术语:真阳性(Pyrefly 报错且确实是 bug)、假阳性(报了但代码没错)、假阴性(有 bug 没报)、真阴性(没报也没 bug)。静态检查器不接触运行时,本质上是在"猜程序员意图",猜错就有假阳性。团队从版本到版本紧盯 FP/FN 两条曲线,用真实世界代码语料衡量表现。对"跑过类型检查器意味着什么"的回答也很克制:只意味着"在 Pyrefly 看来,程序与注解相互一致"。不同检查器对同一程序意见不同的最大原因,是各自对"推断多少、放过多少"的取舍,以及对类型规范实现的完整度——Sam 直言"生态里有多个彼此显著分歧的检查器,这不是个好状态"。Any 则是渐进类型的安全阀:显式标注它是"太难类型化了"的后门;检查器内部也会在无信息处(比如不带参数的 list)推断出 Any。（`00:12:10–00:17:38`）

### 每秒 185 万行:为 Agent 而生的性能观

Pyrefly 官网宣称在 Meta 基础设施上每秒可检查超 185 万行代码。Sam 对性能的解释分两层:所有开发工具都应该快,而当工具快到"即时响应"时会发生质变——它可以挂到每次按键上,变得像对话一样自然。这直接连到 Agent 时代:如果 Agent 能把类型检查器当工具用、低成本地验证每一步,交互轨迹就更容易走向成功——验证越便宜,token 越省、循环越快。Danny 的总结是这与人类用法同构:收紧反馈环、把错误左移——没有检查器时你要跑全量测试套件等几分钟,现在每次保存文件就有新信号。（`00:17:28–00:20:08`）

### Rust 之选与"语言服务优先"的架构

Pyrefly 用 Rust 写,原因是社区与生态:团队前作 Pyre 用 OCaml 写——语言很美但社区太小;Rust 爱学者众、第三方库丰富。Pyrefly 是 Pyre 的精神续作,零代码复用,但吸收了设计教训与 Pyre 规模化失败的地方。架构上主持人概括的三阶段成立:先传递性地解析模块导入,再把 AST 转成完成作用域解析的中间表示"bindings",最后求解这棵 bindings 图。而真正的关键设计是从单文件到多文件时的反转:如果只做类型检查,会写成批处理;但要做语言服务器,就必须"把整个过程由内向外翻"——从用户打开的那个文件出发惰性展开,毫秒内给出有用信息,连"遍历文件树发现所有文件"的时间都不能花。一个早期 bug 印证了惰性的必要:曾经导入文件就急着整个分析,导致一个两三个文件的小项目,因第三方依赖的数百万行代码而检查超过一分钟——本该几毫秒。现在除了惰性首开,还有后台索引任务花几秒钟把项目和第三方依赖建完索引。（`00:20:09–00:28:25`）

### typeshed、迁移工具与 Pyrefly Infer

typeshed 是为没有内联注解的第三方包集中存放类型桩的仓库——有的是为了兼容旧版 Python,有的是维护者不想背注解的包袱;Pyrefly 内置了部分桩,你也可以把 typeshed 桩作为依赖装进项目,让任何检查器都认识这些类型。三个界面的分工:IDE 里是补全、跳转、导航等"写作与导航"动作;CLI 里是 `pyrefly check` 给出全部类型错误清单;CI、编辑器扩展市场与 agent harness 都能接。迁移工具箱相当贴心:自动读取 mypy/Pyright 配置生成等价的 Pyrefly 配置(错误码尽力映射;Pyrefly 推断比 Pyright 多,迁移时会关掉一部分推断以求兼容,之后可以再收紧);首次切换很少全绿,于是有 `pyrefly suppress`——不逐条插注释,而是把现存错误记进一个基线文件整体压住,以后再清理。`pyrefly infer` 则填补 check 的设计空白:函数参数默认不做推断(推断参数类型需要全程序调用点分析,库函数的调用方甚至在别的仓库),参数一律按 Any 处理;infer 是较慢的、偶尔运行的静态分析,扫所有调用点后建议"这里你可能想要这个注解"——为无类型项目自举类型;与运行时追值的 MonkeyType 相对,它完全是静态的。（`00:28:27–00:37:00`）

### 快的三支柱:惰性、并行、增量

除惰性外,Sam 点出另外两根支柱。并行:mypy 受 GIL 限制单线程,Pyright 跑在单线程的 JS 引擎上;Rust 让分析能吃满所有 CPU 核,索引阶段把工作切块并行——"惊人的每秒行数"就是这么来的。增量:依赖图同时记录依赖与反向依赖,改一个文件,反向依赖自动失效重查,不必每次按键都全量重算。工程保障是 CI 里持续测量多维度性能:端到端检查时间、首文件索引时间、以及"改一处后错误跨项目传播更新"的增量时间;发布前跑基准,日常靠警觉与画像防回退。（`00:37:01–00:41:10`）

### 一致性测试、开源治理与"未来尚未写就"

治理模式与 Pyre 时代截然不同:那时 Meta 内部是主要用户,GitHub 上的 PR 与 issue 都慢;Pyrefly 每周发版、附详细 release notes,每周收到几十个 PR 并及时评审——用户早已不是 Meta 内部,通过各编辑器捆绑(Pyrefly 被打包进 Antigravity、Positron 等)每天有超百万活跃 IDE 用户,PyPI 下载与 CI 使用也大量来自社区。Python 类型化有个与 TypeScript 本质不同的点:类型注解是语言规范的一部分(而非 JS 之上的扩展),由 Python 类型委员会维护规范与一致性测试套件(自动化的"检查器是否正确实现规范"的 CI)。Pyrefly 刚刚通过 90% 的测试,团队很自豪;但 Sam 立刻补上边界:该套件只覆盖检查器实际工作的一小部分——对类型推断只字未提(连"x = 1 是什么类型"都没有规定),所以高分的意义有限,决定日常行为的还是真实代码语料,"真正的测试是你自己上手跑"。在大图景里,类型检查器与 linter、测试互补:linters 多是非关键的风格建议,检查器报的是可能导致运行时错误的问题;相比运行时测试,类型检查"几乎免费地获得约 100% 覆盖率"——它读遍所有代码,不用为每个分支写测试。语言服务器与 CLI 本是一体:类型错误本就是语言服务能力的子集,做成 LSP 就同时得到两者;而且 LSP 还能通过 MCP server 服务 AI——agent 可以直接问"这个位置的类型是什么",比 grep 一堆文件自己拼上下文可靠得多。（`00:41:12–00:48:45`）

最大的开放问题留给了 Agent:类型检查器到底能不能帮 Agent 更成功地完成任务?团队正在搭实验框架验证这个假设(工作由同事牵头),因为 Agent 不加帮助也挺擅长读懂代码——类型检查也许只是帮它省 token,也许在 agentic 世界里根本无关紧要。Sam 的原话是:"未来尚未写就。"收尾的行动号召:Pyrefly 仍在 beta、正式版将发,Discord 与双周 office hours 都开着;浏览器里的 Playground(编译成 WASM,连语言服务器和 Pyodide 运行时都带上)可以零安装试玩。Sam 特别喊话 Python 库维护者:"Python 的未来,我希望是有类型的——用户会期待你的库提供类型。"（`00:48:46–00:54:37`）
