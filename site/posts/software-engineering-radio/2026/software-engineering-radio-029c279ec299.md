# 三年闭环实验之后，一位"AI 现实主义者"谈 AI 辅助开发的有效用法

## 速读

拥有 30 年经验、教了 25 年课的 Jason Gorman 自 2022 年底开始做闭环实验(同一实验跑十次取分布、变换模块大小与测试变量),自封"AI 现实主义者"。他与主持人 Giovanni Asprone 的对谈给出了当下最能立住的使用法:微步骤、每个步骤带明确的退出判据、步骤之间冲刷上下文、给模型测试作为收敛目标;并把"长视距全自主编码"直接斥为幻想。

最值得带走的三点:有效上下文比厂商宣传小几个数量级,准确度悬崖在几百到一两千 token;写代码从来不是软件开发的瓶颈,消防水管只会把水灌进代码评审、测试与合并这些下游堵点;AI 是放大器,但只放大"本来就会度量产出"的团队——只统计 commit 数的团队可能正在变差而不自知。

## 主题正文

### 三年闭环实验:可靠性是速度极限

Gorman 的实验方法是物理学家式的:进入 agentic 时代后,把同一实验跑十次拿分布,再变换变量——模块变大变小、提示里带测试还是去掉测试。他同时追踪计算机科学与统计力学两个社区的研究(概率系统正是后者的地盘)。他自封"AI 现实主义者",关注的是"真实的、有效的、经济上和环境上可行的、伦理上站得住的"。核心结论至今未变:语言模型也许会更有能力,但可靠性不会好多少——无论怎么扩大规模,这正是软件开发者的真正速度极限:你能放它自主跑多久,才需要检查和干预。（`00:00:59–00:04:03`）

### 上下文是稀缺资源:注意力稀释与微步骤 TDD

第一个实践发现关于上下文。LLM 无状态、像 Web 服务器,状态要靠调用方来回搬运;对话越长、喂得越多,可靠性越差。机制上,模型要计算上下文中几乎所有 token 两两之间的注意力,概率总和必须为一——token 越多,每个概率被摊得越小,细节和语义随之丢失。他援引研究说,尽管厂商宣传几十万甚至百万 token 窗口,准确度悬崖实际在几百到一两千 token 的量级,有效上限比宣传小几个数量级。（`00:04:04–00:06:30`）

对策是把敏捷时代的拆解习惯用到极致:一次只解决一个问题,上下文只装这个问题所需。他示范的 TDD 节奏是——建一个最小上下文让模型写一个会失败的测试(购物车加一件商品);看到测试失败,冲刷上下文,新开一个上下文让它写"恰好通过该测试"的最简代码;再冲刷。每个微步骤都有明确的退出判据,退出即冲刷,新步骤配新上下文。他给出模型"吃测试就好"的两个机制性解释:训练语料里代码本来就与用例/测试配对,模式匹配更准;近年模型开始用测试执行结果做强化学习反馈——所以测试既是训练分布内的东西,也是多轮尝试时的收敛靶子。闭环实验里,给了明确成功判据的任务完成率显著更高(从未到 100%,但相当好);没有测试,模型只会原地打转。（`00:06:30–00:10:08`）

### Doom loop、长视距神话与"轮渡瓶颈"

他的控制权演化之路:从人肉驱动每一步,到流行的 Ralph(Wiggum) 循环——给个目标掷骰子,不对就重置代码和上下文再掷,设个最大尝试次数;再发现问题:有些题目它怎么掷都掷不出你要的数,他把这叫 doom loop——问题落在训练分布之外,再多次尝试也没用(他用扩散模型类比:让文生图画"倒满的酒杯"就是画不出来)。解法要么降挡回规划模式把问题拆小("掷不出 13,试试 6 加 7"),要么人接手。由此他下了断言:给一组需求然后去海滩的"长视距全自主编码"是幻想——他见过 Agent 跑几小时,没见过跑完还能产出可用东西的。二十个功能丢给模型、自己去酒吧,每一步都可能走错,错了之后的一切都盖在错误之上——成功率"天文数字般地低,我一票否决"。（`00:10:08–00:13:00`，`00:20:19–00:21:09`）

并发 Agent 也救不了长视距。他做过一周实验就放弃的 Claude Code 并发 Agent;道理是持续集成的"花园门":所有并行工作最终都要过同一个发布分支,红绿灯纪律下大家只能排队,再加多少条车道也没用——"去肯特郡轮渡港口的高速公路修八条道,船只有一条"。加上各 Agent 抱着各自发散的代码视图,同步问题就是老掉牙的人月神话。真正有效反而最古典:关注点分离与模块化是秘方——变更的爆炸半径决定上下文大小,改一个文件就能闭环的系统,才配得上小上下文的工作法。（`00:21:30–00:25:36`）

### 地图与列车:大局是人,火候是 AI

TDD、重构、持续集成是"一只脚接一只脚",但路线图仍然要人看。他引 Kent Beck 新发的 Canon TDD 博文与《TDD》书里的 test list:开工前先列一张高层清单,记住"地图不是地形",边走边修正。这件事 AI 替代不了——他直白地把 LLM 叫"超级自动补全":深度神经网络训练不了长程模式,离得越远的关联概率越低;LLM 是"平均机器",模型塌缩(拿模型输出训练下一个模型,越训越笨)就是证据。人可以借 AI 探索架构想法,但"这是架构,去实现吧"这种委托存在信息断层——高层表示与代码级生成之间隔着它跨不过去的表示落差。（`00:12:59–00:17:25`）

### 消防水管:下游瓶颈、放大器与度量错位

没人怀疑这些工具出码快,但写码从来不是瓶颈——从打孔卡时代起就不是,查文档也不是;真正的重活是依赖、沟通、反馈回路和谁都不肯拉的杠杆:批量大小。让 Agent 狂奔只会产出大批变更,砸进评审、测试、合并这些下游队列。他引 CircleCI、Faros("开始容易,完成难")与 DORA 的数据:出码提速的收益正被下游混乱吞掉,生产事故与交付延迟上升,"理解债"累积——修生产问题的时间变长,他怀疑主因是"没人看得懂这些代码了"。消防水管的比喻是:限制不在水管在你,一次只能喝一口,那就短促地开阀。（`00:17:25–00:19:13`）

放大器效应他也只认数据:DORA 三年来较一致的发现是,一小部分本来就高绩效的团队确实提速且不牺牲稳定性;但无法排除因果是反向的——AI 是对开发方法论的压力测试,把瓶颈照出来,逼着团队小步走、勤评审、搞变异测试和静态分析。危险的是度量错位的团队:量 commit 数、PR 数、进水量,却不量出水和价值——他见过"感谢 Claude Code,周 commit 从 50 涨到 500"的帖子,这什么也说明不了。用他的话说,这些团队"正幸福地浑然不觉 AI 在让他们变差"。对还没建立这些实践的团队,他的建议按 DORA 的自测问卷先定位自己在分布的哪一段:先挤进蓝色高绩效区,再把消防水管接上;处于他自创的"灾难级"段反而好消息——小改一步(比如"改代码先写测试")就能到平均;偏红的团队则应把 AI 隔离在顾问角色(聊天窗口、行内补全),别让它直接碰代码。他相信价值大头在流程与实践,工具只是"用好实践的借口"。（`00:25:40–00:28:44`，`00:29:39–00:31:44`，`00:34:29–00:37:43`）

### Clever Hands、认知退化与"未来是软件开发者"

对工具学习成本他不担心:相对领域知识是"毫米对高山",招个好 C# 开发写 Java 也就几周。要防的是控制错觉——有研究(他引《Superintelligence or superstition?》)发现对 AI 输出的置信度与相信超自然/星座显著相关;他命名的"Clever Hands 效应"典出 20 世纪初那匹会算术的马(驯马师在场才答得对):他亲眼见过结对的开发者全程干预修码,结束却面不改色地说"看,Claude 全搞定了"。他认可 frontier 模型当橡皮鸭——向"十亿人的群体智慧"抛问题、解决空白页,但要清楚它是被强化学习调教得爱附和的镜子(AI 精神病正是这么来的),导航位不信它看大局,驾驶位不让它无人监督。（`00:37:44–00:46:37`）

更深的忧虑是理解力的退化:新兴研究显示越依赖越依赖;他自己 17 年培训观察是代码与需求理解力都在下滑、近三年加速——多年经验的开发者不会从零手写构造函数,读不懂十年前不成问题的练习题。病根从 Stack Overflow 抄粘贴就开始,AI 在加速;他给初学者的忠告是"代码要从眼睛过大脑再出手指"。叠加"越来越多没人看过的代码在被生产"这一事实,他担心的是理解变慢与代码变多同时发生。对 spec 驱动开发(LinkedIn 主流版:自然语言规格进 Claude Code 出系统),他的判定是"只要你对产出没有执念,也凑合能用"——自然语言天生歧义且不可修;LLM 善于生成代码、拙于修改别人的代码,而命名混淆实验(他复现过)显示代码可读性越差完成率断崖下跌——"它们是语言模型,这是第一条线索":对人类可读性、低耦合、快回归测试有利的一切,对 LLM 同样有利。未来判断收尾:LLM 不会根本改变这一行,"不再需要程序员"他从 80 年代的广告、90 年代的 CASE、到 no-code 听了四十年;打字可能会消失,但与客户和干系人在反馈回路里定义、设计、交付软件永远是工作的主体——技能树第一位是沟通与理解,第二位是不破坏地修改软件,和今天一模一样;工具不百分百可靠,就总需要有人能读懂、修改、调试。"软件开发的未来,是软件开发者。"（`00:46:38–00:53:20`，`00:53:20–00:56:55`）
