## 速读

这期 Data Skeptic 由 Kyle 主持，邀请推荐系统研究者 Yashar Deldjoo 讨论大型语言模型和 agentic 系统会怎样改变推荐。Yashar 的重点不是宣布经典推荐过时，而是分层说明：推荐系统先要满足可信 AI 的基本要求；LLM 可以增加对话、外部知识和多模态处理；语言 agent 则可能把输出从“给我一份排序列表”推进到“替我完成一个有多重约束的任务”。同时，幻觉、上下文漂移、安全性和评估困难会随系统自主性上升而更重要。（`00:04:33–00:10:53`）

这期适合想理解推荐系统下一步形态的工程师、产品和研究人员。一个实用的判断框架是三类任务：agentic replacement 让 agent 直接承担推荐；agentic augmentation 让 LLM 或 agent 辅助已有系统；simulation and evaluation 则用 agent 模拟用户、数据或系统行为，提前评估方案。（`00:32:30–00:36:07`）

## 主题正文

### 可信 AI 的五个维度

Yashar Deldjoo 将 trustworthy AI 或 responsible AI 概括为五个维度：泛化能力、鲁棒性、隐私、可解释性，以及公平与偏差。（`00:04:50–00:05:43`）泛化是从历史数据学习并预测未来；鲁棒性则关注系统面对机器生成或人为设计的攻击时是否仍能工作。（`00:05:51–00:06:17`）

节目用推荐场景解释攻击：生产者可能不诚实地修改商品外观或描述，把目标商品推入推荐列表；另一类攻击则试图压低某些商品或类别的曝光。（`00:06:32–00:07:25`）公平与偏差更难定义，因为推荐系统处在消费者和生产者等多方利益相关者之间，不同主体可能有不同的公平标准；相比之下，鲁棒性还可以通过质量下降幅度等方式量化。（`00:07:35–00:08:13`）因此，agentic 推荐不能只追求更自然的交互或更高的点击率，还要明确服务对象、责任边界和可审查的取舍。

### LLM 的增益与幻觉风险

Deldjoo 认为，LLM 的一项直接价值是自然对话。传统推荐更多是根据历史行为生成列表，而对话式系统可以通过连续交流理解用户当下的目标，让推荐变成澄清需求和共同探索的过程。（`00:11:21–00:12:49`）另一项价值是把域内行为关系与更广泛的外部知识连接起来，并辅助处理文字、图像等多模态信号。Deldjoo 更愿意称其为 augment，即增强已有方法，而不是自动取代它。（`00:13:03–00:15:44`）

风险也来自开放式生成。模型可能推荐目录中不存在的项目，或给真实项目生成错误元数据；对话还可能出现 context drift：用户开始时有一个目标，轮次增加后，模型忘记核心目标而被局部话题带走。（`00:08:38–00:10:49`）流畅、自然的表达不等于事实正确，也不等于符合用户目标。节目还指出，既有的偏差与公平问题可能被大规模互联网训练数据放大，而幻觉等则是生成模型带来的新风险。（`00:09:51–00:10:53`）

### 从排序到任务：混合而非一刀切

Kyle 将经典推荐概括为排序：把最适合用户的项目排在前面。Deldjoo 认为，语言 agent 的方向是从“请排序”转向“请替我完成任务”。旅行规划是访谈中的例子：用户可能同时提出家庭成员、预算、天气、环保程度、儿童友好性和距离等约束，单纯依赖历史行为的传统模型很难一次接收并协调这些条件。（`00:15:51–00:18:12`）

agent 可以让语言模型充当决策中枢，调用不同工具获取地点、价格和其他条件，再将结果汇总。（`00:18:34–00:19:24`）但 Deldjoo 并没有主张抛弃协同过滤。经典模型在边界清晰、任务稳定的场景已经成熟，能提供可接受的基础质量；LLM 和多模态模型则可以补充自然语言交互、开放知识、复杂偏好表达和视觉预览。例如，系统可以先帮助用户探索服装搭配，再寻找接近最终选择的真实商品。（`00:21:05–00:24:26`）更稳妥的架构，是让成熟推荐器承担擅长的部分，让生成模型处理需要对话澄清或多约束整合的部分。

### 三类 agentic 用法

第一类是 agentic replacement，即 agent 直接替代经典推荐模型完成推荐，成为“agent as recommender”。这类方案最接近完整替换，因此也要承担事实性、稳定性、成本、延迟和安全方面的责任。（`00:32:30–00:33:50`）

第二类是 agentic augmentation。此时 LLM 不是推荐器本身，而是帮助已有系统完成子任务，例如生成训练数据、缓解冷启动或提供工具。Deldjoo 将其称为 agent assistant recommender system：agent 辅助推荐系统，而不是移除推荐系统。（`00:33:50–00:34:55`）这一路线更容易保留成熟模型的可控性，并把生成模型放在较窄、较易检查的边界内。

第三类是 simulation and evaluation。模拟可以发生在数据层、用户层，或用户与系统共同组成的闭环层面，用来预先观察系统行为和可能的用户反应，减少直接进行线上用户研究的成本。（`00:34:55–00:36:07`）但模拟表现良好不能直接证明真实用户也会如此反应，模拟器本身仍需验证。

### 工具、记忆与自主性

Deldjoo 用自主性描述推荐系统从被动到互动、动态和主动的变化：协同过滤较被动，之后可以看到 LLM、单 agent 和多 agent。让 agent 与单纯 LLM 区分开来的，是工具调用和记忆能力；工具使系统能从外部服务取得信息，记忆则保留与用户目标有关的上下文。（`00:36:11–00:37:38`）

节目把记忆分为工作或短期记忆、长期或情景记忆、语义记忆和程序记忆。短期记忆支持理解“上一个”“刚才那个”；情景记忆找回较早的一次具体交互；语义记忆从多次对话积累用户偏好；程序记忆则让系统理解用户反复要求的惯常任务。（`00:37:35–00:41:44`）这会让对话更连贯，也会把隐私、错误记忆、过期偏好和用户控制权带进推荐系统的核心设计。

### 评估与社会伦理风险

节目后段谈到 Deldjoo 参与的生成式推荐相关工作，关注三件事：不同数据模态的生成模型、如何评估它们，以及社会和伦理风险。（`00:43:27–00:44:07`）节目按底层数据提到协同或 ID 信号、文本与 LLM、多模态基础模型等类别。（`00:44:07–00:44:49`）这说明“生成式推荐”不是单一模型，而是由数据模态和系统结构共同决定的家族。

复合系统让评估更难。一个 RAG 式流程可能同时包含经典推荐模型、LLM 和工具，既要看端到端的最终质量，也要按模块检查检索、生成、工具调用和排序。评估目标因此不再只有排名准确性，还要考虑幻觉、延迟等维度。（`00:44:53–00:46:27`）公平、偏差、隐私、可解释性和鲁棒性也不能等上线后再补充：当 agent 能调用工具、保留记忆并执行任务，错误可能从一个不准确的列表扩展为一连串行动。Deldjoo 将后续研究重点概括为理解未知风险、寻找缓解方式，并处理语言模型和 agent 带来的复杂性。（`00:46:57–00:48:03`）所以更合理的期待不是 agents replace everything，而是按任务风险和系统成熟度选择替换、增强或模拟，并为每种选择配套可追踪的评估。
