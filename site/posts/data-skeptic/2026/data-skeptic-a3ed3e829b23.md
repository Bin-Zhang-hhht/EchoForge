## 速读

Data Skeptic 本期属于其「人机交互」系列，主持人 Kyle 对谈科罗拉多大学博尔德分校（CU Boulder）信息科学助理教授、Data & Design Group 负责人 Jonathan Zong：图表是一种高度视觉化的语言，但对依赖屏幕阅读器的用户来说，网上大多数图表只是被播报成一行「image」或文件名。Zong 的论文 Rich Screen Reader Experiences for Accessible Data Visualization 探讨如何让屏幕阅读器用户获得与明眼读者可比的图表体验，节目围绕其提出的三个设计维度——结构、导航、描述——与开源库 Olli 展开。（`00:00:39–00:02:31`，`00:22:52–00:24:03`）

对做可视化、前端与无障碍的工程师，最值得关注的三块内容：一是为什么认真写好的一段 alt 文本仍然不够——读图目的各不相同，有用的描述就不同，摘要统计几乎相同的两份数据，画出来可能一幅平淡无奇、一幅是只恐龙；二是三个设计维度如何落地成一棵可用键盘遍历的树、空间与定向导航，以及内容、顺序、详略皆可调的描述；三是 13 名盲人与低视力参与者用户研究给出的正反两面证据——层级下钻广受欢迎，也有人明确表示更愿意把图表转回表格来读。（`00:06:30–00:11:30`，`00:24:03–00:29:21`，`00:34:13–00:37:45`）

## 主题正文

### 图表为何「读」不了：屏幕阅读器与 alt 文本

嘉宾先给明眼听众补齐基础：屏幕阅读器是可以下载或内置于操作系统的辅助软件，macOS 自带的 VoiceOver 会把光标所在的内容以语音读出，用户靠键盘命令移动光标；此外还有屏幕放大镜、可与屏幕阅读器配合的盲文点显器等多种辅助技术，很多人叠加使用。（`00:04:38–00:05:39`）

问题出在图像内容上：屏幕阅读器读的是文本，图片要靠发布者提供的 alt 替代文本才能被读出，缺失时用户听到的往往只是「image」或文件名。Zong 概括的现状是：很多图根本没有描述，平台虽然在提醒作者补 alt 文本，但经常被跳过；早年还有为搜索排名往 alt 文本里堆关键词的做法，内容与图像毫无关系。（`00:05:57–00:07:09`）

更深一层的困难在于：即使作者有诚意，也很难写出一条放之四海皆准的描述。人们读图的目的各不相同——有人找整体模式，有人带着具体问题，有人只想查某个数字——描述是否有用取决于读者想完成什么，这让一步到位的无障碍方案很难成立。（`00:07:09–00:07:56`）

主持人从 Edward Tufte 的 chart junk（图表垃圾）概念发问，Zong 的回应是：Tufte 的书影响了他那一代人，但可视化社区近年也在重新审视这些想法——不少艺术家与数据记者发现，装饰性元素反而能增进对数据的理解；图表通常嵌在新闻文章或幻灯片里，图形呈现承载着数据之外的大量信息。（`00:07:56–00:09:35`）

因此描述本身也需要分层。Zong 的同事 Alan 做过一个把图表描述内容分类的研究：最底层是低层特征——柱子什么颜色、坐标轴标签是什么；更高层是统计模式、离群值与感知层面的东西——Anscombe 四重奏和 Datasaurus Dozen 是经典例子：摘要统计几乎相同的多份数据，形状却天差地别，其中一幅是恐龙，如果只描述数据本身，就漏掉了「这图是只恐龙」这一关键信息；再往上是时事与社会语境——气候、选举、疫情等主题的图表，写描述时要考虑受众是谁、要传达什么信息。这些判断发生在任何自动化之前。（`00:09:35–00:11:30`）

### 与盲人研究者共同设计：从「拉平曲线」到「Nothing About Us Without Us」

Zong 把自己的研究缘起概括为对的人、对的地点、对的时间：他在 MIT 可视化小组读博，师从 Arvind Satyanarayan，做交互式可视化工具；2020 年疫情来临，可视化站上公共传播的中央舞台——「拉平曲线」可能是近年最著名、影响也最大的可视化之一——但团队同时意识到可视化的局限：它把非明眼用户排除在外，这是个有趣的张力。（`00:11:52–00:12:53`）

当时他与实验室同事 Alan Lundgard、Crystal Lee 合作，并结识了盲人研究者、现供职于伦敦大学学院（UCL）的 Daniel Hajas。此后六个月里，他们每周在 Zoom 上碰头，用共同设计（co-design）的方法请 Daniel 担任共同设计者：他既带来辅助技术知识与每天使用屏幕阅读器的专家经验，也带来残障生活的切身体验。Daniel 试完原型会回以详尽的长邮件，其中很多反馈推翻了 Zong 作为明眼人的直觉——HCI 的理论与框架本身就主要围绕图形用户界面建立。他把这段经历总结为：弄清自己有什么、没有什么专长，把智识上的谦逊带进协作。（`00:12:53–00:15:29`）

他引用残障运动的口号「Nothing About Us Without Us」：让有残障经验的人参与设计他们将要使用的工具，既是社会层面的要求，也是方法论上的必要——你需要能向真正知道的人验证自己的设计与假设。（`00:15:38–00:16:05`）

共同设计带来了具体的洞察。图形界面上，人能一眼扫过全页、按信息层级决定聚焦哪里；而屏幕阅读器界面默认要把一切线性化成箭头键可遍历的顺序，「总览再挑细节」的结构常常缺席。他们的原型尝试了树形而非列表的组织方式，Daniel 把有限列表比作身处一个有边界的房间——知道门在哪，就能把空间分成有意义的子区域；无结构的列表则要求用户在脑中费力重建界面里并未体现的模型。另一个原型里，导航到图表某处后按向下键会增加细节层级，把高亮部分沿轴拆成子区间——Daniel 反馈这种体验像是「在数据里缩放」。Zong 意识到，平移、缩放这些数据探索隐喻本就隐含着空间性，让屏幕阅读器界面具备空间可供性是个值得追求的方向。（`00:16:05–00:18:37`）

### 三个设计维度：结构、导航与描述

论文把贡献表述为一组屏幕阅读器可视化界面的设计维度：任何设计师做这类界面时都必须考虑的事项。团队做了大量原型来探索设计空间，留下几个最满意的做进了 Olli；框架的意义在于帮助其他人系统地思考、为自己的系统做合适决策。目标始终是让屏幕阅读器用户的图表体验与明眼读者可比。（`00:22:52–00:24:03`）

结构维度问的是：用什么数据结构让屏幕阅读器遍历图表？线性列表对有 500 个点的散点图是灾难——得一一点过去。他们探索了树与图：树加入层级与分组，根节点是图表总览（是散点图还是柱状图、坐标轴是什么），嵌在新闻页里的读者可以快速判断要不要继续听，不必穿过每个数据点；下一层是坐标轴与图例节点（x 轴是哪个字段、取值范围如何），再往下是类别或区间，最底层的叶子节点才是单个数据点。这让用户能控制探索的详略层级、跳过不感兴趣的部分、节省时间。（`00:24:03–00:26:06`）

导航维度除了沿结构移动（上下键在树的层级间、左右键在同层兄弟间），他们还原型了空间导航——上下键对应图表的顶部与底部而非抽象结构，对散点图来说更能传达数据的呈现布局；以及定向导航——用菜单直接跳到想找的位置，再用箭头键做局部探索。（`00:26:06–00:27:10`）

描述维度拆成三部分。内容：描述图表的什么，从编码、颜色等低层特征到上下文——一张包含 2008 年的股价图，也许该提一句金融危机。顺序：数据信息之外往往还要混入导航与定位信息，比如「第 1 个、共 2 个」这类索引（通常由屏幕阅读器提供，但未必开启）；这取决于任务——找第 3 项时索引放前面有用，找某个类别时类别名放前面更好，否则得先听完「第 1 个、共 7 个……」。详略：新用户需要更完整的句子，熟练用户听一句「轴 50 到 70」就够。团队后续做了让用户自定义描述内容、顺序与详略程度的界面，让描述能适配读者或数据分析师当下要做的事。（`00:27:10–00:29:21`）

### Olli：从研究原型到开源库，以及 13 名参与者的反馈

Olli 是把研究发现做成开源 JavaScript 库：npm install 后引入网页，既可以喂给它 Vega-Lite 等既有格式的可视化规格，也可以手动指定数据集与字段，它会输出一棵键盘可遍历的树状结构，附带不同详略层级的描述与顺手的键位绑定。（`00:29:31–00:30:11`）

面向的用户是想要独立、自主探索数据的屏幕阅读器用户：用 alt 文本时只能接受作者关于什么重要、哪些结论值得写的选择，而 Olli 希望用户能像明眼读者一样看整体模式、下钻局部，自己拼出结论，或用底层数据验证别人给出的描述。（`00:30:24–00:31:17`）

面向开发者，它想降低无障碍基线的门槛。Zong 坦承无障碍很难——他半开玩笑说自己读了整个博士才学会写好一段 alt 文本——但不能拿难当借口，所以把工具做成可直接放进网页的库，有望拉高可视化无障碍体验的基线；团队还把 Olli 做成了 Python 可视化库 Altair 的一个渲染器，Python 用户也能让程序同时输出图表与 Olli 输出。（`00:31:17–00:32:12`）

对于手握大量栅格化图表的媒体开发者，Olli 也不是只能配 Vega-Lite：图表出自其他库或设计师的 Illustrator 文件，也可以写一份 Olli 规格——包含数据集、把字段映射到视觉属性的编码或通用的轴与图例——生成的输出可以与现有 PNG 并列，或叠加在已写好的 alt 文本之上。他说接下来想与数据记者合作研究真实工作流：截稿压力下如何做无障碍、一个包要在媒体内部过审需要什么，把工具带到真实使用现场。（`00:32:12–00:34:13`）

研究评估与共同设计并行推进：13 名盲人与低视力参与者比较了工作方式不同的原型，与「理想无障碍可视化」——有 alt 文本、可能附数据表——的基线体验对照。Zong 强调研究的不是哪个更好——好从未被定义——而是设计选择如何影响人们对数据的思考。正向反馈包括：喜欢先在高层级浏览、感兴趣再下钻，说明层级与多档细节支撑了明眼读者也在用的下钻策略；有参与者说它给了自己不同的思考方式、更多空间化思考——可交互、可导航的结构让空间隐喻成为可能，而不是一段静态 alt 文本一次性把段落糊给你。（`00:34:13–00:36:12`）

谨慎的声音同样存在：有参与者说这类图对用过的人或许可理解，但自己要把图表转回表格才读得顺。Zong 把这解读为日常使用屏幕阅读器的人有高度个人化的工作流与既有惯例；学习新界面的前期投入对深度用户也许值得，对很多人未必，这是完全可以理解的反应，值得继续改进可学习性。更宏观的问题是：图形界面有成熟的 UX 惯例与几种标准布局，屏幕阅读器界面则相当混乱，用户无法期待应用之间体验一致——像 Olli 这样可复用的工具库，另一个价值就是为屏幕阅读器界面沉淀一致的设计语言。（`00:36:12–00:37:45`）

### 触觉、多模态与更大的图景

触觉方向上，团队做了 Tactile Vega-Lite——Vega-Lite（JavaScript 可视化工具包，Python 侧对应 Altair）的扩展原型。Zong 把无障碍工作的核心主题概括为模态差异：各感官的工作方式本就不同。触觉图表有浮雕纸打印、3D 打印、可刷新点阵触显（针脚程序化升降）等形态，但后者分辨率低、刷新慢，仍在进步；他引用过一个比喻：用触觉地图好比明眼人透过小筒看地图，靠手局部感知、从局部拼出全局，而可视化往往先给整体再拆解。即使遵循北美盲文管理局（Braille Authority of North America）的最佳实践，产出的本质上仍是视觉形式被打印成了触觉——柱状图在触觉下真正有信息量的只有柱端，柱体内部的空间并不传达什么。同方向的还有 Monash 大学的 Kim Marriott（可刷新触显）与伊利诺伊大学的 JooYoung Seo（盲文点显器与数据）。他个人的判断越来越倾向多模态系统——把可视化、声音化与文本组合起来，给所有人更多理解数据的选择；不少明眼人也表示喜欢图表旁边有文字或音频可听。（`00:19:07–00:22:36`）

主持人抛出可视化世界的两极争论：一种立场是每个选择（坐标轴、线宽）都是叙事，作者在讲述自己的图表；另一种是只给不带观点的数据，结论读者自己下。Zong 认为这确实概括了两极，并给出「客观传达」很难成立的证据：他的前同事、现属 UCSD 的 Amy Rae Fox 做过一项研究，收集 Reddit、Tumblr 与数据艺术圈等来源的图表，抹去全部主题信息后请人观看——即便是最朴素的图表，人们也会立刻从图形设计推测作者与所用工具，看到 Matplotlib 默认样式就猜是科学家做的；反过来，Nadieh Bremer 与 Stephanie Posavec 那类风格化却屡获新闻奖的作品，被抹去信息后会被猜测是外行手绘。换言之，无论作者自认为多么客观，读者都会通过你做的选择，把主观性投射到你身上。（`00:37:45–00:39:59`）

这对 Olli 的含义是默认值的权力：Olli 是高度模板化、标准化的工具，结构、描述的默认顺序、收录内容都由团队默认决定；虽然提供了自定义能力，但据 HCI 的已有认识，大多数人永远不会去碰默认值——这些决定因此对解读方式、对内容的权威感与客观性有实际影响。（`00:39:59–00:40:46`）

他还想让无障碍覆盖可视化中更具表达力的部分：艺术家手工精绘的图与 Matplotlib 默认输出的图，描述是否应该一样？更广的观察是，屏幕阅读器界面长期纯粹以效率为中心——这有充分理由，盲人与低视力社群重视的是在职场与他人同速工作、同场对话——但这留下了巨大空间去思考屏幕阅读器界面的表达力与美学：如何通过屏幕阅读器欣赏艺术与诗？Alt Text as Poetry 项目正尝试让人们超越实用视角看待描述。他给出一个递进：有没有描述？描述有没有用？再往上一层是——描述读起来是否令人愉悦。（`00:40:46–00:42:14`）

课题组围绕 Olli 还有其他方向：让盲人与低视力用户不只是消费别人做的可视化，而是能自己创作；与一位盲人科学家领导的海洋学实验室合作，研究图表、描述、3D 打印触觉地图等多感官表征如何支撑协作与科学交流。（`00:42:14–00:43:10`）

展望上，团队有学生在做无障碍地图——地理可视化有独特挑战（哪些区域相邻、政治与文化定义的地理分组），可尝试把 Olli 的思路用于地图；更长期地，他想把基于 Vega-Lite 等声明式规格的思路从可视化推广到 Web 应用的无障碍。现有 WCAG（Web 内容无障碍指南）与 ARIA（为 HTML 标注无障碍元数据的标记语言）很重要，但指南是情境性的，开发者容易做错、每次从零发明；从 Vega-Lite 这类语法式方法学到的经验是——用字段、编码这样的高层概念来声明（而非 D3 式的渲染级命令），能获得编译通过即有好输出的保证与组合性质。他认为可以把编程语言设计的思想引入 Web 无障碍，而结构、导航、描述这套框架，也许能让可视化成为研究图形界面无障碍的一个特殊案例。跟进渠道：他的个人网站 jonathanzong.com、课题组网站 dataanddesign.org，社交平台主要是 Bluesky 与 LinkedIn。（`00:43:27–00:46:08`，`00:46:53–00:47:24`）
