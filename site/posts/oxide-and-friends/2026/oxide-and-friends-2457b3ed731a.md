## 速读

「要能在网页上 3D 逛机架」是 Oxide 自 2020 年起的执念，今年五月终于上线：不是艺术渲染，而是从机械 CAD 出发的真机架。设计负责人 Ben Leonard 在这期里讲清了三件事——为什么资产准备比应用本身更难、Web 3D 的性能工程怎么做，以及为什么拒绝 20 万美元的外包报价自己造。适合做 Web 图形、CAD 资产管线或「要不要自建工具」决策的读者。

## 主题正文

### 真正的瓶颈在资产，不在应用

Explorer 的想法可以追溯到 2020 年，真正动手前 Ben 卡住的从来不是 Web 应用本身，而是 CAD 资产：32 个 sled、每个 sled 一块 PCB、上万个元件，模型有数百万个多边形，连在 CAD 软件里转个视角都要等几秒，而且没有可靠的自动减面（`00:07:39`–`00:11:22`）。解法是人与工艺：他和 3D 艺术家 Kennen 手工重建整套模型，按细节分级做多份 LOD，逐处删除、重网格化，在「视觉保真、细节有意义、跑得动」之间反复权衡（`00:09:26`–`00:13:24`）。Cosmo 计算 sled 的内部细节尤其丰富——切换 PCB 设计工具带来的副产品是高精度 PCBA 模型；而 sidecar 交换机还留在旧 Cadence 工具链里，于是 Explorer 里看不到交换机 PCB 的丝印，由此引出一段「暴躁 Pierre」丝印彩蛋的公司传说（`00:11:29`–`00:12:53`、`00:36:19`–`00:42:05`）。

### 技术栈与把 UI 动画原则搬进 3D

实现基于 Three.js + React Three Fiber（声明式地把 3D 对象当标签写），模型以 GLB/glTF 导出并经 Draco 压缩；组件清单是一个 JSON 文件，导览（guided tour）是另一个 JSON——每步只描述目标组件 ID 或「空间中一点+缩放」，相机自动在路径点间插值（`00:17:55`–`00:23:55`、`00:50:41`–`00:52:35`）。有趣的一手经验：他装了一个讲网页动画原则的 Claude skill，本是为模态框这类 UI 准备的，结果两条原则直接适用于 3D 相机——插值要做到与帧率无关、动画时长应随移动距离缩放，「把传统 UI 原则套到非传统体验上」屡试不爽（`00:52:42`–`00:54:34`）。

### 性能工程与 Claude 写的基准

让它流畅跑靠的是一组组合拳：32 个 sled 走实例化渲染、视锥剔除、启动时按 GPU 分三档自适应画质，运行中监测帧率下降降档并防振荡（`00:58:35`–`01:01:18`）。更值得学的是验证方法：他让 Claude 写了一个性能基准工具——URL 参数触发、自动跑测试、输出 JSON 结果，两次实验的结果喂回 Claude 对比「哪个改动真的有效」，既是优化依据也是防性能回归的护栏；这些结论沉淀在仓库的 perf.md 里，让新的 AI 会话不用重蹈覆辙。顺带的小故事：太太的笔记本上不到 1 FPS，Claude 从基准输出里直接诊断出浏览器没开硬件加速（`01:01:18`–`01:03:49`）。他还观察到一个明显的代际差：Sonnet 时代的模型对这类项目帮不上忙，Opus 之后才成为「力量倍增器」——两个仓库都是手写开头、越写越 AI（`01:04:11`–`01:04:55`）。

### 为什么拒绝 20 万美元外包

项目的直接导火索是营销团队找到一家专做硬件 3D Explorer 的代理公司，报价 20 万美元——对 Ben 来说这恰恰是动手的信号。Oxide 的 RFD 站、文档、招聘页全是自建，理由不只是省钱：自建让资产与技艺都留在手里，未来可以长进产品控制台、做支持场景（点开 sled 会演示拉手拔出的动画，未来可做交互式维修引导）、乃至把独有的热力数据做成可视化——那个「热力探索器」尝试过，卡在三维空间+时间的双重信息压平设计上，仍是待解课题（`00:24:27`–`00:28:39`、`00:31:57`–`00:36:19`）。Bryan 的补充判断是：LLM 已经把「自己造」的经济性民主化了，而能写代码的设计师会把工具链握在自己手里，这是设计与工程交汇处最大的红利（`00:27:40`–`00:29:32`）。
